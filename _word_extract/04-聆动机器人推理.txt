聆动机器人推理
1 推理源码解析
1.1 文件概述
这是一个 ROS2 推理节点，用于在聆动机械臂（LindenBot）双臂机器人 上部署 ACT（Action Chunking with Transformers） 模型。它的核心流程是：

[表格]
  相机(3路) ──┐             ├──→ get_observation() ──→ preprocessor ──→ ACTPolicy.select_action() ──→ postprocessor ──→ 机械臂发布机械臂状态  ─┘(关节+夹爪)         50Hz 推理线程                             100Hz 发布线程(slew限速)
1.2 代码整体架构

[表格]
  main()  └─ rclpy.init()      └─ LeRobotInferenceNode.__init__()            ├── init_model()         ← 加载 ACT 模型 + 预/后处理器            ├── create_subscribers()  ← 订阅臂状态 + 夹爪状态            ├── create_publishers()   ← 发布臂命令 + 夹爪命令            ├── 打开 3 路相机设备 (OpenCV VideoCapture)            └── model_control_service ← /model_ifrun (SetBool 启动/停止)                  │                  当收到 request.data=True 时：                  ├── set_arm_position_mode() ← 切从动臂到位置控制模式                  ├── 首次推理(ramp准备)                  ├── 启动 publish_thread (100Hz, slew限速)                  └── 启动 inference_thread (50Hz, 更新目标动作)          推理线程 (inference_loop @ 50Hz):            └── run_inference_once()                  ├── get_observation()  ← 读3路相机 + 16维状态                  ├── preprocessor()     ← 归一化、to(device)                  ├── policy.select_action() ← ACT 核心推理                  └── postprocessor()    ← 反归一化              ↓              target_action [16] (带线程锁)          发布线程 (publish_loop @ 100Hz):            └── _slew_toward(published_cmd → target_action)                  ├── 滑动窗口平均(5帧)                  ├── EMA平滑(α=0.15)                  └── 硬性速度上限(臂0.003rad/tick, 夹爪0.02/tick)              ↓              publish_cmd_space() → 3个ROS话题

1.3.3 推理循环（inference_loop）→ run_inference_once()

[表格]
  Pythondef run_inference_once(self):    obs = self.get_observation()          # [1] 相机+状态    processed = self.preprocessor(obs)    # [2] 归一化 + to(device)with torch.no_grad():        action = self.policy.select_action(processed)  # [3] ACT 推理    action_dict = self.postprocessor({'action': action})  # [4] 反归一化    a = action_dict['action'].flatten()   # [16]return dataset_action_to_ros(a)       # [5] 恒等映射
执行频率：50Hz → 每 20ms 更新一次 self.target_action
ACT 的 select_action 机制：
输入当前 observation，输出 chunk_size=100 步的 action chunk
内部用 FIFO 队列管理，每次 select_action 返回队列头部动作并将其弹出
当队列为空时自动重新推理
1.3.4 发布循环（publish_loop）→ _slew_toward() + publish_cmd_space()
执行频率：100Hz → 每 10ms 发布一次
平滑策略 _slew_toward()（L458-L480）—— 三层过滤：

[表格]
  第1层：【滑动窗口平均】  buffer 最近5个 target，取均值            ↓第2层：【EMA平滑】      cur + (smoothed_target - cur) * 0.15            ↓第3层：【硬性限速】      每个关节每 tick 最大变化            臂关节: MAX_ARM_STEP_RAD = 0.003 rad/tick            夹爪:   MAX_GRIP_STEP    = 0.02   /tick

1.3.5 首次推理的 Ramp 准备（model_control_callback）

[表格]
  Python# 首次推理获取目标first_target = self.action_to_cmd_space(first_raw)# published_cmd 起点：臂=当前实测弧度，夹爪=直接取目标start_cmd = first_target.copy()for i, jn in enumerate(LEFT_ARM_JOINTS):    start_cmd[i] = self.joint_positions[jn]       # ← 当前关节弧度for i, jn in enumerate(RIGHT_ARM_JOINTS):    start_cmd[8 + i] = self.joint_positions[jn]   # ← 当前关节弧度self.published_cmd = start_cmd  # 从当前位置出发self.target_action = first_target  # 目标位置
关键设计：避免启动时从零点（所有关节角度=0）开始执行，导致机械臂从当前位置突然跳变到零位再向目标移动。而是从当前实测位置直接朝目标平滑逼近。
1.4 恒等映射 vs. Cyclic Shift（L99-L110）

[表格]
  Python# ✅ fixed 数据集：转换脚本的 cyclic-shift bug 已在源头修复，#    数据集 16 维即 ROS 物理顺序：[L0..L6 左臂7, L_grip, R0..R6 右臂7, R_grip]#    因此部署侧不做任何循环移位 —— 下面两个函数为恒等映射。def ros_state_to_dataset(ros_state_16):    return np.asarray(ros_state_16, dtype=np.float32).copy()def dataset_action_to_ros(dataset_action_16):    return np.asarray(dataset_action_16, dtype=np.float32).copy()
历史溯源：
旧版 bug：convert_lerobot_v3_old.py 中的 CSV 列偏移 bug 导致数据集顺序为 [L0..L5, R0, L6, L_grip, R1..R7, R_grip]，部署时需要 np.roll() 做循环移位恢复
fixed 版：convert_lerobot_v3_fixed.py 和 fixed_simple.py 已在源头修复了 CSV 读取 bug，数据集顺序 = ROS 物理顺序，所以部署侧不需要任何映射
