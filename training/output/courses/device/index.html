SETUP本机准备

只需在这台电脑上启动一次本机助手，设备端免安装

数据流变为「浏览器 → 本机助手（127.0.0.1）→ 设备 SSH」：助手部署在本机，监听回环地址， 用你填写的账号密码通过 SSH 连接设备——设备上不需要安装、部署任何服务，只要 sshd 在监听即可。 若只用「本机 USB 直连」串口，本节可以直接跳过。

1启动本机助手（两种方式任选）

方式一：打开工作台，点「新建连接」→ 选择 SSH → 点「启动本机助手」按钮，页面会自动拉起服务。
方式二：手动双击课程目录里的 start_helper.bat（仅监听 127.0.0.1:8100，关掉窗口即停止）。 首次运行会自动从清华源安装 aiohttp / paramiko / pyserial，约需十几秒。

# 等价的手动方式（在 training/output/courses/device 目录）
python start_helper.py # 默认 127.0.0.1:8100；可用 --port 9000 改端口

2（可选，一次性）注册 eai-helper 协议

协议注册把 eai-helper:// 写进操作系统（Windows=注册表 HKCU，无需管理员； Linux=.desktop + xdg-mime，无需 root；macOS=内置 URL scheme 的启动器 .app + lsregister）。 三平台的注册动作已内置在启动脚本里自动完成——只要新机器跑过一次 start_helper.bat（Windows）或 ./start_helper.sh（Linux/macOS）， 之后点入口即自动、无窗口拉起助手；也可手动单独执行对应 register 脚本重刷注册。

register_helper.bat            # Windows
./register_helper.sh           # Linux
./register_helper_macos.sh     # macOS（生成并注册 ~/Applications/eai-helper.app）

3打开工作台并连接设备

点「启动工作台」→「＋ 新建连接」→ SSH，填写设备 IP（如 192.168.1.100，端口默认 22） 与设备上的 Linux 账号密码。助手持这个账号 SSH 登录设备，密码仅存内存、随连接销毁，不落盘。

备选直连方案：ttyd / filebrowser / noVNC（老页面探测用，非必需）

A安装三个服务（设备上，可选）

Debian / Ubuntu 系设备，一条命令装齐。工作台不需要它们；仅当你想用上面「连接配置」的直连探测入口时才装。

# 终端（ttyd）／桌面（websockify + noVNC）
sudo apt update
sudo apt install -y ttyd novnc websockify

# 文件管理（单个 Go 二进制，前端已内嵌）
curl -fsSL https://raw.githubusercontent.com/filebrowser/filebrowser/master/get.sh | bash

B启动服务

三个服务分别监听 7681 / 8081 / 6080，与上方「连接配置」里的默认端口一致。VNC 复用设备上已在运行的 VNC server（默认 5900）。串口始终走本机 USB 直连，无需任何服务。

# 终端 —— 7681
ttyd -p 7681 -c admin:你的密码 -W bash

# 文件管理 —— 8081，根目录指向工作区
filebrowser -a 0.0.0.0 -p 8081 -r /home/iflytek -d /opt/device-dev/filebrowser.db

# 桌面 —— 6080，把本机 5900 的 VNC 转成 WebSocket
websockify --web=/usr/share/novnc 6080 127.0.0.1:5900

C设备上要有 VNC server（镜像物理桌面）

上面装的 novnc/websockify 只负责「网页化」，5900 那端还需要一个真正的 VNC server。 设备已有图形桌面时，用 x11vnc 共享 :0 最省事：

# 装 x11vnc（novnc/websockify 同上）
sudo apt install -y x11vnc

# 共享物理桌面 :0（gdm 登录界面下 -auth guess 会失败，直接指定 Xorg 的授权文件）
sudo x11vnc -display :0 -auth /run/user/999/gdm/Xauthority \
     -forever -shared -repeat -noxdamage -rfbport 5900 -localhost -nopw

# Rockchip（RK3576/RK3588）板卡必做：Mali 驱动常加载失败会让物理屏和 VNC 全黑
#   libGL error: failed to load driver: rockchip
echo 'LIBGL_ALWAYS_SOFTWARE=1' | sudo tee -a /etc/environment
sudo systemctl restart gdm

完整的一键部署（含 systemd 开机自启、X 会话重启自动重连、关闭息屏）见 README.md 的 3.1 节。

D把地址填到上方

回到本页「连接配置」，填入设备局域网 IP（如 192.168.1.100），点「检测连接」→ 想要的项目状态变绿即表示服务已就绪。

🔒 本机助手只监听 127.0.0.1（回环地址，局域网内其他人无法访问），且从本机发起的仍是常规 SSH 登录—— 设备侧只需保证 sshd 在线与账号密码强度即可。完整说明见同目录 README.md。
