URDF 与 Xacro：给机器人造一份数字骨架

rviz2 里那台蓝底盘黑轮的小车，源头是一份 XML——URDF。它是 Rviz2/Gazebo/TF2/运动规划的唯一模型输入。本实验讲透 link 三重属性与 joint 六类型的原理，用 Xacro 宏语言把 150 行模型压缩到 80 行，并让惯性矩阵从"魔法数字"变成公式推导。

难度 ⭐⭐⭐4 学时设计性关键词 URDF · link · joint · Xacro · 惯性矩阵

01问题引入：屏幕里的小车，是谁画的聚焦问题 · 激活旧知

先回忆EXP-19 的 TF 树（谁是谁的 child、原点在哪）——URDF 就是那棵树的源头文件：你用 link 和 joint 描述机器人，robot_state_publisher 把它变成 TF 变换和三维模型，rviz2 里那台小车就是从这里"画"出来的。
1echo /scan 只看到一堆浮点数——数据有了，"车"在哪？
2rviz2 勾选 RobotModel 后，一台蓝底盘、黑驱动轮、白万向轮的小车瞬间出现
3模型形状、颜色、轮轴位置全部来自参数 robot_description——它的内容就是一份 URDF 文件
4拖动 joint 滑块，轮子绕轴旋转：几何 + 运动约束 + 物理属性，一份 XML 全定义
定义URDF（Unified Robot Description Format，统一机器人描述格式）是一种 XML 语言，用来描述机器人的几何结构（长什么样）、运动学约束（怎么动）与动力学参数（多沉、惯性多大）。它是 Rviz2、Gazebo、TF2、MoveIt 运动规划的唯一模型输入源——写好一份 URDF，整条工具链共享同一台"数字孪生"。

02核心原理：link 三重属性 × joint 六类型示证新知

link 属性作用取值/几何体何时必须
<visual>渲染外观（给 Rviz2 看）box / cylinder / sphere / mesh（数万三角形也行）只想可视化时——可单独存在
<collision>物理碰撞检测（给 Gazebo 看）同上，但应简化为包围盒以降低实时计算量仿真必须
<inertial>动力学：mass + 3×3 惯性矩阵ixx iyy izz ixy ixz iyz仿真必须（否则模型飞走）
三属性为何分离① 视觉模型数万三角形、碰撞模型要实时求交——解耦才能各自优化；② 同一个空心盒与实心铁块外观相同但惯性不同——独立声明才不撒谎；③ 纯可视化场景可只写 visual，省掉物理开销；④ Gazebo 要求三者齐全，缺 inertial 模型会乱飞、缺 collision 穿地不碰撞。
joint 类型自由度典型场景关键子标签
fixed0传感器底座、万向轮脚轮origin
revolute1（限位）机械臂肘/肩关节必须 limit lower/upper + axis
continuous1（无限转）驱动轮、履带axis
prismatic1（滑轨）升降柱、滑动平台limit + axis
floating6自由漂浮体（不推荐手写）—
planar3平面运动体（不推荐）—
最容易混淆的两种 originlink 内的 origin（visual/collision/inertial 之下）= 该几何体相对自己 link 原点的偏移；joint 里的 origin = 子 link 相对父 link的初始位姿。语义完全不同——把轮子的偏移写进 visual origin 而不是 joint origin，轮子会在原地转圈却装不到车轴上。
另注：URDF 坐标系遵循 REP-103 —— X 前、Y 左、Z 上；origin 的求值顺序是先 rpy 旋转、再 xyz 平移。

04原理专题：惯性矩阵——从魔法数字到物理公式示证新知

长方体 · 底盘
Ixx=m/12·(y²+z²)　Iyy=m/12·(x²+z²)　Izz=m/12·(x²+y²)

例：底盘 0.40×0.25×0.08 m、质量 3.0 kg → ixx=0.017、iyy=0.042、izz=0.053。沿某轴的惯量 = 质量对该轴分布的"转动惰性"，垂直于该轴的边长平方贡献最大。

圆柱体 · 车轮
Ixx=Iyy=m/12·(3r²+h²)　Izz=m/2·r²

轮轴沿 Y：绕轴（Y）转动惯量小、绕直径大时看 h 贡献。r=0.05、L=0.03、m=0.2 代入即可，杜绝拍脑袋的 0.01。

数学红线
矩阵必须对称正定

ixx、iyy、izz 全部 > 0，且满足三角不等式 ixx+iyy≥izz 等。非法值会让 Gazebo 求解器发散——模型原地爆炸或瞬间飞出场景。

工程护栏
初学用 1e-3 占位

只做 Rviz2 可视化时惯性可省；进 Gazebo 前若懒得算，统一写 ixx=iyy=izz=1e-3（对角等值必正定），先跑通再精算。Xacro 则用公式自动算（见 08 节）。

为什么是"两个发布者"分工URDF 是静态结构（轮子装在哪），/joint_states 是动态状态（此刻转了多少度）。robot_state_publisher 把两者相乘得到每帧 TF——这正是"模型"与"状态"分离的设计哲学，同一份 URDF 可复用于全车队。

07实操 A：手写完整差分车 URDF（设计性任务）应用新知

1建工作空间与目录：ros2 pkg create urdf_demo --build-type ament_cmake 后建 urdf/ 子目录
2写 4 种材质 + 底盘 link（box 0.40×0.25×0.08，mass 3.0，惯性 0.017/0.042/0.053）
3写左右驱动轮（cylinder r=0.05 L=0.03，continuous，axis 0 1 0，xyz ±0.15 / -0.03）
4写前万向轮（sphere r=0.025，fixed）→ check_urdf 验证 "3 child(ren)"
<!-- 核心三关节（完整文件见讲义） -->
<material name="black"><color rgba="0.2 0.2 0.2 1.0"/></material>
<!-- .... link chassis: box + mass 3.0 + ixx0.017 iyy0.042 izz0.053 .... -->

<joint name="left_wheel_joint" type="continuous">
  <origin xyz="0.0 -0.15 -0.03" rpy="0.0 0.0 0.0"/>
  <parent link="chassis"/>
  <child link="left_wheel"/>
  <axis xyz="0 1 0"/><!-- 绕 Y 轴转，与 REP-103 车体横向一致 -->
</joint>

<joint name="right_wheel_joint" type="continuous">
  <origin xyz="0.0 0.15 -0.03" rpy="0.0 0.0 0.0"/>
  <parent link="chassis"/><child link="right_wheel"/>
  <axis xyz="0 1 0"/>
</joint>

<joint name="front_caster_joint" type="fixed">
  <origin xyz="0.18 0.0 -0.055" rpy="0.0 0.0 0.0"/>
  <parent link="chassis"/><child link="front_caster"/>
</joint>

08实操 B：Xacro 参数化重构（复用压缩到 80 行）融会贯通

1property 收编魔法尺寸：chassis_length/width/height、wheel_radius/length、wheel_mass……
2推导量用表达式：wheel_y_offset=${chassis_width/2 - 0.02}、wheel_z_offset=${-chassis_height/2 + wheel_radius}——改车宽轮距自动跟
3box_inertia / cylinder_inertia 宏套公式；wheel 宏以 x_reflect=±1 镜像出左右轮
4xacro 展开 → check_urdf 复验 → 移动 launch 指向 .xacro 再进 RViz
<!-- ① 属性层：尺寸/质量/推导量全部参数化 -->
<robot name="diff_drive_robot" xmlns:xacro="http://www.ros.org/wiki/xacro">
  <xacro:property name="chassis_length" value="0.40"/>
  <xacro:property name="chassis_width"  value="0.25"/>
  <xacro:property name="chassis_height" value="0.08"/>
  <xacro:property name="chassis_mass"   value="3.0"/>
  <xacro:property name="wheel_radius" value="0.05"/>
  <xacro:property name="wheel_length" value="0.03"/>
  <xacro:property name="wheel_mass"   value="0.2"/>
  <xacro:property name="wheel_y_offset" value="${chassis_width/2 - 0.02}"/>
  <xacro:property name="wheel_z_offset" value="${-chassis_height/2 + wheel_radius}"/>

  <!-- ② 惯性宏：公式即代码，Gazebo 永不爆炸 -->
  <xacro:macro name="box_inertia" params="mass x y z">
    <inertial><mass value="${mass}"/>
      <inertia ixx="${mass/12 * (y*y + z*z)}" ixy="0.0" ixz="0.0"
               iyy="${mass/12 * (x*x + z*z)}" iyz="0.0"
               izz="${mass/12 * (x*x + y*y)}"/>
    </inertial>
  </xacro:macro>
  <xacro:macro name="cylinder_inertia" params="mass radius length">
    <inertial><mass value="${mass}"/>
      <inertia ixx="${mass/12 * (3*radius*radius + length*length)}" ixy="0.0" ixz="0.0"
               iyy="${mass/12 * (3*radius*radius + length*length)}" iyz="0.0"
               izz="${mass/2 * radius*radius}"/>
    </inertial>
  </xacro:macro>

  <!-- ③ 车轮宏：一个模板 + 反射因子 = 左右两轮 -->
  <xacro:macro name="wheel" params="name parent x_reflect">
    <link name="${name}">
      <visual><geometry>
        <cylinder radius="${wheel_radius}" length="${wheel_length}"/>
      </geometry><material name="black"/></visual>
      <collision><geometry>
        <cylinder radius="${wheel_radius}" length="${wheel_length}"/>
      </geometry></collision>
      <xacro:cylinder_inertia mass="${wheel_mass}" radius="${wheel_radius}" length="${wheel_length}"/>
    </link>
    <joint name="${name}_joint" type="continuous">
      <origin xyz="0.0 ${x_reflect * wheel_y_offset} ${wheel_z_offset}" rpy="0.0 0.0 0.0"/>
      <parent link="${parent}"/><child link="${name}"/>
      <axis xyz="0 1 0"/>
    </joint>
  </xacro:macro>

  <!-- ④ 两行调用，左右轮齐活 -->
  <xacro:wheel name="left_wheel"  parent="chassis" x_reflect="-1"/>
  <xacro:wheel name="right_wheel" parent="chassis" x_reflect="1"/>
</robot>
坑症状解法
xmlns:xacro 未声明xacro 不识别 <xacro:macro> 标签robot 根标签加 xmlns:xacro="http://www.ros.org/wiki/xacro"
宏调用 name 参数撞车展开后重复 link/joint 名，解析失败左右轮必须传不同 name；宏内用 ${name}_joint 拼接
rgba 写成 0~255颜色全白/报错URDF 颜色值域是 [0,1]，CSS 习惯要改
continuous 与 revolute 混用轮子被 limit 卡在 360° 内轮子用 continuous；revolute 必须写 limit lower/upper
宏定义与调用不在同一 robot 标签内"unknown macro name"定义必须先于调用且都在同一 <robot> 下
launch 里硬编码 src/ 绝对路径install 后找不到模型用 get_package_share_directory()——share 在 install/<pkg>/share/<pkg>/

09注意事项与避坑清单融会贯通

  • origin 求值顺序：先 rpy 旋转、再 xyz 平移——顺序颠倒视觉全变；开 TF Display 查坐标轴方向。
  • 惯性矩阵对称正定：ixx/iyy/izz>0 且满足三角不等式，非法值 = Gazebo 爆炸；初学 1e-3 占位。
  • joint 类型不可混：轮子 continuous（无限转）、肘关节 revolute + limit；给轮子设 revolute 会限死角度。
  • Xacro 声明命名空间：xmlns:xacro 缺失则所有宏标签失效。
  • Fixed Frame 用根 link：必须是 URDF 中真实存在的 link 名（通常为 chassis/base_link），否则 RobotModel 拒绝渲染。
  • 路径用包索引：get_package_share_directory() 取路径，绝不要硬编码 src/ 下的绝对路径。
  • 三种验证手段分工：check_urdf 查语法结构、urdf_to_graphiz 查拓扑外观、RViz 查几何与坐标。

10本课总结与思考融会贯通

概念
URDF = 数字孪生的唯一入口

XML 描述几何结构、运动学约束与动力学参数，Rviz2/Gazebo/TF2/运动规划共享同一模型源。

结构
link 三属性 × joint 六类型

visual/collision/inertial 按用途分离，各场景只声明所需；fixed/revolute/continuous/prismatic 按自由度选型，两种 origin 语义严格区分。

协作
两发布者数据流

joint_state_publisher 给关节角，robot_state_publisher 用 URDF 解算 TF，Rviz2 依据 Fixed Frame 绘制——状态与模型解耦。

进阶
Xacro 参数化三板斧

property 收编尺寸、${} 表达式推导联动量、macro + 惯性公式消灭复制粘贴——80 行管住 150 行模型，6 轮再翻倍。

思考题 ① 底盘是 L 形（两个长方体拼成），它的惯性矩阵怎么求？（提示：平行轴定理 I = I_cm + m·d²，d 为部件质心到整体质心的距离——先分别算两块、再平移相加。）
② B2 实验箱机械臂 6 个旋转关节，手写 URDF 约 300 行；请设计一套 Xacro 宏方案把它压到 50 行以内——给出宏的划分思路（建议按"连杆段"抽象一个 macro：含尺寸参数、惯性参数、上下关节），并说明如何集中管理各关节的 limit 与关节类型。
