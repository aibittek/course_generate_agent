工作空间与 colcon：代码放在哪、怎么编

工作空间是 ROS2 的"工程边界"：src 放源码、build 编译、install 交付、log 留痕；colcon 负责编译，Overlay/Underlay 机制负责让新旧代码层层覆盖。

难度 ⭐2 学时验证性纯软件 · 不接硬件关键词 colcon · overlay · symlink

01问题引入：代码到底放哪儿

1
新手把 Python 脚本随手丢在 ~/ 家目录，跑得好好的。
2
一周后：脚本依赖别的包、别的包更新了、还要交付给同学——找不到、编不了、删不掉。
3
结论：需要一个约定好的工程边界，把"我的代码"和"系统安装的 ROS2"分开。
4
ROS2 的答案：工作空间（Workspace） + 构建工具 colcon。
定义 Workspace一个包含 src/ 目录的文件夹，你所有的功能包源码都放进 src/，构建产物统一生成在其它三层目录里。ROS2 官方也称其为 workspace，ROS1 时代的 catkin_ws 概念一脉相承。

02核心原理：四层目录结构

src/
源码层（唯一手写层）

所有功能包的源码、package.xml 都在这里。它是唯一需要纳入 git 版本管理的目录。

build/
编译中间产物

CMake 缓存、.o 文件、构建元数据。可随时整个删除，重新编译即可。

install/
可执行 + 环境脚本

编译交付物：可执行文件、库、launch、以及关键的 setup.bash 环境脚本。

log/
构建日志

每次 colcon 运行的日志。编译失败时先来这里看，而不是重跑十遍。

out-of-source 编译哲学说明
源码与产物分离src 只有源码，build/install/log 全是生成物——rm -rf build install log 永远安全。
干净的 git.gitignore 常规只需排除 build/ install/ log/，仓库里只有 src。
可重建性任何一台装好 ROS2 的机器，git clone + colcon build 即可复现环境。

03colcon 构建四阶段动画

colcon 四阶段流水线：发现包 → 拓扑排序 → 并行编译 → 安装交付；排序之后才轮得到 Build，所以依赖多的包永远最后编。

04Underlay / Overlay：叠层查找原理

ROS2 用环境变量列表实现包查找：可执行文件、Python 模块、接口定义都按顺序在多层前缀里搜索，先匹配到的赢。

1
Underlay（底层）：系统安装的 ROS2（/opt/ros/humble），提供 rclpy、rviz2 等基础能力。
2
Overlay（上层）：你自己的工作空间 install/，可以覆盖底层同名包，也可以新增包。
3
执行 source install/setup.bash 把你的层追加到列表顶部——后 source 者胜出。
4
验证：echo $COLCON_PREFIX_PATH，你的路径应出现在系统路径前面。
坑 1
顺序颠倒，包"消失"

先 source 自己的工作空间再 source /opt/ros，系统层会压在你上面，你的包找不到。

坑 2
setup.bash 递归

工作空间的 setup.bash 会自动带着底层（underlay chain），日常只需要 source 它一个。

坑 3
新终端全忘了

source 只对当前 shell 生效。每次开新终端都要重来，或写进 ~/.bashrc。

05colcon 命令精讲

标准四步曲——顺序不能乱：

# ① 确认底层已加载（装完 ROS2 的默认动作，或显式执行）
source /opt/ros/humble/setup.bash
# ② 在工作空间根目录（有 src/ 的那层）执行编译
colcon build
# ③ 激活你的工作空间（把 install/ 送进环境）
source install/setup.bash
# ④ 验证
ros2 pkg list | grep my_test_pkg   # 看到包名即成功
# 高频选项
colcon build --packages-select my_test_pkg   # 只编指定包（大工程提速关键）
colcon build --symlink-install               # Python/launch 改动免重编，直接生效
colcon build --event-handlers console_direct+# 实时滚动输出，失败原因一目了然
# 成功标志：Summary: 1 package finished [2.34s]
symlink 的边界--symlink-install 让源码改动即时生效，但改了 setup.py / package.xml / CMakeLists 后仍要重新 colcon build——链接的是内容，不是构建描述。

06实操 A：从零创建工作空间

1
安装构建工具（多数桌面版已自带）：sudo apt install python3-colcon-common-extensions
2
建目录骨架：mkdir -p ~/ros2_ws/src——src 是识别工作空间的标志。
3
在 src 里建一个测试包（细节见 EXP-04）。
4
回到根目录 build → source → 验证三连。
# ① 检查工具链（讲义步骤1）：应显示 build/test/list 等子命令
colcon --help | head -1
# command not found？ sudo apt install python3-colcon-common-extensions -y

# ② 建目录骨架（src 是识别工作空间的标志）
mkdir -p ~/ros2_ws/src
tree -L 2 ~/ros2_ws        # 此时只有 src/ —— build/install/log 编译后才会生成

# ③ 在 src 里建一个测试包（细节见 EXP-04）
cd ~/ros2_ws/src
ros2 pkg create --build-type ament_python \
  --node-name hello_node --dependencies rclpy my_test_pkg

# ④ 回根目录：build → source → 验证
cd ~/ros2_ws
colcon build                            # 预期：Summary: 1 package finished
source install/setup.bash
ros2 pkg list | grep my_test_pkg   # my_test_pkg 出现 ✅
tree -L 1 ~/ros2_ws                 # 四层齐了：build/ install/ log/ src/ ✅
ls ~/ros2_ws/install/                # 含 setup.bash 等环境脚本 ✅
grep -o 'your_ws[^:]*' $COLCON_PREFIX_PATH   # 确认你的层在列表里

07实操 B：Overlay 覆盖五连击

纯终端实操，全程在设备上执行。验证"后 source 者胜"与"Underlay 不可跳过"，请严格按顺序执行并记录每步输出：

# ① 正确顺序：系统层先，自己层后
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 pkg prefix my_test_pkg   # → /home/<你>/ros2_ws/install/my_test_pkg ✅

# ② 颠倒顺序：新开终端重来
source ~/ros2_ws/install/setup.bash
source /opt/ros/humble/setup.bash
ros2 pkg prefix my_test_pkg   # → 报错 not found 或落到旧层 ⚠（若系统无同名包）

# ③ 看清环境变量里的排列
echo $COLCON_PREFIX_PATH | tr ':' '\n'

# ④ 反向验证：新开终端，只加载自己的层、跳过 Underlay
source ~/ros2_ws/install/setup.bash
ros2 --help                   # → 仍 command not found ⚠
# 原因：Overlay 只"追加"路径，不自带 ros2 本体 —— Underlay 不能省

# ⑤ 一键恢复：删产物重新来过（永远安全的操作）
rm -rf build install log && colcon build

08注意事项与验收清单

  • 四层目录齐全：src/build/install/log，且 git 仓库里只跟踪 src
  • colcon build 输出出现 Summary: N package finished
  • ros2 pkg list 能搜到自己刚建的包
  • echo $COLCON_PREFIX_PATH 中你的工作空间排在 /opt/ros 之前
  • 能口头解释：为什么 build/install 可以随便删？为什么顺序颠倒包会"消失"？
  • 成功复现"实操 B"五连击：正序命中 / 颠倒抢跑 / 跳过 Underlay 后 ros2 --help 仍不可用
坑症状解法
执行位置不对colcon 提示找不到 src/ 或在错误目录生成产物必须在工作空间根目录（src 的上一层）执行
source 顺序颠倒自己的包 pkg list 里搜不到 / 运行的是旧版确保工作空间 setup.bash 最后 source
磁盘越用越大build 残留几十 GBrm -rf build install log 后重编，src 不受影响
改了代码没生效Python/launch 改动运行还是旧行为加 --symlink-install 重编；改构建描述文件则必须重编

09本课总结与思考题

结构
src / build / install / log

唯一手写层是 src；三个生成层随时可删，这是 out-of-source 的全部意义。

工具
colcon 四阶段

Discovery → Topological → Build → Install，依赖排序保证编译顺序正确。

机制
Underlay / Overlay

环境变量列表按序查找，后 source 者胜，这就是覆盖与找回的全部原理。

习惯
根目录构建 + 四步曲

build → source → 验证；symlink 让脚本类改动立等可取。

思考题 ① 两个工作空间 a、b 各含同名包 my_pkg（版本不同），同一终端里先 source a 后 source b，运行的是哪个？想让 a 生效怎么办？
② 团队想共享一份"公共 Underlay"（驱动+接口由维护者统一更新，成员只写自己的包），该如何设计 source 顺序？画出你的三层叠放图。
