功能包与依赖管理：ROS2 的交付单元

功能包（Package）是 ROS2 的最小交付单元：一段代码、一份清单 package.xml、一种构建类型。读懂清单、声明对依赖，是工程化的第一步。

难度 ⭐⭐2 学时验证性关键词 package.xml · ament

01问题引入：为什么要"装包"

上一章编译 talker 时，你已经在每个源码目录里见过 package.xml——当时只说它是"包的身份证"，缺了 colcon 就不认这个目录。这张身份证上到底写了什么？为什么依赖要分门别类地声明？缺的依赖又怎么一键补齐？这一章把它拆开讲。

1
先看没有它会怎样：你的机器人有 20 个脚本——驱动、算法、启动文件……散落一地时无法交付。
2
同学拿到后问：先跑哪个？依赖什么库？接口消息哪来的？没人答得出。
3
ROS2 的答案：把"代码 + 清单 + 资源"打包为功能包，用机器可读的 package.xml 声明一切——身份证不是摆设，是写给 colcon、rosdep 和协作者看的契约。
4
类比：package.xml 就是 npm 的 package.json / Python 的 pyproject.toml——清单即契约。
定义 PackageROS2 中包含至少一个可执行/库文件、并带有 package.xml 清单文件的目录。上一章的工作空间管理"一批包"，这一章的功能包是"一个交付单元"——先把单元本身搞清楚，才谈得上把它们组织进工作空间、声明依赖、编译交付。

02核心原理：两种功能包类型

ament_python
纯 Python 包

setup.py + 模块目录 + entry_points 声明入口。无需编译（colcon 做安装），开发迭代最快。适合：应用逻辑、工具脚本。

ament_cmake
C++ 包

CMakeLists.txt 驱动编译，生成可执行/动态库并安装接口。适合：驱动、算法、性能敏感节点。

ament_cmake_python
混合包

C++ 为主但附带 Python 接口层（如机器人 SDK 同时给 C++ 库和 Python 绑定）。

interface 包
纯接口包

只有 .msg/.srv/.action 定义，无代码。独立成包可避免接口变更引发全量重编（EXP-09 详解）。

对比维度ament_pythonament_cmake
构建描述setup.py + setup.cfgCMakeLists.txt
清单两者都必须有 package.xml（格式 3）
编译耗时近零（安装型）随代码量增长
入口声明entry_points console_scriptsadd_executable + install
典型选择应用层/编排层驱动/算法/接口生成

03动画：从清单到可运行的依赖链

依赖的生命周期：声明 → 解析 → 补装 → 链接；四个环节任一断裂都会在"链接成功"处报错。其中 colcon Discovery 就是 EXP-03 第 02 节四阶段里的第①步，这里直接拿来用，阶段细节不再重复。

04专题：读懂 package.xml 与依赖标签

<!--?xml：格式 3 是当前标准 --?>（省略头部后）：
<package format="3">
  <name>my_test_pkg</name>
  <version>0.1.0</version>
  <description>我的第一个功能包</description>
  <maintainer email="you@mail.com">你的名字</maintainer>
  <license>Apache-2.0</license>
  <depend>rclpy</depend>                 # 编译+运行都需要（最常用）
  <buildtool_depend>ament_python</buildtool_depend> # 构建系统本身
  <exec_depend>ros2launch</exec_depend>  # 仅运行期需要（launch 文件）
  <test_depend>ament_lint_auto</test_depend> # 仅测试期需要
  <export><build_type>ament_python</build_type></export>
</package>
标签生效阶段典型用途
depend编译 + 运行默认选择：消息类型、客户端库
build_depend仅编译头文件/生成代码需要，运行用不到
exec_depend仅运行launch、 rviz 配置、脚本工具
buildtool_depend构建工具ament_cmake / ament_python 自身
test_depend测试lint、pytest 套件
为什么要分阶段声明依赖分阶段可以让 CI 只装构建依赖跑编译、部署镜像只带运行依赖——清单越精确，交付镜像越小、rosdep 解析越快。

06ros2 pkg / rosdep 命令精讲

# 创建包（在工作空间 src/ 下执行）；包名紧跟 create ——
# --dependencies 是可变长参数，包名放它后面会被当成依赖吞掉，报 package_name required
ros2 pkg create my_test_pkg --build-type ament_python \
  --node-name hello_node --dependencies rclpy

# 运行期自查三件套
ros2 pkg list                      # 系统里有哪些包
ros2 pkg prefix nav2_bringup       # 包安装在哪一层（层叠规则见 EXP-03 第 02 节）
ros2 pkg executables my_test_pkg   # 该包暴露哪些可执行文件

拆开看第一条命令：它的功能是在当前目录（必须是 src/）生成一个完整的包骨架——package.xml、setup.py、setup.cfg、resource/、test/ 目录和节点源文件一次建好，创建完直接 colcon build 就能编。各部分含义：

命令的组成部分作用本例产生的结果
my_test_pkg（位置参数）包的名字，决定目录名，也写进清单的 <name>；必须紧跟 create生成 src/my_test_pkg/ 目录
--build-type ament_python选构建系统：python 生成 setup.py 骨架；cmake 生成 CMakeLists.txt 骨架生成 setup.py、setup.cfg
--node-name hello_node顺手生成一个节点源文件，并把它登记进命令入口生成 my_test_pkg/hello_node.py，日后 ros2 run 可直接跑
--dependencies rclpy预写进 package.xml 的依赖清单，后面可空格跟多个包名清单里多一行 <depend>rclpy</depend>
# 依赖安装的事实标准：rosdep（只装清单里声明了的）
rosdep init      # 一生一次：写入系统级 sources.list.d（需 sudo）
rosdep update    # 更新「ROS包名 → apt包名」映射数据库
rosdep install --from-paths src --ignore-src -r -y
#  ↑  扫描 src 下所有 package.xml，缺什么装什么；-r 允许单条失败继续
rosdep 的本质它是一张翻译表：把 package.xml 里的 ROS 依赖名翻译成 apt/pip 的发行版包名。所以需要 init（装表）+ update（更表）两次动作。

07实操 A：建 ament_python 包，改三处完成话题闭环

1
进入工作空间 src/，用 ros2 pkg create 生成骨架（自动带 package.xml、setup.py、节点文件）。
2
根目录 colcon build --packages-select my_test_pkg，观察 Summary 行。
3
source 后 ros2 run 启动，观察"打一行就退"；用 ros2 pkg executables 核对入口点。
4
按下面三处改动把模板改成发话题的真节点（只改三处，不整份重写）。
5
重编再跑：窗口 1 每秒打印"发出: …"，保持运行。
6
另开窗口，用 EXP-02 学的 list / echo / hz 四条命令闭环验收。
cd ~/ros2_ws/src
ros2 pkg create my_test_pkg --build-type ament_python \
  --node-name hello_node --dependencies rclpy
cd ~/ros2_ws && colcon build --packages-select my_test_pkg
source install/setup.bash
ros2 pkg executables my_test_pkg   # → my_test_pkg hello_node
ros2 run my_test_pkg hello_node    # 输出 Hi from my_test_pkg. 后直接退出——模板只是 4 行 print 脚本，还不是真节点

生成的模板文件其实只有 4 行 print——没 import rclpy、没有节点、没有 spin，所以打完就退出，ros2 node list 里自然也查不到它。现在把它改成真节点，每秒往 /chatter 发一条消息。这是第一次改代码，不整份重写，跟着三处改动做，每处都写清楚加什么、加在哪。

第 0 步，先看看现在的文件长什么样（一共就 4 行）：

cat ~/ros2_ws/src/my_test_pkg/my_test_pkg/hello_node.py
# def main():  print('Hi from my_test_pkg.')，加上两句入口调用——
# 没有 rclpy、没有节点、没有 spin，所以打完就退出，连 node list 都查不到

改动 1｜文件最顶部（def main 之前）加三行 import：

import rclpy
from rclpy.node import Node
from std_msgs.msg import String   # 缺模块时：sudo apt install ros-humble-std-msgs

改动 2｜紧接着 import 下面、def main 之前，加一个节点类——发布者和定时器都在这里：

class HelloNode(Node):
    def __init__(self):
        super().__init__('hello_node')
        self.pub = self.create_publisher(String, 'chatter', 10)  # 发布者：话题 chatter，队列 10
        self.timer = self.create_timer(1.0, self.tick)           # 每秒调一次 tick
        self.n = 0

    def tick(self):
        self.n += 1
        self.pub.publish(String(data=f'Hello World: {self.n}'))
        self.get_logger().info(f'发出: Hello World: {self.n}')

改动 3｜把原来整个 def main 函数换成下面这 4 行（print 换成初始化 + spin；spin 让进程停在这里持续发消息，不再打完就退）：

def main():
    rclpy.init()
    rclpy.spin(HelloNode())
    rclpy.shutdown()
# ⑦ 保存后重新编译、运行，用上一章的命令验收
cd ~/ros2_ws
colcon build --packages-select my_test_pkg   # 改了源码必须重编（--symlink-install 可省这步，见 EXP-03 第 02 节）
source install/setup.bash
ros2 run my_test_pkg hello_node              # 窗口 1：每秒打一条"发出: …"，保持运行

# 窗口 2：EXP-02 学的四条命令逐项验收
ros2 node list              # → /hello_node   节点活着
ros2 topic list             # → /chatter      话题在
ros2 topic echo /chatter    # → 每秒一条 data: 'Hello World: N'
ros2 topic hz /chatter      # → 约 1.0 Hz     频率对

四项全中，闭环完成：自己建包 → 改代码 → 选定包编译 → 运行 → 用上一章的工具验收。以后每个新包都走这一套，只是把 my_test_pkg 换成你自己的包名。

08实操 B：创建 ament_cmake 包并看依赖生效

cd ~/ros2_ws/src
ros2 pkg create cmake_pkg_demo --build-type ament_cmake \
  --dependencies rclcpp std_msgs
# 查看生成的清单里 <depend> 是否落盘
grep depend cmake_pkg_demo/package.xml
cd ~/ros2_ws && colcon build --packages-select cmake_pkg_demo
# 成功后查看两层产物
ls install/cmake_pkg_demo/lib/   # C++ 可执行安装位置
ros2 pkg prefix cmake_pkg_demo   # 确认走上层 Overlay

再回看 src/cmake_pkg_demo/CMakeLists.txt：find_package(rclcpp REQUIRED) 与 package.xml 里的 depend 必须成对出现——清单管"装不装"，CMake 管"链不链"。

09注意事项与验收清单

  • package.xml 是 format="3"，name/version/maintainer/license 四件套齐全
  • 声明的 depend 与代码实际 import/find_package 一致，不漏不多
  • ros2 pkg executables <包名> 能列出自己的节点入口
  • 闭环验收：hello_node 改三处后重编，ros2 topic list 有 /chatter，ros2 topic hz /chatter 约 1.0 Hz
  • 能区分 build/exec/test 三种依赖阶段并说出各自的用途
  • 会用 rosdep install --from-paths src 一键补齐依赖
  • python 包与 cmake 包各建一个且都 build 成功
坑症状解法
在错误目录 create包生成在 ~/ 而非 src/，colcon 扫不到必须先进入 src/ 再 pkg create
包名写在 --dependencies 后面error: the following arguments are required: package_name--dependencies 是可变长参数，会把后面不带 - 的词全当依赖吃掉；包名紧跟 pkg create 写
清单与 CMake 不一致build 报 Could not find a packagepackage.xml 与 find_package 成对补；或用 rosdep 重扫
改了入口点没反应ros2 run 找不到新节点检查 setup.py entry_points 后重编（构建描述变更不走 symlink）
rosdep 从没 init/updateERROR: No sources list filesudo rosdep init + rosdep update 各一次

10本课总结与思考题

单元
Package = 代码 + 清单

package.xml 是机器可读的契约，工作空间负责组织一批包。

类型
python / cmake / 混合 / 接口

按性能与交付形态选型，接口独立成包可解耦重编。

依赖
分阶段声明

depend / build / exec / test 各管一段生命周期，越精确越干净。

工具
ros2 pkg + rosdep

pkg 自查包状，rosdep 按清单翻译并补装系统依赖。

思考题 ① 一个 C++ 包用了 geometry_msgs 的消息，但只在运行期通过插件加载——依赖该写 depend 还是 exec_depend？各自代价是什么？
② 若同事机器上 rosdep install 一切正常但你报 Could not find rclcpp，可能有哪三个原因？（提示：没装 ROS2 / 没 source / 装的发行版不同）
