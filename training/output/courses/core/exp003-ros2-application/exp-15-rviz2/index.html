rviz2 三维可视化：机器人的"上帝视角"

RViz（Robot Visualization，机器人可视化）在 ROS 2 里的名字就是 rviz2——机器人开发的三维"取景器"：订阅激光点、TF 坐标轴、机器人模型、规划路径这些"空间话题"，实时画成三维画面，让 echo 里滚动的数字变成一眼看懂的图形。应用场景贯穿开发全线：装配阶段看 URDF 模型转没转、调试阶段看雷达点云装没装正、导航阶段看规划路径穿不穿墙，bag 回放验收也以它为统一窗口。本课从 Fixed Frame 讲到七大核心 Display。

难度 ⭐⭐2 学时验证性关键词 rviz2 · Fixed Frame · Display · TF 可视化

目标本课学完，你应该能做到

① 说清架构
OGRE + Display 插件

能阐述 rviz2 基于 OGRE 渲染引擎与 Display 插件体系的架构——为什么需要"以坐标系为容器、以 Display 为图层"的三维可视化，以及 Fixed Frame 的核心地位。

② 掌握配置
七大 Display

能正确设置 Fixed Frame，并依次添加配置 RobotModel、TF、LaserScan、PointCloud2、Image、Path、Marker 七种 Display。

③ 独立完成
配置可复现

能用 rviz2 -d <config> 加载配置，调整后通过 File → Save Config 保存，实现调试环境一键复现。

④ 迁移应用
当标准可视化前端

在后续 bag 回放、URDF 模型验证、仿真可视化中，能把 rviz2 作为标准三维前端按需配置。

本课的重点与难点 重点：Fixed Frame 选错 = 一片黑。这是 rviz2 最高频的"故障"，其实根本不是故障。
难点：理解 rviz2 只是"消费者"——没有 TF 和 /robot_description 的发布者，它什么都画不出来。
和前后的关系 本课是 EXP-19 TF2 与 EXP-20 URDF 的可视化出口，两课都会用 rviz2 做验收。

01问题引入：机器人眼中的世界长什么样

先回忆EXP-06 里 topic echo 打出来的一串串数字（浓度、温度、坐标）、消息头里的 frame_id——这些抽象数据本章要变成看得见的图形。rviz2 就是所有话题数据的"显示器"，也是后面 TF、URDF、导航的可视化舞台。
1
盲人摸象

echo /scan 一屏数字：[2.31, 2.29, 2.35...]——你知道前方有障碍，但不知道形状

2
空间数据

激光点云、机器人模型、路径轨迹，本质都是 3D 空间的点和形状

3
直观验证

导航规划的路径对不对？模型装配的关节转没转？一眼看穿 vs 十分钟 echo

4
正解

rviz2 把消息"画"进三维视口——调试 IMU/雷达/TF/模型的统一窗口

定义 rviz2（ROS Visualization 2）是 ROS2 的三维可视化工具：订阅你关心的话题，把消息内容渲染成几何图形。它不生产数据、不控制机器人，只是一个"取景器"——所以画面异常时，问题通常在数据源（话题/TF）而不在 rviz 本身。

02先看现象：一条命令看见机器人

不写一行代码，两条命令 + 四个动作把"话题里的数字"变成三维画面——照做 2 分钟内看到结果。画面为什么能出来，03 节拆原理；每步的细节在 04 节。

生产者 ×2 + 消费者 ×1（哪 3 个，04 节用 node list 证明）

03原理讲解

Fixed Frame 决定"上帝站在哪"

灵魂参数
Fixed Frame：观测基准系

它回答"相机架在哪个坐标系上看世界"。设成 map：整张地图静止，机器人在图上移动；设成 base_laser：机器人钉在原点，墙壁绕着车动。所有数据都会被 TF 变换到这个系再画。

变换链
TF2 逐层查找

雷达点云 frame_id=laser → 沿 laser→base_link→odom→map 链逐级算到 Fixed Frame。链上任何一环断裂，该 Display 立即报黄 "Transform [sender=unknown]"——这就是 rviz 满屏黄字的第一大原因。

刷新节奏
Frame Rate 30 + 按需重绘

默认每秒渲 30 帧。它只消费数据不驱动系统：把 Fixed Frame 改掉、关掉某个 Display，被调试的机器人毫发无损——放心折腾。

怎么设置 Fixed Frame（可照抄） ① 界面改（即时生效）：Displays 面板顶部 Global Options → Fixed Frame，下拉选或直接敲 frame 名。
② 随配置带入：rviz2 -d ~/ros2_ws/install/car1_description/share/car1_description/rviz/car1.rviz（这份配置里 Fixed Frame = base_footprint）；导航配置 navigation.rviz 里是 map。
③ 裸启默认：rviz2 无配置时默认 map。回放联调时再加 --ros-args -p use_sim_time:=true（用法详见 EXP-11）。
Fixed Frame 设成画面效果典型用途
map地图静止，机器人在地图中移动导航调试（默认值就是它）
odom忽略全局定位漂移，看相对里程检查里程计平滑度
base_link / base_laser车体钉在原点，环境绕着车动检查单传感器安装与标定
某个不存在的 frame全屏黄 Warning，画面冻结不用管——这就是下节诊断台要抓的症状
本课案例用法：04 节第 4 步加载 car1.rviz（Fixed Frame=base_footprint）看整车；导航实操切 navigation.rviz（=map）看全局——两份配置的差别就是观测基准换了。
失败模式 判断"rviz 坏了还是系统坏了"的分界线：能把数据画出来的前提是"变换链通"。任何 Display 变黄先查 TF（Add → TF 看坐标轴在不在），而不是先怀疑 rviz。TF 通了还有问题，才去查话题本身（有没有数据、QoS 配不配）——完整排查顺序见 04 节"黑屏诊断台"。

对照图 15-1（display.launch.py 启动实拍）：rviz2 主窗左侧面板分两段——上半 Displays 回答"画什么"，下半 Views 回答"从哪看"。下面按面板顺序把常用参数讲清，图中数值即当前 car1.rviz 配置的实测值。

参数含义

参数图中值含义

Focal Shape Size + Fixed Size0.05 · ✓焦点辅助小球的显示大小；勾 Fixed=像素恒定不随远近变
Save / Remove / Rename / Reset—视角方案管理：常用机位存盘复用；Reset 恢复默认 = 视角迷路的第二保险（第一保险是右键 → Reset View）
面板底下那行提示 = View Controller 键位（可照抄） Left-Click 旋转（对应 Yaw/Pitch）、Middle-Click 平移（对应 Focal Point 平移）、Right-Click / 滚轮 缩放（对应 Distance），Shift+ 触发更多组合键。鼠标手势和上面的数值是同一台相机的两种操作入口——拖完再看 Views 数值会动，这就是"左手感、右手参数"。
顺带认两个窗：左侧 joint_state_publisher_gui 的滑块（wheel_*_joint / arm_joint*）拖动即改 /joint_states → robot_state_publisher 重算 TF → 右侧模型与坐标轴跟随；rviz2 标题栏的 car1.rviz* 带星号 = 有未保存修改，File → Save Config 落盘后星号消失。

七大 Display 逐个拆

① 地基
Grid

默认就有的网格地面，提供空间标尺。迷失视角时右键 → Reset View 一键回正——这是新手最该记的肌肉记忆。

② 骨骼
TF

Add → TF 自动订阅 /tf 与 /tf_static，RGB 三轴画出每个坐标系，Show Names 显示名字。断链=某段坐标轴消失，比 view_frames 生成 PDF 实时得多——PDF 是快照，TF 图层是直播。

③ 外形
RobotModel

读 Description Topic（/robot_description）画网格式车体。需要三方协作：URDF 定结构 → robot_state_publisher 按 /joint_states 算各 link 变换 → rviz 渲染。调试可关 Visual 只留 Collision、调 Alpha 半透明看内部。

④ 感知
LaserScan

Topic 选 /scan，Size 约 0.03。极坐标点变换成 3D 空间点，Color Transformer 按距离映射颜色（近红远绿）。前提：frame_id 必须在 TF 链上，否则黄字。

⑤ 点云
PointCloud2

深度/视觉相机的点云。fields 描述每点的打包结构，RGB 常按 FLOAT32 打包——结构对不上颜色就乱。数据量大时调降 Point Size、抽稀订阅。

⑥ 规划
Path

nav_msgs/Path 折线，如正弦的 /plan。算法对不对，曲线一眼定：折角突变=规划抽风，路径穿墙=代价地图有洞——比读坐标数组快两个数量级。

⑦ 标注
Marker

万能便签：SPHERE/ARROW/TEXT_VIEW_FACING/Cube/LineStrip 形状，action 分 ADD/DELETE/MODIFY，ns+id 定位实例。想在画面里标"目标点 3"？发个文字 Marker 即可，不用给 rviz 写插件。

配置资产
.rviz 文件

File → Save Config As 导出全部 Display 设置；下次 rviz2 -d xxx.rviz 一键还原。团队共享后，新人开箱即是同款调试视图——配置是工程资产，进 git。

三方协作链 RobotModel 不显示时，按数据流逆向查四步：① ros2 topic echo /robot_description --once（URDF 在不在）→ ② ros2 node list | grep state_publisher（rsp 活没活）→ ③ ros2 topic echo /joint_states（关节数据来没来）→ ④ Fixed Frame 是否与 link 树根连通。外加 check_urdf 校验模型语法。
✅ 结论：每个 Display 独立订阅、独立变换、独立报错，按图层隔离故障⚠️ 风险：Topic 没勾/选错 → 图层空白；frame_id 不在 TF 链 → 黄字🔍 验证：04 节实操截图①~⑥ + 导航实操"图层逐个点亮"

    ⚠ 最高频的坑：只开"消费者"没开"生产者"
    新手最常犯的错误就是直接敲 rviz2 -d car1.rviz，然后发现：画面全黑 / 车不显示 / ros2 topic list | grep tf 是空的 / tf2_echo base_footprint base_link 一直报
    Invalid frame ID "base_footprint" ... frame does not exist。


    这不是 rviz 坏了，也不是 tf2_echo 的 bug——因为 TF 树和 /robot_description 是 robot_state_publisher 发的，你只开了显示窗口，没人生产数据，rviz 自然是空的。


    ✔ 正确姿势：永远用 launch 一次把生产者和 rviz 都起好——
    
ros2 launch car1_description display.launch.py
    
它同时启动 joint_state_publisher_gui + robot_state_publisher + rviz2，才有东西可看。
    


    一句话记住：TF 永远要问"谁在发"——只有 robot_state_publisher（配合 joint_state_publisher）在跑，base_footprint 才存在。
  

  

    原理：为什么先查 glxinfo
    rviz2 依赖 OGRE→OpenGL 渲染，需要驱动提供硬件上下文。板卡（如 RK 系列 Mali-G52）驱动缺失或跑在 llvmpipe 软件渲染上时，轻则卡成幻灯片，重则启动即退。渲染能力是 rviz2 的地基，比任何 Display 设置都更靠前——黑屏第一问永远是"驱动正常吗"。

顺带记录：rviz2 退出时的 Segmentation fault 不是故障
    只开 rviz 时，Ctrl+C 退出 rviz2 会打印 Segmentation fault (core dumped)——这是 rviz2/Ogre 在 ARM 上退出时的常见崩溃，不影响任何功能，别当成故障去排查。
    

  


  

    报错逐行解码（照着对号入座）
    Package 'py_nodes' not found —— 本机没装这个包名；命令引用了一个不存在的包，改成本机真实包名（如 car1_description）。

    -bash: $: command not found —— 你把文档里的提示符 $ 一起复制进终端了；$ 不是命令，删掉即可，这行不算错。

    topic list 输出为空 —— 关键证据：没有发布者，所以没有话题。

    tf2_echo 一直 Waiting + frame does not exist —— 同上，TF 树不存在。

    开头那行 Waiting 一闪而过 —— 那是启动瞬间的竞态（subscriber 还没建好），紧接着就来数据，属正常，不用管。
  


  
环境提醒：venv 与系统 Python
  若当前 shell 在 ros2_venv 之类的虚拟环境里，C++ 写的 robot_state_publisher 不受影响；但将来跑 Python 节点时要留意 venv 与系统 Python 冲突——ROS2 的 Python 节点依赖系统 rclpy，混用 venv 可能 import 失败。跑 Python 节点前建议 deactivate 后只用 source /opt/ros/humble/setup.bash。

4用 ros2 topic 逐个核对图层是否真有数据终端 3

    
rviz 画不出东西时，第一件事就是回到命令行确认"数据在不在"。用频率、QoS、内容一眼判断：

    
ros2 topic hz /scan                          # 雷达图层：COIN-D6 通常 10Hz 上下（以现场为准）
ros2 topic info /map --verbose               # 地图图层：QoS 里应有 Durability: TRANSIENT_LOCAL
ros2 topic echo /plan --once                 # 路径图层：派了目标点后才有数据
ros2 run tf2_ros tf2_echo map base_link      # 定位图层：map→车体

    
$ ros2 topic hz /scan
average rate: 10.02
$ ros2 topic info /map --verbose
Type: nav_msgs/msg/OccupancyGrid
Publisher count: 1
QoS profile:
  Durability: TRANSIENT_LOCAL   # ← 地图用 latched，晚订阅也收得到
$ ros2 run tf2_ros tf2_echo map base_link
Translation: [1.234, -0.567, 0.000]       # ← 车在地图里的实时位置

    
⚠ 两处输出格式细节（照原稿写会找不到）
    ① QoS 字段实际打印为 Durability: TRANSIENT_LOCAL（在 QoS profile: 段内），不是 Durability Policy: Transient Local。

    ② tf2_echo map base_link 若报 extrapolation / frame 不存在，说明 amcl 还没收敛——先去 rviz 用 2D Pose Estimate 给一个初始位姿，再回来查。

  


  
rviz2 窗口第 5 步 · 2D Pose Estimate / 2D Goal Pose看界面

  

    
5亲手给机器人"指位置"和"派任务"rviz 窗口

    
navigation.rviz 里确实预装了这三个工具：SetInitialPose(/initialpose)、SetGoal(/goal_pose)、PublishPoint(/clicked_point)。用法就是拖箭头：

    
# rviz 顶部工具栏两个关键按钮：
2D Pose Estimate  → 在地图上按住拖一个箭头 = 告诉 amcl "车大概在这，朝这个方向"
                     松手后 /initialpose 发出，粒子云立刻向该处聚拢
2D Goal Pose      → 拖一个目标箭头 = 给 nav2 派目标
                     松手后 /goal_pose 发出 → 出现全局路径(绿) + 局部路径(蓝)

    
操作 2D Pose Estimate 后应看到：
粒子云（/particle_cloud）向箭头处聚拢——定位收敛
操作 2D Goal Pose 后应看到：
/plan 绿线（全局路径）+ /local_plan 蓝线（局部路径）出现
若路径不出现 → 回到终端 3 用 ros2 topic echo /plan --once 确认有无数据

06本课总结与验证题

  

    
定位
取景器，不是数据源
rviz2 只订阅、变换、渲染；异常优先查话题与 TF，而不是怀疑视图工具。

    
灵魂
Fixed Frame 是观测基准
一切数据变换到它才绘制；换帧=换视角，地图系看全局、车体系看感知。

    
图层
七 Display 按需叠加
Grid/TF/RobotModel/LaserScan/PointCloud2/Path/Marker 各管一维，按图层隔离故障。

    
资产
.rviz 配置进 git
团队共享调试视图，与 launch、params 一样属于可复现工程资产。

  

  
验证题（改动型 · 每题先自己作答，再展开核对）

1（目标①·改设置）正在用 car1.rviz 调车（Fixed Frame=base_footprint，模型稳、坐标轴跟着关节动）。把 Fixed Frame 改成 laser（雷达系）后重看画面：小车模型和激光点谁会"绕着动"？为什么？

参考答案与得分点
得分点：①Fixed Frame 变观测基准 → 车体会随关节/外参绕动，激光点云反而钉住不动（在它自己的系里）②一切 Display 都被变换到 Fixed Frame 才绘制，基准变了=换相机架的位置 ③frame 必须真实存在，否则黄字。（①②各 40%，③ 20%）



2（目标①③·改流程复现故障）按 Ctrl+C 停掉 display.launch 后，只敲 rviz2 -d car1.rviz。预期 ros2 topic list | grep tf 输出是什么？tf2_echo base_footprint base_link 会报什么？指出根因和恢复的正确命令。

参考答案与得分点
得分点：①topic list 无 /tf /robot_description 输出（无发布者）②报 Invalid frame ID "base_footprint" ... frame does not exist/一直 Waiting ③根因：只起了消费者 rviz2，生产者 robot_state_publisher 没起 ④恢复：ros2 launch car1_description display.launch.py。（①②④各 25%，③ 25%）



3（目标②·加图层）要在 rviz 里显示深度相机点云（话题 /camera/depth/points，类型 PointCloud2）：写出 Add 的 Display 类型与要改的两个属性；若加上后图层 Status 报黄，先查哪两样？

参考答案与得分点
得分点：①Add → PointCloud2 ②Topic 勾选并设为 /camera/depth/points、Color Transformer/Size 按需 ③黄字两查：header.frame_id 是否在 TF 链上（Add → TF 看该坐标轴在不在）、Fixed Frame 是否写错 ④相机没起时先 ros2 topic hz /camera/depth/points 确认有数据。（①②各 30%，③ 40%）



4（目标③·改配置传播）你把 Fixed Frame 临时改成别的值调试后，直接 File → Save Config 覆盖了 car1.rviz 并提交。队友 rviz2 -d 加载后满屏黄字。错在哪一步？给出修复与今后避免的做法。

参考答案与得分点
得分点：①调试用的临时 Fixed Frame 被存进了共享配置 ②修复：改回 base_footprint 再 Save Config（或 git checkout 恢复）③避免：调试改动另存 nav_debug.rviz，共享配置只存团队约定口径 ④配置是工程资产、进 git 需 review diff（YAML 可读）。（①40%，②20%，③25%，④15%）



5（目标④·改环境接回放）接下来要用 EXP-16 的 rosbag 回放数据在 rviz 里复现现场：命令要补什么参数？漏了会看到什么现象？

参考答案与得分点
得分点：①ros2 bag play xxx --clock 与 rviz2 --ros-args -p use_sim_time:=true 双开关 ②漏开则 rviz 的 now=今天、消息 stamp=录制日 → Transform 时间外推报错/数据不更新 ③Time 面板（Panels → Add New Panel → Time）随回放走=对钟成功。（①②各 40%，③ 20%）
