TF2 坐标系变换：让机器人知道自己"在哪、朝哪"

雷达一帧有 360 个点、摄像头一张图有几万个像素，但它们各自活在自己的坐标系里。本实验吃透 TF2 的树状变换原理与四元数表示，实现静态/动态坐标发布，并用 tf2_echo / view_frames 完成可视化验证。

话题通信实战 tf2_ros 四元数 view_frames 前置：EXP-06 话题通信 硬件：实验箱 B2 / 小车 C1

01 引例：这束激光该画在哪

1场景：小车顶部装了一台 2D 激光雷达，正前方 30cm 处有一个障碍物——这是相对雷达自己的说法（活在 laser_frame）。
2问题：建图算法、导航算法、机械臂抓取……它们需要的都是相对车体中心（base_link）甚至相对世界原点（map）的坐标。30cm 的雷达读数，直接丢给建图节点，地图就歪了。
3需求：必须有一个"翻译官"，随时回答——"雷达系里的点 (30, 0)，换算到车体系是多少？换算到地图系又是多少？"
4答案：ROS2 的 TF2（Transform Library）。它把机器人身上的每个部件定义为一个坐标系，维护一张"坐标系变换树"，任何两个坐标系之间都能算出变换关系。
💡 核心定位TF2 不是可有可无的辅助库——没有 TF2，多传感器融合、SLAM、导航、机械臂抓取全部无从谈起。它是"多坐标系数据能对齐"的地基。

02 原理：TF2 树为什么长成一棵树

2.1 树状结构：只记"直接父子"，路径唯一

TF2 把所有坐标系组织成一棵有根树（严格说是 DAG 的树形约束）：每个坐标系最多一个父坐标系。机器人上的典型结构：

ROOT · 世界
map

全局地图原点，由 SLAM / 定位节点维护，漂移会被不断修正。

里程计系
odom

轮式里程计原点，短时间平滑但会长期漂移。

车体系
base_link

机器人本体中心，一切传感器都最终挂到它身上。

传感器系
laser_frame / camera_link

雷达、相机各自的测量原点，安装位置即静态变换。

2.2 查询算法：沿树上溯，O(深度)

  1. 要算 A → B，先沿树向上回溯，把 A 到根路径上所有变换收集起来；
  2. 再从 B 沿树回溯到根；
  3. 找到两条路径的汇合点，沿途变换按逆序 / 顺序连乘，即得 A→B 的合成变换。
✦ 为什么禁止成环？如果 A→B、B→C、C→A 构成环，汇合点算法将永远找不到终止，查询陷入死循环。所以 TF2 强制树形结构、每个 frame 只能有一个 parent——这是查询能在有限步内完成的前提。（发布两个节点抢同一个 child frame 的 parent， actively 报错警告。）

2.3 两条话题，两种更新策略

话题内容QoS / 频率设计意图
/tf动态变换（odom→base_link、机械臂关节角…）10 ~ 100 Hz 普通 Reliable + KeepLast(100)量大、值一直在变，新订阅者只需拿到"最新值"，历史旧值没有意义 → KeepLast 限深
/tf_static静态变换（雷达到车体的安装位姿…）一次性发布，QoS = Transient Local（latch）装好就不变；后启动的节点也必须能拿到 → 靠 Transient Local "重放"最后一条给新订阅者（同 ROS2 参数的 transient_local 语义）
🔁 和 EXP-10 参数的呼应/tf_static 的 latch 语义与"参数默认值能被后加入节点读到"是同一套 QoS 机制。这就是"原理可迁移"——学透 QoS，这里的Latch行为一看就懂。

2.4 谁来发布？

  • 静态：自己写死的安装位姿 → 用 StaticTransformBroadcaster 发一次即可（驱动包通常已经发好）；
  • 动态：里程计节点发 odom→base_link，SLAM 发 map→odom，URDF 关节状态发 base_link→各 link——你不需要自己算全树，只需发布"你负责的那一段边"，其余由系统自动合成。

04 原理专题：旋转为什么要用四元数

4.1 欧拉角的三宗罪

表示法表达问题
欧拉角 (roll, pitch, yaw)直观，人眼能理解"偏航 30°"① 万向节死锁：俯仰 ±90° 时丢失一个自由度；② 插值不均匀，动画打结；③ 顺序敏感（ZYX vs XYZ 结果不同）
旋转矩阵 3×39 个数，乘法直接复合冗余（只有 3 个自由度却用 9 个数），累积浮点误差后可能不再正交，需周期性重新正交化
四元数 q=(x,y,z,w)4 个数，无奇点ROS2 的标准选择：万向节死锁不存在、插值用 Slerp 均匀平滑、复合只要哈密顿乘法

4.2 2D 平面旋转的半角公式（本实验只需 yaw）

机器人在地面打转，本质是绕 Z 轴转 yaw 角。此时四元数退化为两个非零分量：

# 绕 Z 轴旋转 yaw：四元数只有 z、w 两个分量非零
z = sin(yaw / 2)
w = cos(yaw / 2)   # x = y = 0

# yaw = 90°  ⇒  z = sin45° = 0.7071,  w = cos45° = 0.7071
# yaw = 180° ⇒  z = sin90° = 1.0,     w = cos90° = 0.0
# 反解：yaw = 2·atan2(z, w)   ← 看代码时反过来算角度就用它
💡 记忆锚点"半角"是关键：四元数存的是 yaw/2 的三角函数。验证：yaw=180° 时 w=0、z=1，正好是"转满半圈的信息被编码在半角空间里"。看别人的代码看到 atan2(z, w) * 2 就是在从四元数反求偏航角。

4.3 在 ROS2 消息里长什么样

geometry_msgs/msg/Transform = translation(x,y,z) + rotation(x,y,z,w)；Quaternion 四个字段顺序固定为 x, y, z, w（不是 w,x,y,z！阅读时留心）。

06 代码精讲：发布者与查询者

6.1 发布静态变换（实操 1 要写的）

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TransformStamped
from tf2_ros import StaticTransformBroadcaster

class StaticTfPub(Node):
    def __init__(self):
        super().__init__('static_tf_pub')
        # ① StaticTransformBroadcaster —— 内部自动用 /tf_static + TransientLocal
        self.pub = StaticTransformBroadcaster(self)
        self.send()

    def send(self):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id  = 'base_link'   # 父
        t.child_frame_id   = 'laser_frame'  # 子（只能有一个父！）
        t.transform.translation.x = 0.10    # 雷达在车体前方 10cm
        t.transform.translation.z = 0.20    # 高度 20cm（TF2 支持 3D）
        # 无旋转 ⇒ 单位四元数 (x=0, y=0, z=0, w=1)
        t.transform.rotation.w = 1.0
        self.pub.sendTransform(t)   # 只发这一次，后加入的订阅者也能收到

6.2 查询变换（下游节点的标准姿势）

from tf2_ros import Buffer, TransformListener

self.buffer = Buffer()
self.listener = TransformListener(self.buffer, self)   # 监听 /tf + /tf_static 填充 buffer

# 查询 laser_frame 的数据 → map 系；超时 1.0s（树还没齐时阻塞等待）
t = self.buffer.lookup_transform(
    'map', 'laser_frame',
    rclpy.time.Time(),      # Time()=最新时刻；传具体时间则做历史插值
    timeout=rclpy.duration.Duration(seconds=1.0))
tx = t.transform.translation.x
qz, qw = t.transform.rotation.z, t.transform.rotation.w
yaw = 2.0 * math.atan2(qz, qw)   # 第 4 节半角公式反解
✦ 设计看点① 查不到时不是崩溃而是超时等待——因为发布者可能后启动；② TransformListener 就是普通的订阅节点，把两条话题的值缓存进 Buffer；③ 发布者只发一条静态边，查询者却能跨整棵树——解耦靠的就是 /tf 这对公共话题，和 EXP-06 的话题解耦完全同构。

07 实操 1 · 创建 tf2_demo 包并发布静态变换

1进入工作空间并创建包（依赖 tf2_ros 负责发布/监听，tf2_tools 提供 view_frames 等调试工具）：
cd ~/ros2_ws/src
ros2 pkg create tf2_demo \
  --build-type ament_python \
  --dependencies rclpy tf2_ros tf2_tools geometry_msgs \
  --destination-directory .
2把 6.1 的 StaticTfPub 写入 tf2_demo/static_tf_pub.py，加执行权限；在 setup.py 的 entry_points 注册 static_tf_pub = tf2_demo.static_tf_pub:main（同 EXP-05 要求）。
3补一个 main()：
def main(args=None):
    rclpy.init(args=args)
    node = StaticTfPub()
    rclpy.spin(node)      # spin 保持节点存活，静态消息靠 QoS 重放
    node.destroy_node()
    rclpy.shutdown()
4构建并 source，启动发布者：
cd ~/ros2_ws && colcon build --packages-select tf2_demo
. install/setup.bash
ros2 run tf2_demo static_tf_pub

08 实操 2 · 三种手段验证 TF 树

1命令行直查——对应第 3 节动画的一次 lookup：
ros2 run tf2_ros tf2_echo base_link laser_frame
# 输出 Translation: [0.1, 0.0, 0.2]  Rotation: [0,0,0] (x,y,z,w)
# 至 Ctrl+C 前会持续刷新（动态边场景下数值会变）
能打印出变换矩阵 = 链路可用。
2导出整棵树——生成 PDF 树状图（离线图片在 ~/.ros 下，名为 frames.pdf）：
ros2 run tf2_tools view_frames
# 订阅 /tf、/tf_static 5 秒 → 打印每个 frame 的发布频率与超时告警 → 生成 frames.pdf
检查：是否为合法树形（无环、每个 child 只有一个 parent）。
3RViz 可视化——启动 rv2，Add → By display type → TF，勾选 Frames / Names / Arrows；若同时播传感器数据（如选用真实小车则执行 ros2 launch car_common car_bringup.launch.py），把 Fixed Frame 设为 map，观察点云/激光是否落在车体与地图的正确相对位置——对不上 = TF 有问题。
4纯软件自检（可选）——再写一个 tf2_echo 风格的查询节点（6.2 代码），打印 base_link→laser_frame 的 yaw 反解值，应与发布的平移/零旋转一致。
💡 从"验证"学"调试"排查 TF 的三板斧就是本节顺序：tf2_echo 查单边 → view_frames 查全树 → RViz 查最终效果。实际项目里 90% 的"数据对不齐"，用这三步五分钟内能定位到是哪条边断了/错了。

09 注意事项与验收

⚠️ 注意事项

类别说明
禁环防空转TF2 是有根树，严禁成环；同一 child_frame 被两个节点配不同 parent 发布时会报错警告（"frame conflicts"）。
时间戳一致动态查询默认按最新时刻对齐；多源数据融合时显式传时间戳，否则插值错位会出现"点在地图上漂"。
静态用对 Broadcaster静态变换务必用 StaticTransformBroadcaster（/tf_static + latch）。用普通 TransformBroadcaster 循环重发静态值 → 占带宽、后加入节点仍可能漏。
四元数单位化rotation 必须满足 x²+y²+z²+w²=1；(0,0,0,1) 表示零旋转；自算角度后记得转四元数再塞进消息。
牢记报错就在现场Lookup would require extrapolation = 时间戳超出缓冲窗口（常见于缓冲太短或时间不同步），先检查各节点 use_sim_time 是否一致。

✅ 验收标准

  • tf2_demo 包编译通过，ros2 run tf2_demo static_tf_pub 正常启动无异常
  • tf2_echo base_link laser_frame 输出平移 [0.1, 0, 0.2]、旋转单位四元数
  • view_frames 生成 frames.pdf，肉眼确认树形合法（base_link→laser_frame 单父、无环）
  • 独立终端 ros2 topic echo /tf_static --qos-durability transient_local 能读到静态变换消息
  • RViz TF display 显示坐标轴与箭头，各 frame 标签正确
  • 页面交互台：拖 yaw 到 180° 能说出 w=0 的原因；链查询能报出跨 3 层的拼接路径

10 实验总结与思考

成果
发布并验证了一条静态 TF 边

tf2_demo 包 + StaticTransformBroadcaster，三级验证手段（echo / view_frames / RViz）全通过。

原理
树 + 连乘 + 缓冲

TF2 = 有根树（无环保证查询终止）+ 边的连乘合成 + 带时间戳的 Buffer 缓冲插值。

QoS
动态 KeepLast vs 静态 Transient Local

/tf 要"最新"、/tf_static 要"后到也有"——同一套 QoS 机制的两种业务化用法。

迁移
四元数反解 yaw

2·atan2(z, w) 是读码必备；机械臂姿态、相机位姿都是同一套四元数。

🧠 思考题

  1. 为什么 /tf_static 只需要发一次，而后启动的 view_frames 依然能看到这条边？如果把它改成默认 QoS（KeepLast、Volatile），会出现什么现象？
  2. 四元数半角公式里，为什么是 yaw/2？当 yaw 从 179°转到 181°时，(z, w) 数值发生了什么变化，这对纯数值插值意味着什么？（提示：对照欧拉角插值的跳变问题）
  3. 如果里程计节点把 odom→base_link 发到了 /tf_static 上，车开动后 TF 树会发生什么？从 QoS 语义解释。
