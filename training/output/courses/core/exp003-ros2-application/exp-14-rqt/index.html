EXP-14 · 第四章 · 验证性 · 2 学时

rqt 可视化工具箱：GUI 调试六件套

对着终端敲 echo、grep、awk，是命令行侠的浪漫，但效率有天花板。rqt 是 Qt 插件化调试工作台：图形看拓扑、曲线看波形、滑块改参数——把"查/看/调"三件事从终端搬进 GUI。本课讲清插件架构原理，实战六大核心插件。

难度 ⭐2 学时验证性关键词 rqt_graph · rqt_plot · rqt_console · rqt_reconfigure

01问题引入：黑盒调试的困局

1
故障

小车导航突然停了，报错只有一句 "no feedback from controller"

2
盲查

开 5 个终端分别 echo 各话题、grep 日志——10 分钟过去还没看清链路

3
核心问题

节点关系是什么？哪条话题断了？波形哪里跳变了？终端很难一眼回答

4
换武器

rqt_graph 一张图看拓扑，rqt_plot 一条曲线看跳变，3 定位断点

定义 rqt 是基于 Qt 的插件化调试工作台：本体只提供菜单、停靠窗口和插件管理，所有功能（画图、过滤、调参……）都是可热插拔的插件。你看到的 rqt_graph、rqt_plot 等不是六个软件，是同一个容器里的六个窗口——可以按需拼装、保存成布局（Perspective）一键还原。

02核心原理：插件化架构为什么好用

容器层
Qt 主窗口 + 插件发现

rqt 启动时扫描 /opt/ros/humble/share/rqt_* 下声明的插件入口，动态加载进菜单。写一个自己的 rqt 插件，就能把私有调试界面挂进官方工具箱。

数据层
共享同一个 ROS 上下文

所有插件共用 rqt 进程内的 ROS 节点——你在 rqt_graph 里看到的图，和 rqt_plot 订阅的是同一套话题系统，无需逐个工具重新连接。

组合层
Perspectives 布局保存

窗格停靠、插件组合、参数设置可整体存成 Perspective。排查导航问题存一个、调试串口存一个，切换工作场景一键还原，团队共享布局文件保持排查口径一致。

分层哲学
GUI 预览，CLI 定案

rqt 定位是"快速看"：graph 3 秒找断点、plot 秒级看趋势。脚本化/CI 场景仍回 CLI（ros2 topic echo / ros2 param）。GUI 提效率，CLI 保可复现，别二选一，要各司其职。

任务命令行做法rqt 做法效率差距
找断流话题逐个 topic echo + 人肉比对rqt_graph 看箭头有无，右上刷新秒级 vs 分钟级
看正弦波形echo 刷屏心算rqt_plot 输入 /topic/field 直接画线直观 vs 不可行
改运行参数ros2 param set 每次敲键盘rqt_reconfigure 拖滑块实时生效连续调 vs 单点改
过滤 WARN 日志grep 关键字，丢失上下文rqt_console 按级别/节点/内容多维过滤多维 vs 单维
要点 rqt_plot 的纵轴是自适应的：波形小幅抖动会被放大成"剧烈震荡"，判断幅值优劣时务必看左侧刻度，不要只看形状——这是新手把正常噪声误判为故障的高发坑。

03动画：同一系统，四双眼睛

动画：中央是运行中的 ROS2 系统，rqt_graph（拓扑）、rqt_plot（波形）、rqt_console（日志）、rqt_reconfigure（参数）四个插件像四台投影仪，把同一套节点/话题/参数数据各自投射成不同视图，共享同一 ROS 上下文。

04原理专题：六大核心插件逐个拆

① 拓扑
rqt_graph

Plugins → Introspection → Node Graph。椭圆=节点、矩形=话题、箭头=数据流。Hide Debug 勾上，/parameter_events、/rosout 消失，主链路一目了然。右上 Refresh 手动刷新——节点动态变化时不会自动重绘。

② 波形
rqt_plot

Visualization → Plot。路径必须写全 /topic/field，如 /sine_wave/data（String 消息不可绘）。"加号"按钮从话题树选字段最稳；还支持数学表达式 /a/data + /b/data 合成曲线。

③ 日志
rqt_console

Logging → Console，汇总订阅 /rosout。DEBUG/INFO/WARN/ERROR/FATAL 五级分色，Filter 支持级别+节点+内容多条件（默认 AND）。配合 rqt_logger_level 可运行中动态提级，不用重启节点。

④ 调参
rqt_reconfigure

Configuration → Dynamic Reconfigure. 滑块/下拉/复选直接下发参数。前提：节点用 API 声明参数并注册了 set 回调（见 EXP-10）。把"改参→编译→重启"从分钟级压到拖一下滑块的秒级。

⑤ 数据
rqt_topic

echo 的 GUI 版：话题列表带频率/类型，点开分层展示消息字段，位姿/多传感器嵌套结构不用在刷屏流里对齐看。适合"看一眼就走"的快速检查。

⑥ 回放
rqt_bag

Logging → Bag。时间轴拖动、勾选话题、字段绘图、导出 CSV——录包数据分析的 GUI 入口，与 CLI 的 ros2 bag info/play 互补（详见 EXP-16）。

奈奎斯特提醒 rqt_plot 画采样信号时，采样频率至少是信号频率的 2 倍才能还原波形（奈奎斯特采样定理）。1Hz 正弦波用 0.5Hz 采样画出来会变成一条"低频假波"——GUI 不会替你报警，请自己心里有这根弦。这也正是 EXP-11 讲 ros2 topic hz 的意义：先确认采样率，再信波形。

06命令精讲：启动方式三连

  
# 方式一：启动完整工作台（自带菜单可再开任意插件）
$ rqt

# 方式二：直启单个插件（省去菜单导航，脚本常用）
$ rqt_graph
$ rqt_plot
$ rqt_console
$ rqt_reconfigure

# 方式三：带参数启动（指定绘图话题，省手打）
$ rqt_plot --args /sine_wave/data
$ rqt_logger_level set logger:=my_node level:=debug   # 动态提级

# 远程无显示器的机器人（ssh 图形转发）
$ ssh -X pi@192.168.1.100
$ rqt        # 图形界面经 X11 转发到本地；失败见下表"无显示"

  

    原理：为什么 ssh -X 能弹窗
    Qt 程序通过 X11 协议"画"窗口——X 架构天然把"计算"（机器人上的 rqt）与"显示"（你笔记本的屏幕）分离，ssh -X 把远端的 X11 流量加密隧道转发回本地 X Server 显示。Wayland/纯 headless 环境此路不通，改用 VNC 或在有显示器的机器上跑。
  







  
07实操 A：graph + plot 三分钟联调

  

    
1
起系统
跑一个带正弦话题的示例包：ros2 run sine_wave sine_wave_node

    
2
看拓扑
rqt_graph → 勾 Hide Debug → 确认正弦节点→话题→订阅者的箭头连通

    
3
画波形
rqt_plot 输入 /sine_wave/data → 应看到平滑正弦滚动

    
4
制造故障
kill 掉发布节点 → graph 箭头消失，plot 曲线冻结——两种视图交叉印证

  

  
$ ros2 run sine_wave sine_wave_node        # 终端1：发布节点
$ rqt_graph                                # 终端2：先看图
#   确认 /sine_wave (std_msgs/Float32) 的发布-订阅关系存在
$ rqt_plot --args /sine_wave/data          # 再画线
#   字段路径只写 /sine_wave 会报"不能绘图"——消息不是标量
$ kill %1                                  # 杀发布者，观察两视图反应

  
观察点plot 冻结不代表"崩溃"，是没有新消息到来——横轴还停在最后时刻。判断节点死活回到 graph/CLI（ros2 node list），多视图交叉验证是 rqt 的正确打开方式。







  
08实操 B：console 多维过滤 + reconfigure 秒级调参

  

    
1
日志洪水
rqt_console 打开，跑一个带 WARN/ERROR 的节点，默认全量涌入

    
2
设过滤器
Minimum Sev erity=WARNING + 关键字 Contains=timeout → 只剩高价值条目

    
3
动态提级
rqt_logger_level 把目标节点提到 DEBUG，抓到隐藏上下文后调回

    
4
滑块调参
rqt_reconfigure 拖 sample_rate_hz 滑块，调速节点波形即时响应

  

  
# 日志端：节点需注册了参数回调才能被 reconfigure 支持（见 EXP-10）
$ rqt_console          # Filter: Node=my_node AND Severity≥WARN
$ rqt_reconfigure       # 左树选节点 → 出现声明过的参数控件
# 关键前提：参数写在声明处而非硬编码，回调里真正改了行为
$ rqt                  # 调完满意 → Perspectives → Save As 存布局

  

    
坑症状解法

    
无显示环境Could not connect to display用 ssh -X 重连；Wayland 机器改 VNC

    
graph 图是空的一个节点椭圆都没有右上 Refresh；确认 rqt 与系统同源（都 source 了 humble）

    
plot 曲线出不来提示不能绘制路径写到字段级 /topic/field；String 类型换话题

    
reconfigure 无控件左侧列表是空的节点没声明参数或没注册 set 参数回调——补 EXP-10 的骨架

    
布局每次重配窗口仍回老样子Perspectives → Save As 存盘，启动时选择预设

多维过滤的一个技巧
  只筛 WARN 往往还会被海量 INFO 之外的同级 WARN 淹没——叠加第二个条件（节点名或关键字）做 AND；反过来若怀疑"问题起因在 INFO 里"，就先把最小级别放到 INFO、按关键字 Contains 缩小，再顺时间线往上游找。







  
10本课总结

  

    
架构
容器 + 可插拔插件
rqt 本体只是 Qt 工作台，六个核心插件共享同一 ROS 上下文，Perspectives 保存布局。

    
分工
六插件各管一维
graph 看结构、plot 看波形、console 看日志、reconfigure 调参数、topic 看数据、bag 看回放。

    
心法
交叉验证
曲线冻结别只信 plot，拓扑断流回 graph——GUI 给速度，CLI 给确定性，两边互相印证。

    
前提
工具强依赖代码规范
reconfigure 有控件的前提是"正确声明参数+回调"——工具是果，EXP-10 的参数规范才是因。

  

  

    思考题
    
① 想在 console 只看"planner 只能输出 WARN 以上日志"，Filter 该怎么组合？若 WARN 被 INFO 淹没，除了级别过滤还有哪些策略？

    
② 要在 rqt_plot 里画小车的 XY 轨迹（不是"x随时间"曲线），数据源是 /odom 的 position.x 和 position.y——路径该怎么填？（提示：plot 支持表达式，想想两条曲线怎么合成坐标平面上的点。）
