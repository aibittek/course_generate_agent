ROS2 简介：机器人软件的操作系统

ROS 是什么？为什么机器人需要"中间件"？本实验从机器人软件的协作之痛出发，讲清 ROS2 的三大设计支柱，用动画拆解 ROS1 中心化 Master 与 ROS2 去中心化 DDS 的架构跃迁，再通过 talker / listener 第一次跑通你自己的 ROS2 通信系统。

难度 ⭐ · 2 学时 ROS2 HumbleDDS 中间件 turtlesimtalker · listener

01问题引入：机器人软件为什么需要中间件

一台服务机器人身上有激光雷达、摄像头、底盘、机械臂、语音模块——由不同厂商、不同语言、不同进程开发。如果没有统一的通信层，你会遇到：

1每个模块一种私有协议，两两对接要写 N×(N−1)/2 转接代码
2进程发现、断线重连、丢包重传全部手写，一改全崩
3ROS 用中间件统一只说一种语言：节点 / 话题 / 服务 / 动作
4上层算法变成可插拔积木：换雷达 = 换一个发布同一话题的节点
💡 一句话定义ROS（Robot Operating System）不是操作系统：不管理硬件，它是一个通信框架 + 工具集 + 包生态，运行在 Linux 之上，为机器人软件提供"进程之间如何说话"的标准答案。

02核心原理：ROS2 的三大设计支柱

支柱一
去中心化的分布式图

没有 Master 单点。每个节点自带 DDS 参与者身份，通过多播自动发现彼此，组成一张"节点-话题"关系图。

支柱二
语言与框架无关

Python（rclpy）、C++（rclcpp）乃至 Swift/Java 都能发声——接口由 IDL 消息定义统一约束，与实现语言解耦。

支柱三
工具生态开箱即用

ros2 CLI、rqt、rviz2、rosbag2、launch——同一套图信息喂给全部工具，"看不见的系统"随时可自省。

对比维度ROS1（Melodic 及以前）ROS2（Foxy / Humble / …）
通信架构中心化：Master(rosmaster) 统一注册去中心化：DDS 点对点，无中心进程
底层协议TCPROS（自研 TCP 长连接）RTPS（DDS 标准，UDP + 多播发现）
节点发现启动必须先起 Master，向它注册多播自动发现，谁先谁后无所谓
编译系统catkin_make 单一 CMake 大工程colcon 每包独立构建，支持混合语言
生命周期节点崩了只能重启整个进程Managed Node 四状态，可"待机-激活"恢复
服务质量无 QoS，可靠性不可配QoS 三要素（可靠性/持久性/历史）可按话题配置
🔍 关键跃迁ROS1 的 Master 是"电话总机"——总机不在，全网瘫痪；ROS2 的 DDS 是"群聊"——任何两个人先加上好友（发现），之后直接私聊（P2P 传输）。这决定了 ROS2 天生适合多机、车载与机器人集群场景。

03原理动画：Master 宕机 vs DDS 组网

左图：ROS1 所有节点都要经 Master 注册，Master 一倒，新节点找不到彼此；右图：ROS2 节点间直接多播出一张网，任意单节点下线不影响其余节点通信。

动画 1-1｜左：Master 一倒全网失联；右：消息在网状直连中持续流动（6 秒循环）

04专题：RMW 抽象层与 Humble 发行版

ROS2 在应用与 DDS 实现之间插入了 RMW（ROS MiddleWare）抽象层，同一份代码可以运行在不同 DDS 实现上：

1rcl 语言客户端层：rclpy（Python）/ rclcpp（C++），API 完全一致
2rmw 抽象接口层：统一的发布/订阅/服务接口定义
3dds 具体实现：rmw_fastrtps（默认）/ rmw_cyclonedds / rmw_connextdds
发行版字母表
Humble Hawksbill（本课程）

2022.05 发布的 LTS 版本，支持至 2027.05；此前 Foxy（2020）、Galactic（2021），此后 Iron、Jazzy。配套 Ubuntu 22.04。

切换 DDS 实现
一个环境变量完成

RMW_IMPLEMENTATION=rmw_cyclonedds_cpp——排障时用来隔离"是不是 DDS 实现的锅"，无需改一行代码。

生命周期管理
Managed Node 四状态

Unconfigured → Inactive → Active → Finalized：节点可"待机而不退出"，故障后原地恢复（EXP-10 深入）。

06命令精讲：环境验证三板斧

# ① 确认发行版（预期输出 humble）
echo $ROS_DISTRO
humble

# ② 加载 ROS2 环境（每个新开终端都要执行！）
source /opt/ros/humble/setup.bash

# ③ 看 ros2 命令认识自己的能力清单
ros2 --help
# ... verbs: action bag interface launch node param pkg run service topic ...
#            ↑ 八大动词组，EXP-02 逐一拆解
⚠️ 为什么 source 是"三板斧"之一ROS2 的一切命令都靠 setup.bash 注入的环境变量找到：不 source，ros2 直接 command not found；换了工作空间不 source install/setup.bash，你编译的包就"不存在"。这是新手第一大坑，贯穿全课程。

07实操 1 · ROS2 的 Hello World：talker

1开终端 A：source 环境后运行 ros2 run demo_nodes_cpp talker
2观察输出：[INFO] ... Publishing: 'Hello World: N' 每秒刷新
3后台发生的事：DDS 发现 → 节点创建 → 在 /chatter 注册 Publisher → 定时器驱动发消息
# 终端 A
source /opt/ros/humble/setup.bash
ros2 run demo_nodes_cpp talker
# [INFO] [1712...]: Publishing: 'Hello World: 1'
# [INFO] [1712...]: Publishing: 'Hello World: 2'
🔍 run 命令解剖ros2 run <包名> <可执行文件>——它只做一件事：去 ament 索引里按包名找到 install 目录，启动其中的可执行文件。找不到包？99% 是没 source 或没编译。

08实操 2 · 零配置互联：listener 与系统监控

1另开终端 B：ros2 run demo_nodes_cpp listener——无需任何"连接配置"
2DDS 多播自动发现 /chatter 的发布端，开始打印 [INFO]: I heard: [Hello World: N]
3终端 C 四连自省：node list → topic list → topic info → topic echo / hz
# 终端 C：以第三方身份俯瞰整个系统
ros2 node list
# /listener  /talker
ros2 topic list
# /chatter  /parameter_events  /rosout
ros2 topic info /chatter
# Type: std_msgs/msg/String   Publisher count: 1   Subscription count: 1
ros2 topic echo /chatter        # 第三方"匿名"订阅，实时看到 data
ros2 topic hz /chatter          # average rate: 1.000
💡 弹性验证（试一下）① 先启动 listener 再启动 talker——照样通（发现无顺序）；② Ctrl+C 杀掉 talker 重启——listener 自动恢复接收。把 Master 概念从脑子里删掉，这就是 DDS。

09注意事项与验收清单

  • 每个新终端都执行过 source /opt/ros/humble/setup.bash，echo $ROS_DISTRO 输出 humble
  • talker 输出 Publishing: 'Hello World: N'，序列号持续递增
  • listener 输出 I heard: [Hello World: N]，与 talker 同步
  • ros2 node list 同时看到 /talker /listener；ros2 topic hz /chatter ≈ 1.000 Hz
  • 能口头解释：ROS1 Master 和 ROS2 DDS 在"节点发现"上的本质区别
⚠️ 常见坑现象 → 解法
未 source 环境ros2: command not found → source /opt/ros/humble/setup.bash
包未安装Package 'demo_nodes_cpp' not found → sudo apt install ros-humble-demo-nodes-cpp
多播被阻断虚拟机/容器内两终端互看不见 → 桥接网络放开多播，或临时用 ROS_DOMAIN_ID=0 统一域
域 ID 不一致一边 ROS_DOMAIN_ID=42 一边默认 0 → 互相"隐身"，对齐环境变量
GUI 无显示turtlesim 黑屏 → 确认 X11 转发 / echo $DISPLAY 非空
