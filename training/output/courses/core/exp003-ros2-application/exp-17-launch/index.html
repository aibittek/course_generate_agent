EXP-17 · 第四章 · 设计性 · 2 学时

ROS2 Launch 启动文件：一键编排多节点系统

系统有 5 个节点，开机要开 5 个终端、按顺序 source、一个个敲 run——漏一个就是"话题没数据"的灵异现场。Launch 文件把整个系统声明成一份"启动剧本"：一条命令起全部，一次 Ctrl+C 停全部。本课讲清 ROS2 为什么把启动语言换成 Python，掌握 remap、条件启动与事件触发三大编排能力。

难度 ⭐⭐2 学时设计性关键词 LaunchDescription · remap · IfCondition · OnProcessExit

01问题引入：五个终端的手忙脚乱

1
现状

雷达驱动、定位、规划、控制、可视化 = 5 个终端，每个都要 source、按序启动

2
事故

新同学少 source 了一步，规划器收不到 /scan，排查一下午发现是"没起步"

3
更糟

关机时逐个 Ctrl+C，漏关的僵尸节点还在发 cmd_vel——车突然自己动了

4
正解

把 5 个节点写进一份 Launch 文件：ros2 launch 一条命令全起，Ctrl+C 一次全停

定义 Launch 文件（.launch.py / .launch.xml / .launch.yaml）声明：启动哪些节点、各自带什么参数、话题怎么重映射、按什么顺序和条件编排。ros2 launch 解析这份声明并执行——它是从"手工业"到"一键部署"的关键一跃，也是后续 EXP-18 元功能包、EXP-19/20 模型加载的统一入口。

02核心原理：ROS2 为什么把启动语言换成 Python

架构演进
从 XML-only 到 Python-first

ROS1 的 roslaunch 只支持 XML，"A 退出后等 3 秒再启 B"这类逻辑要么写不出来、要么嵌套到没人看得懂。ROS2 把启动编排升级为图灵完备的 Python API——if/for/函数/模块随便用，复杂编排变成普通编程。

核心产物
LaunchDescription = Action 列表

入口函数 generate_launch_description() 返回一个 LaunchDescription，里面装一组 Action（Node、LogInfo、DeclareLaunchArgument……）。ros2 launch 读它、按序执行——这就是"剧本"的实体。

事件驱动
不止是顺序执行

Action 之间还有条件依赖与事件触发（OnProcessExit/OnProcessStart/TimerAction）：节点退出可引发连锁动作、可以定时注入步骤——这是 XML 静态声明给不了的动态编排能力。

运行时变量
LaunchConfiguration

"声明参数 + 引用取值 + 命令行 key:=value 传入"三件套，让一份文件适配多场景：调试模式多起一个 rqt、仿真模式把 use_sim_time置 true——全靠传参，不复制文件。

格式表达力适用建议
Python（.launch.py）图灵完备：条件/循环/事件/动态计算复杂编排、生产系统推荐首选
XML（.launch.xml）静态声明，与 ROS1 语法接近固定节点组、迁移旧配方简单场景可用
YAML（.launch.yaml）特性支持最少极简清单一般不推荐用于生产
要点 Launch 是编排层不是运行时：它负责起进程、注参数、建重映射，起完之后自己还活着做"监管员"（收信号、管退出）。所以节点崩了日志里会看到 [talker-1] process has died——这行监管日志就是 Launch 身份的最好证明。

03动画：解析、拉起、优雅退出的全过程

动画：ros2 launch 解析 .launch.py 得到 Action 列表，Runner 按序拉起 talker/listener 子进程并做日志前缀标记，条件节点仅在表达式成立时启动；按下 Ctrl+C 后 Runner 向所有子进程广播 SIGINT 干净收场——"一次性起全、一次性停全"与"退出可触发连锁"是同一事件机制的两面。

04原理专题：remap、条件、事件三件套

解耦利器
remap：逻辑名 → 物理名

节点代码写的是"逻辑话题"（激光车都发 /scan），Launch 在启动时把它改道到 /scan_front。不改源码完成适配——多实例、第三方节点硬编码、命名规范统一，全靠它。

两个方向
内→外 最常用，外→内 也行

remappings=[(A, B)] 永远是"把 A 映射到 B"，A 是节点代码里的名字。外→内则让外部数据流进节点的内部名——搞反顺序是 remap 失灵的第一大原因。

作用域放大
namespace 前缀

namespace='robot1' 让节点变 /robot1/talker、话题变 /robot1/chatter——同机跑两台机器人模型互不干扰；与 remap 组合可表达任意拓扑。

条件守卫
IfCondition / UnlessCondition

附着在任何 Action 上的开关：If(expr) 真才执行，Unless(expr) 假才执行。配合 LaunchConfiguration——真机起传感器驱动、仿真不起，一个文件两套行为。

事件触发
OnProcessExit：A 走，B 来

A 节点退出时自动启动 B——数据采集结束→自动起分析脚本；标定节点退出→自动录包收尾。Launch 的"事件驱动"就体现在这类回调绑定上。

参数注入
Declare + Configuration + key:=value

声明带默认值 → 引用 → 命令行覆盖。ros2 launch pkg file.py mode:=debug enable_debug:=true，零复制切换场景。

需求用什么一句话
同一节点跑两个实例remap + namespace/scan_front 与 /scan_rear，源码零改动
真机/仿真两套行为IfCondition + LaunchConfigurationuse_sim_time:=true 切换
采完数据自动分析OnProcessExitrecord 退出 → 自动跑 report.py
延时等设备就绪TimerAction（延伸）雷达开电 3 秒后再启驱动
Why Python：一道题看清 需求——"debug 模式起 3 个节点并把日志设 DEBUG；normal 模式只起 2 个；production 模式还要换发现服务器地址"。XML 需要复制多个文件 + 属性魔法；Python 里就是两个 if 加一个字典。这就是启动语言演进背后的设计逻辑：编排复杂度随系统规模增长，语言表达力必须跟上。

06代码精讲：第一个 Launch 文件

  
# basic_launch.py —— 最小可用模板（入口函数名一个字符都不能错）
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():        # ← 必须叫这个名字
    return LaunchDescription([
        Node(
            package='demo_nodes_cpp',
            executable='talker',
            name='my_talker',
            output='screen',            # 日志汇入 launch 终端，带 [my_talker-1] 前缀
            remappings=[('/chatter', '/my_chatter')],
            parameters=[{'use_sim_time': True}],
        ),
        Node(package='demo_nodes_cpp', executable='listener',
             name='my_listener', output='screen'),
    ])

# 运行（包内 launch/ 目录需 install 到 share，见 07 节 CMakeLists）
$ ros2 launch launch_demo_pkg basic_launch.py
# Ctrl+C 一次 → 全部子进程收 SIGINT 优雅退出

  
# 参数化 + 条件启动骨架（步骤 3/4 的核心结构）
from launch.actions import DeclareLaunchArgument, LogInfo
from launch.substitutions import LaunchConfiguration, PythonExpression
from launch.conditions import IfCondition

def generate_launch_description():
    dbg = LaunchConfiguration('enable_debug_node')
    return LaunchDescription([
        DeclareLaunchArgument('enable_debug_node', default_value='false'),
        LogInfo(msg=['debug=', dbg]),
        Node(..., name='listener_core'),                        # 恒启动
        Node(..., name='listener_debug',                        # 条件启动
             condition=IfCondition(PythonExpression(['"', dbg, '" == "true"']))),
    ])

  

    原理：PythonExpression 为什么要包引号
    LaunchConfiguration 取出来是字符串 "true"，PythonExpression 拼成的表达式要能被 eval——"true" == "true" 比较两个字符串为真；写成 true == true 会把 true 当变量名，未定义直接抛异常。字符串比较必须自带引号，或者干脆改用更稳的 EqualsSubstitution。

find_package(ament_cmake REQUIRED)
install(DIRECTORY launch DESTINATION share/${PROJECT_NAME})
ament_package()

# remap_launch.py 关键：talker 改道，listener 一个配平一个不配平
Node(package='demo_nodes_cpp', executable='talker', name='talker_remapped',
     remappings=[('/chatter', '/my_chatter')], output='screen'),
Node(..., name='listener_default', output='screen'),          # 订 /chatter → 沉默
Node(..., name='listener_remapped',
     remappings=[('/chatter', '/my_chatter')], output='screen'), # 收到消息 ✓

# 验证"remap 对节点是透明的"
$ ros2 topic list                        # 有 /my_chatter；/chatter 无发布者
$ ros2 node info /talker_remapped        # Publishers 显示 /my_chatter —— 外部视角
#   节点代码里以为自己在发 /chatter，外界看到的却是 /my_chatter

  
观察点listener_default 不是"卡死"，是订阅了一个没有发布者的话题——同进程内两个 listener 一个有输出一个没有，这个对照就是 remap 生效的最直观证据。remap 只影响列出的名字，/parameter_events 等公共话题不受它管辖。

$ ros2 launch launch_demo_pkg param_launch.py
#   → talker_param + listener_core（normal，2 节点）
$ ros2 launch launch_demo_pkg param_launch.py \
     enable_debug_node:=true log_level:=debug
#   → 多出 listener_debug，且日志级别经 arguments 注入为 DEBUG（3 节点）

# 事件触发骨架：A 退出 → B 自动接管
from launch.actions import RegisterEventHandler
from launch.event_handlers import OnProcessExit
Node(..., name='recorder', executable='ros2_bag_record_stub'),
RegisterEventHandler(OnProcessExit(
    target_action=recorder,
    on_exit=[Node(package='my_pkg', executable='analyze', output='screen')],
)),
# 录包进程一结束，分析脚本自动开工——"采集→分析"流水线零手工

  

    
坑症状解法

    
入口函数名写错module has no attribute 'generate_launch_description'全小写 + 下划线逐字核对，一个字符都不能差

    
No launch file found包明明存在却找不到文件三查：build 过没有 → source 了没有 → CMakeLists 有没有 install(DIRECTORY launch ...)

    
remap 方向反了配了却收不到(A,B)="代码里的名, 实际要的名"；topic list 核对实际名

    
表达式类型不匹配PythonExpression 返回 False 或报错字符串比较自带引号 "true"=="true"，或用 EqualsSubstitution

    
节点名冲突条件为 False 也报 name 重复每个 Node 的 name 唯一——声明即占号，条件只决定起不起进程

10本课总结

  

    
架构
Python-first 事件驱动
LaunchDescription 装 Action 列表，条件与事件让编排从静态声明升级为动态剧本。

    
三件套
remap / 条件 / 事件
remap 不改码适配多实例；If/Unless 一文件多场景；OnProcessExit 串起流程自动化。

    
参数化
Declare + Config + := 
命令行 key:=value 运行时覆盖默认值，一份文件服务调试/生产/仿真。

    
工程闭环
launch 是部署资产
install 规则 + 一键启动 + 全量退出——与 params、.rviz、bag 一样进 git。
