时间 API 与双时钟体系

IMU 200Hz、相机 30Hz，时间戳差一点数据就对不上。本课讲清 ROS2 为什么自建时间抽象层、系统时钟与 /clock 仿真时钟如何透明切换，以及 create_timer 与 Header.stamp 的正确姿势。

难度 ⭐⭐2 学时验证性关键词 Clock · Timer · stamp

01问题引入：时间不对齐，数据全白采

1
IMU 每秒 200 条、相机每秒 30 帧——融合前必须按时间戳配对，配错了姿态就算飞。
2
直接用 Python 的 time.time()？仿真里"1 秒"可能只要真实 0.1 秒，录包回放时两条消息的时间戳也根本对不上。
3
多机部署时，两台电脑系统时钟不同步，延迟甚至算出负值。
4
ROS2 的答案：自建时间抽象层——Clock 类统一出口，底层自动在系统时钟与 /clock 仿真时钟间切换，上层代码一行不改。
时间 = 一等公民机器人系统里时间有两类来源（真实墙上时 / 仿真逻辑时），Clock 把差异吸收在底层：get_clock().now() 永远返回"当前正确的时间"。

02核心原理：双时钟架构与 Time 类型

系统时钟
Wall Clock · 默认

use_sim_time=false（默认）：Clock 读操作系统时间，与真实世界同步——跑在真机 B2 实验箱时的唯一正确选择。

仿真时钟
/clock 话题驱动

use_sim_time=true：Clock 订阅 rosgraph_msgs/msg/Clock；Gazebo 推进一步发一次——仿真的"1 秒"可对应真实的 0.1s 或 10s。

消息类型
builtin_interfaces/Time

sec（int32，Unix 纪元秒）+ nanosec（uint32，0~999999999）——嵌在 Header.stamp 里跨机传输的序列化形式。

API 类型
rclpy.time.Time

Python 侧可运算可比较：to_msg() 转消息、Time.from_msg() 转回、±Duration 加减。

来源哪里拿到适合场景
time.time()Python 标准库与 ROS 无关的纯本地计时（日志文件名等）——机器人数据流里不要用
get_clock().now()节点 Clock（自动选源）一切需要盖时间戳、算延迟、配合仿真回放的场合
msg.header.stamp消息体内的采集时刻跨节点对齐、rosbag 回放、端到端延迟测量
切换对上层透明use_sim_time 由参数驱动，Clock 内部换数据源——你的代码始终只写 get_clock().now()，仿真/真机零改动切换，这就是抽象层的意义。

03动画：use_sim_time 如何切换时钟源

绿色路径 = 系统时钟（默认），蓝色路径 = 订阅 /clock 的仿真时钟；红色虚线提示最大的坑：true 开着却没有仿真器，节点会一直等。

04专题：create_timer 的真实行为与 stamp 规范

定时器原理
挂在 spin 事件循环上的周期源

create_timer(period, cb) 注册触发源；spin 每轮检查到点就把回调加入执行队列——没有 spin 就永远不触发，取代 ROS1 的 while+Rate.sleep()。

名义周期
回调耗时可以拖垮频率

周期是"最小名义间隔"：回调执行 0.3s 而周期 0.2s → 实际频率被压到约 2.2Hz 而不是 5Hz。I/O 密集任务要异步化。

多定时器
同节点内串行执行

demo 节点同时挂 1s 采样定时器 + 5s 摘要定时器，各自独立计时，但回调在同一事件循环里排队——一个堵全堵。

stamp 规范
盖"采集时刻"不是"发布时刻"

在读传感器的那行代码处取 now()；等处理完再盖戳，等于把处理延迟算进了传输延迟——排查延迟问题时会误导自己。

端到端延迟delay = 订阅端收到时刻 − stamp 记录的采集时刻，减去 stamp 才是"通信+排队"的真延迟。局域网有线通常 < 1ms；多机出现负值说明两台电脑系统时钟没对齐——先 NTP 再查代码。

06时间 API 命令精讲

# 取当前 ROS 时间并与消息格式互转
now = node.get_clock().now()
print(now.nanoseconds)                # 总纳秒数（Unix 纪元起）
msg_time = now.to_msg()               # sec + nanosec，可直接赋给 Header.stamp

# 时间运算：间隔、比较、差值
from rclpy.time import Duration
future = now + Duration(seconds=5.0)   # 5 秒后的时间点
diff = now - past                      # Duration：.nanoseconds / 1e9 得秒
print(now > past)                      # True —— Time 支持直接比较

# 两个定时器并存（demo 节点的标准形态）
self._t1 = self.create_timer(1.0, self.sample_cb)   # 1Hz 采样
self._t2 = self.create_timer(5.0, self.summary_cb)  # 5s 摘要，互不干扰
两个 Time 别搞混rclpy.time.Time（API 对象，可加减）与 builtin_interfaces/msg/Time（传输结构，字段 sec/nanosec）——过界必须 to_msg() / Time.from_msg() 转一道，直接赋值字段会类型报错。

07实操 A：带时间戳的采样发布节点

# 落盘讲义 time_demo_node.py：1Hz 采样 + Header.stamp + 5s 摘要
python3 time_demo_node.py             # 终端A
# [INFO] 时间演示节点已启动 · use_sim_time=False

# 终端B：看消息里的 stamp 字段
ros2 topic echo /sensor_data
# header:
#   stamp: {sec: 1731500000, nanosec: 512345678}   ← 接近当前 Unix 时间

# 验证采样节拍
ros2 topic hz /sensor_data

08实操 B：延迟测量与 /clock 体验

# 端到端延迟（stamp → 收到的时刻差，单位 ms）
ros2 topic delay /sensor_data
# 0.3 ms   ← 局域网正常水平；出现负值 = 时钟不同步

# 体验仿真时钟：先以 sim 模式启动（会卡住等 /clock）
python3 time_demo_node.py --ros-args -p use_sim_time:=true

# 另开终端手动扮演"仿真器"，每秒推进 1 秒
ros2 topic pub /clock rosgraph_msgs/msg/Clock "{clock: {sec: 100, nanosec: 0}}" --rate 1
# 节点瞬间"活"过来，stamp 从 sec=100 开始递增 —— 时间轴被接管

# 0.5 倍速版本：--rate 0.5，观察 stamp 推进变慢、1Hz 定时器越发越慢
回放一致性rosbag play 加 --clock 也会发布 /clock——配合全系统 use_sim_time:=true，离线复现时所有节点共享录制时的时间轴，时间戳天然对齐。

09注意事项与验收清单

  • 默画双时钟架构：use_sim_time 是源开关，get_clock().now() 是统一出口
  • 讲清 Time（API）与 builtin_interfaces/Time（消息）的互转关系
  • 实测 topic hz ≈ 1.000、topic delay 正常量级，理解负值的含义
  • 亲手体验一次：true 开着没 /clock 的阻塞，以及手动 pub 的"复活"
  • 说出 stamp 应该盖在采集时刻的哪一行代码
  • 解释回调超时为什么会拖低实际频率（名义周期 ≠ 实际频率）
坑症状解法
忘调 spin定时器永远不触发节点创建后必须 rclpy.spin(node) 启动事件循环
init 顺序错get_clock().now() 报 Clock not initialized先 rclpy.init() 再建节点，之后才能取钟
真机误开 use_sim_time节点卡死没有任何输出无 /clock 发布者即永久等待——真机保持 false
delay 出现负值跨机测量越测越离谱两机 NTP 对时；单机则查 stamp 是不是盖晚了
回调里做重 I/O频率标称 5Hz 实测 2Hz 不稳重活移出回调（异步/多线程），回调保持轻量
运行中切换 use_sim_time改了没反应时钟模式须在初始化时确定——重启节点才能切

10本课总结与思考题

抽象
双时钟一个出口

Clock 吸收系统时钟与 /clock 的差异，上层代码仿真真机零改动。

类型
API Time ⇄ 消息 Time

to_msg()/from_msg() 互转；sec+nanosec 结构贯穿所有 Header。

节拍
create_timer 挂 spin

名义周期受回调耗时拖累；多定时器同循环串行。

规范
stamp 盖采集时刻

delay/hz 诊断通信质量；负延迟先怀疑时钟未对齐。
