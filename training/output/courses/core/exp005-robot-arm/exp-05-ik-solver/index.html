EXP-05 · 第 2 章 · 综合性 · 4 学时

逆运动学解算

把浏览器里的 IK 搬进 Python：直接调用 car1 的 ik_solve / fk_solve 库，跑 100 样本闭环批量验证，用 system_offset_analysis 量化你这台机器"天生歪"的 4° 与 2.3°，再按下减法补偿，把 +2.5mm 系统误差压到 +0.3mm。

⭐⭐⭐ · IK 库 API · --direct 直连

01问题引入

EXP-04 你在浏览器里验证了 FK/IK 的数学。但真机控制器是 Python 写的：arm_controller 要在几十毫秒内把 /arm/target_pose 反解成五路 PWM，靠的正是 arm/kinematics/ 下的 IK 库。问题来了——

  • 数学上完美的 IK，装到你这台机械臂上就准了吗？舵机安装有公差、连杆有加工误差，实际臂会"多弯一点点"。
  • 怎么科学地量出这个偏差？量出来以后，是改 DH 参数还是打补丁？
  • 调算法时每次都要开一整套 ROS2 吗？能不能绕过节点、脚本直连串口单测？

本实验给出工程答案：用 batch_fk_ik() 批量闭环量化精度，用 system_offset_analysis() 抓出系统偏移（J2 +4.0°、J3 +2.3°），用"减法补偿"修正，用 --direct 直连模式提速调试。

02原理通俗讲解

FK 是"验算"，IK 是"解题"。考试时：IK 拿到目标点这张"题目"，解出五个关节角这份"答案"；FK 则是把答案代回原题验算——答案代回去对不上（误差大），说明解错了或机器歪了。闭环测试就是"出题→解题→验算"的自动流水线。

系统偏移 = 你的椅子天生矮了两厘米。每个人坐某把椅子都觉得"够不到桌"，不是你手短，是椅子矮——换谁来都一样，这就是系统误差（可补偿）；而每次坐下高度还随机晃两毫米，那是随机误差（只能提工艺）。car1 的实测：未补偿时闭环误差均值 +2.5mm，补偿后 +0.3mm——扣掉的就是那两把"歪椅子"：J2 多 4.0°、J3 多 2.3°。

减法补偿：软件"少发一点"。IK 假设臂是标准几何，实际臂 J2 多长了 4°，那就让软件发指令时少 4°（q[1] -= 0.0698、q[2] -= 0.0401），实际关节反而到位了。好比知道秤缺一斤，装货时少放一斤。

补偿 vs 改 DH
微调贴纸 vs 重画图纸

改 DH 会动整个工作空间预测模型；offset 补偿不碰"基线图纸"（DH），随时可禁用对比，多人协作时 DH 是公共基线、offset 是个人微调。

--direct 模式
不走驾校，直接上手摸车

绕过 ROS2 节点，脚本直连串口发 PWM。底层算法调试少一层中间商，时序更可控——但安全责任也全在你。

03关联知识点

IK 库两大 API（源码 arm/kinematics/ik_analytical.py、fk.py）：

接口签名返回
ik_solveik_solve(target_xyz, target_pitch, prefer_elbow='up')长度 5 的弧度列表 [q1..q5]；失败返回 None
fk_solvefk_solve(joint_angles)4×4 位姿矩阵 T，位置取 T[:3,3]，RPY 用 transform.matrix_to_euler(T)

目标姿态用 pitch（俯仰角）描述：pitch=180° 即夹爪垂直向下——这是抓取的标配姿态。示例目标 (0.28, 0, 0.1) + pitch=180°。

批量闭环指标（batch_fk_ik(n=100)）：工作空间随机采样 100 点 → 逐点 IK → FK 反算 → 统计。car1 解析法典型性能：

指标阈值实测基线
平均误差 Avg< 0.5mm0.42 mm
最大误差 Max< 1.5mm1.23 mm
P95 误差—0.89 mm
成功率100%100%（误差阈值内）

偏移标定值（system_offset_analysis 实测）：J2 offset = +4.0°（0.0698 rad）、J3 offset = +2.3°（0.0401 rad）。另注：批量验证遇 "matrix not invertible" 是奇异点，讲义规定 5cm 球内跳过。

04实验目标

  • 掌握 IK 库 API：会 import ik_solve / fk_solve，处理返回 None（目标不可达）的情况。
  • 独立完成 100 样本闭环批量测试，得到 Avg/Max/P95/成功率四指标，并与基线对表。
  • 运行 system_offset_analysis 识别 J2+4.0°、J3+2.3° 系统偏移，理解"减法补偿"推导。
  • 在补偿开/关两种配置下对比误差（+2.5mm → +0.3mm），说出补偿相对改 DH 的三点优势。
  • 会在 --direct 直连串口模式与 ROS2 模式间切换，并遵守先 test_servo_direct.py 验机的安全顺序。

06动画讲解：逆解构型切换 + 系统偏移的"减法"

动画 8 秒一循环：前半段同一目标点在 elbow-up / elbow-down 两种构型间切换（IK 多解）；后半段演示输出端的减法补偿——q[1]−0.0698、q[2]−0.0401 叠加后再下发，DH 参数原封不动。

07互动讲解：误差判定与偏移补偿台

互动台 · 闭环误差判定 + 减法补偿实验
指标阈值：Avg<0.5mm · Max<1.5mm · 成功率 100%。补偿常量：J2−0.0698 rad(4°)、J3−0.0401 rad(2.3°)。基线：未补偿均值 +2.5mm → 补偿后 +0.3mm。

玩法：输入批量测试打印的 Avg 误差点"误差判定"——2.5mm 判为 未补偿系统误差，0.3mm 判为 已补偿达标。再输入你输出给舵机的 J2/J3 弧度点"应用补偿"，观察下发前被减掉的两个常量。这正是 ik_solve(..., use_offset=False/True) 两种调用的差异白盒。

09重点与易错点

核心口诀：IK 出口打补丁，DH 图纸不乱动。补偿只发生在"IK 输出 → 下发舵机"这一毫米的路上；工作空间预测、仿真器、URDF 全部使用原始 DH——所以仿真与实机既能分离，又能一键对比。
坑现象对策
ik_solve 返回 None打印 None，无角可发目标点超出工作空间——缩 r、抬 z 再试（对照 EXP-04 可达率）
一步到位奔袭目标首跑就撞限位/撞桌先抬高 z、缩小 r 逐步逼近 (0.28,0,0.1)
没验机就跑 IK异常角直接下发先 test_servo_direct.py interactive_mode 验设备与软限位
matrix not invertible批量测试中断奇异点，5cm 球内跳过该样本
补偿方向搞反误差不降反升（2.5→更大）记住是减法：q[1]−=0.0698、q[2]−=0.0401；拿 use_offset 两态对拍
--direct 参数缺失脚本找不到口--direct --port /dev/ttyUSB0 --baud 1000000 三项齐全
  • 交付四指标：Avg 0.42 / Max 1.23 / P95 0.89 mm / 成功率 100%，与基线同量级才算通过。
  • 偏移补偿前后各留一组数据：+2.5mm 与 +0.3mm，写进实验报告。
  • 想清楚再答面试：为什么不直接改 DH，而要维护 offset？（提示：三点优势——基线、可禁用、协作。）

思考题 1：补偿把均值从 2.5mm 压到 0.3mm，但 Max 仍有 1.23mm——这部分残余误差没有均值可补。它可能来自哪些环节？（提示：舵机回差、连杆柔性、PWM 量化……对照 EXP-02 的脉冲分辨率想一想。）
思考题 2：如果下周换了另一台 car1，它的 J2 偏移是 −2.5°——只允许你改一个配置文件，整条补偿链路（标定→配置→IK 输出→舵机）应该怎么改？为什么"个人微调"必须和"公共 DH 基线"分开放？
