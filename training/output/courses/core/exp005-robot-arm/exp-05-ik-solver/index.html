01问题引入

EXP-04 你在浏览器里验证了 FK/IK 的数学。但真机控制器是 Python 写的：arm_controller 要在几十毫秒内把 /arm/target_pose 反解成五路 PWM，靠的正是 arm/kinematics/ 下的 IK 库。问题来了——

  • 求解器返回了一组关节角、error 字段还是空的，这组角就一定准吗？（答案：不一定——这叫静默偏差）
  • 怎么科学地量出偏差？量出来以后，怎么区分是"模型算错了"还是"这台机器装歪了"？
  • 调算法时每次都要开一整套 ROS2 吗？能不能绕过节点、脚本直连串口单测？

本实验给出工程答案：先跑 test_fk_ik.py 内置闭环测试——如实面对当前 4 个用例 3 个 FAIL、误差 18~23mm 的真实现状；再用 demo_ik_closed_loop.py 200 样本三档 pitch 暴露规律；用"理论链 vs 实机链"分量法归因；读源码里真实的补偿 config.py 几何常量与 Y_TCP；最后用 --direct 直连实机验证。

先撕掉两个旧说法（讲义源码核对红线）：仓库里没有 system_offset_analysis()、没有 config/system_offset.yaml、没有 "J2 +4°/J3 +2.3°" 这组偏移值，也没有 batch_fk_ik()——旧指南把误差归因为"装配偏移 + 减法补偿（2.5mm→0.3mm）"的说法无法复现，别写进实验报告；一切以本页的实测与复算为准。

02原理通俗讲解

FK 是"验算"，IK 是"解题"。考试时：IK 拿到目标点这张"题目"，解出五个关节角这份"答案"；FK 则是把答案代回原题验算。闭环测试就是"出题 → 解题 → 验算"的自动流水线——只有验算过了，答案才算对。

静默偏差 = 改卷老师只查"写了没有"，不看"写得对不对"。IK 的 error 字段为空，只说明"目标可达、我给了你一组角"；这组角经 FK 回代可能差 18mm——它全程不报错，误差是静默的。所以本实验第一条纪律：每次求解必做 FK 反算，>1.5mm 即弃用该点。

系统误差还能确诊，靠"对照"不靠"拍脑袋"。旧版拿"J2 +4° 的装配偏移"当系统误差例子——源码查无此值。现行证据链干净得多：同一套数学，pitch=90° 时 P95≈0.001mm（模型自洽），pitch=180°/0° 误差却涨到几十上百毫米——误差跟"工具体朝哪"强相关，嫌疑就落在J4→TCP 工具体在 IK 与 FK 两侧的建模不一致（L_TCP/PHI_TCP/Y_TCP 定义差异），而不是机械装歪。修法自然是把两端模型对齐，而不是打偏移补丁。

真实补偿
几何常量 = 标定 = 补偿

装配偏差直接写进 config.py 的 J2_offset/link1/link2/tool，FK 与 IK 共用——改一处、两条链同时变；另有 Y_TCP=0.215mm 内建于 IK 的 q1 补偿。不存在独立 offset 文件。

pitch 纪律
0° 朝上 · 90° 水平 · 180° 朝下

本库 pitch 从竖直量起（与 arm_controller.py:166 注释一致）。别照 fk.py/ik_analytical.py 顶部 "0 = horizontal forward" 的旧 docstring——讲义注明那是错的。

--direct 模式
不走驾校，直接上手摸车

绕过 ROS2 节点，pyserial 直连 /dev/stm32 发 PWM（串口与波特率硬编码，只认 --direct/--debug）。底层算法调试少一层中间商——安全责任也全在你。

奇异位：误差暴涨时的头号嫌疑J 的行列式趋近 0 时（手臂近乎伸直/折死），IK 反解出的关节速度会趋于无穷——数值解在此发散、解析解分母趋零，正是"误差跟工具体朝向强相关"的帮凶之一。概念、汇率表比喻与可拖动的奇异位演示，见 EXP-04 · 进阶 · 雅可比与奇异性；阻尼 λ=0.1 就是给奇异位踩的刹车。

04实验目标

  • 理解 IK 库（config / transform / fk / ik_analytical）的模块化拆分与接口设计 —— 原理理解
  • 掌握 FK/IK 闭环验证方法与误差统计，能识别"求解成功 ≠ 解准确"的静默偏差 —— 流程掌握
  • 独立使用 interactive_ik_test.py 完成实机 IK 闭环测试（先 n 核 PWM、再 y 下发） —— 独立完成
  • 能把"理论链（IK→FK，纯计算）"与"实机链（IK→舵机→真实末端）"分开实测并给出误差归因 —— 独立完成
  • 在 --direct 直连模式与 ROS2 模式间切换调试，并能用 FK 反算核对任意 IK 解 —— 迁移应用

06动画讲解：多解切换 + 静默偏差三连击

动画 8 秒一循环：左半同一目标点在 elbow-up / elbow-down 两构型间切换（IK 多解，分支由 branch 字段标明）；右半三连击——求解器报"成功"→ FK 回代出 18.40mm → 三档 pitch 成功率 99%/72%/61.5%：错得很有规律，正是"工具体建模不一致"的指纹。

07互动讲解：误差判定与归因台

互动台 A · 闭环误差归因判定（先分类，再动手）
阈值：闭环容差 1.5mm（Avg 目标 <0.5mm）。当前真实基线：4 点 3 FAIL（18.40/22.95/21.73mm）；200 样本 90°→99.0% · 180°→72.0% · 0°→61.5%，IK 报错 0 次——全是静默偏差。
互动台 B · 几何常量灵敏度（config.py 是"标定即补偿"的旋钮）
示意曲线：两端模型一致（Δ=0）时闭环误差最小；扰动任一几何常量，FK 与 IK 同时被改写——灵敏度方向可信，量级以你重跑 test_fk_ik.py 的实测为准。

玩法：台 A 输入 test_fk_ik / demo_ik_closed_loop 打印的误差——18.4mm 判为工具体建模不一致量级（与 pitch 强相关），0.0mm 判 达标，几十上百毫米看你敢不敢用于抓取。台 B 拖动 ΔL 观察"一个常量、两条链路"的联动——这就是讲义说的"几何常量既是标定也是补偿，没有独立 offset 文件"。

09重点与易错点

核心口诀：error 为空 ≠ 解对，FK 回代是唯一照妖镜；几何图纸（config.py）FK/IK 两端共用，别再造偏移文件——改图就说改图，改完必重跑闭环对账。
坑现象对策
只看 error 字段求解"成功"却差 18mm每次必跑 FK 反算；interactive_ik_test 打印的 误差 >1.5mm 即弃用该点/该 pitch
以为闭环必全绿想调大容差"修"通过当前真实就是 3/4 FAIL、180° 仅 72%——如实写进报告，这是待解问题不是环境问题
套用旧版 J2+4°/J3+2.3°报告编造数据源码查无此值与补偿函数（讲义红线）；一切以实测/复算为准
pitch 朝向搞反工具朝上当朝下记纪律 0°上 · 90°平 · 180°下（arm_controller.py:166），勿信旧 docstring
误加 --port/--baud脚本不认参数只解析 --direct/--debug，串口波特率硬编码 /dev/stm32 @1Mbps
直连与 ROS2 抢口串口打开失败二选一，直连前 cleanup_ros.sh；ls -l /dev/stm32 查软链权限
一步到位奔袭目标首发撞限位/撞桌先 test_servo_direct 验机核软限位；默认点先 n 后 y；抬 z 缩 r 逐步逼近
在 Python 找数值法没有 numerical_ik.py数值法只在仿真器 ik-numerical.js（DLS，lambda=0.5/maxIter=200）
  • 交付五件套：test_fk_ik 四点结果表 + demo 200 样本三档 pitch 统计 + 归因表（理论链/实机链分列）+ Y_TCP 打印截图 + 解析vs数值对比表。
  • 归因表里每个超差点必须回答：pitch 多少？error 空吗？与工具体朝向相关吗？
  • 评分锚点（讲义 1.9）：API 使用 15 + 闭环与归因 30 + 几何标定理解 15 + 直连调试 15 + 解析vs数值 10 + 报告 15 = 100。
