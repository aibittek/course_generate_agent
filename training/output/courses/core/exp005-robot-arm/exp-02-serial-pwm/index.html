EXP-02 · 第 1 章 · 验证性 · 4 学时

串口底层协议与 PWM 控制

这一步不启动任何 ROS2 节点：用 Python pyserial 裸机打开 /dev/ttyUSB0，亲手组 0xAA55 帧头 + CRC8 校验的数据帧，把 500~2500μs 的 PWM 暗号直接送到舵机 —— 看清 ROS2 外壳底下真正的电信号世界。

难度 ⭐⭐ · 4 学时 · 验证性 1Mbps 8N1 CRC8 查表 PWM 500~2500μs interactive_mode

01问题引入：节点之下是什么在响

EXP-01 里你发一条 /arm_controller/joint_trajectory，Gazebo 的手臂就弯了 —— 可实机上"弯"这个动作是谁执行的？答案藏在一条 USB 转 TTL 串口线里：ROS2 节点把角度翻译成一连串字节，字节以 1Mbps 的速度冲向总线舵机，舵机数着脉冲宽度转到指定角度。

如果 ROS 层报错，你怎么知道是"规划错了"还是"线没插好"？唯一的办法是绕过 ROS：裸机直接打开 /dev/ttyUSB0，自己发帧、自己看应答。这就是本实验的"裸机路线"—— 协议层调试、单舵机快速验证、排除 ROS 架构干扰的三把利器。

⚠️ 第一条红线不要启动 bringup！ test_servo_direct.py 直接占用 /dev/ttyUSB0，与 bringup 的 base_driver 节点互斥 —— 运行前先 bash cleanup_ros.sh 停掉所有 ROS 节点。

02原理通俗讲解：舵机的"暗号脉宽"

生活比喻 · 时钟报时
PWM = 暗号脉宽

总线舵机只认一种暗号：一个宽度在 500~2500μs 之间的高电平脉冲。脉冲越宽转得越远 —— 1500μs 是"立正"（中位），996μs 与 2000μs 是左右极限。

生活比喻 · 挂号信
0xAA55 = 信封上的暗印

总线上电来电往，舵机怎么知道这封信是给自己的？帧头 0xAA 0x55 就是专属暗印，看到它才拆信。

生活比喻 · 骑缝章
CRC8 = 防篡改封蜡

1Mbps 下难免错一个比特。CRC8 是信封上的骑缝章：收信人合不上章就整封退回，绝不执行错误脉宽。

生活比喻 · 秒表口令
1Mbps = 每秒百万字节

串口没有时钟线，双方约定同一速率（BAUDRATE=1000000，8N1）—— 口令对不上，听到的全是乱码。

帧的完整结构与换算关系（本课程全系列通用）：

字段取值/含义类比
帧头0xAA 0x55信封暗印，固定两字节
功能码 func0x05 多舵机写 / 0x0B 释放扭力信的类别：下指令 or 松手掌
长度 len + 数据段舵机 ID 与对应 PWM 值信的正文：几号舵机、转到几 μs
CRC8256 字节查表 _CRC8_TABLE，与 board_sdk.py 完全一致骑缝章，错一字节即拒收
🔍 关键跃迁PWM ↔ 弧度只差一条公式：弧度 = (PWM − 1500) × 0.002356（CENTER_PWM=1500，PWM_TO_RAD=0.002356）。EXP-03 起 ROS2 的 joint_command 发弧度，底层发 μs —— 两侧永远由这条公式对账。

03关联知识点：串口 · 帧 · CRC8

知识点 1
pyserial 三行开串口

serial.Serial('/dev/ttyUSB0', 1000000, timeout=1) —— 超时 1 秒防止无限阻塞；Linux 权限靠 dialout 组或 chmod 666。

知识点 2
带宽账本

5 个关节 × 50Hz × 约 7 字节/帧 ≈ 1750 B/s，只占 1Mbps 带宽的 约 1.4% —— 所以总线上还能挂更多舵机。

知识点 3
裸机 vs ROS2 路线

裸机：字节级可控，适合协议调试；ROS2（EXP-03）：bringup + arm_controller 桥接，适合系统集成。同一硬件，两种开发体验。

SERIAL_PORT = '/dev/ttyUSB0'
BAUDRATE    = 1000000          # 1Mbps 8N1
try:
    ser = serial.Serial(SERIAL_PORT, BAUDRATE, timeout=1)

04实验目标

  • 能默写帧结构 0xAA 0x55 + func + len + data + CRC8，并解释每一段的作用
  • 完成串口权限授权（dialout 组或 chmod 666），验证 /dev/ttyUSB0 可读写
  • 运行 python3 test_servo_direct.py，用 interactive_mode 菜单控制 5 关节 + 夹爪
  • 用 s 1 1520 等命令单点微调，用 work 一键回工作位 [1500,1100,2200,1850,1500]
  • 录制 pre_grasp → grasp_down → lift 六步动作序列（save），导出 pick_and_place.yaml 并 colcon build 安装
  • 用 cutecom 等串口助手抓一条真实帧，逐字节对照协议结构

05实验环境与准备

硬件连接
USB 转 TTL → /dev/ttyUSB0

1Mbps 8N1；先 ls -l /dev/ttyUSB* 确认设备名，CH340/CP2102/FT232 驱动名都可能是 ttyUSB0。

权限授权
两种解法二选一

临时：sudo chmod 666 /dev/ttyUSB0；永久：sudo usermod -a -G dialout $USER 后重新登录。

清场动作
cleanup_ros.sh 先行

一键停掉所有 ROS 节点，避免 base_driver 与脚本抢同一串口 —— 抢占的典型症状是 Permission denied 或乱码应答。

# ① 清理占用串口的应用（不启动 bringup！）
bash cleanup_ros.sh

# ② 确认设备与权限
ls -l /dev/ttyUSB0
# 预期：crw-rw-rw- 1 root dialout /dev/ttyUSB0；没有就 chmod 666
dmesg | grep tty     # 找不到设备时看内核插入日志

06动画讲解：脉宽暗号与数据帧

同一个 1500μs 是"立正"，2000μs 是"向右看齐"；而一整封"信"则按 帧头→正文→骑缝章 的顺序逐字节出发：

动画 2-1｜上：同一条时间轴上 1000/1500/2400μs 三种脉宽对应三种关节角；下：0xAA55 帧逐字节点亮并流向总线（2.6 秒循环）

07互动讲解：PWM ↔ 关节角换算器

双向换算，公式只有两条：弧度 = (PWM−1500)×0.002356，PWM = 弧度÷0.002356+1500；试算台同时把关 500~2500 安全红线：

08实操步骤：test_servo_direct 实战

1清场 + 授权：cleanup_ros.sh 停 ROS，chmod 666 /dev/ttyUSB0
2启动裸机调试：python3 test_servo_direct.py，看到"打开串口 /dev/ttyUSB0 @ 1000000..."即成功
3interactive_mode 单点调试：work 回工作位 → s 1 1520 微调 1 号舵机 → g 1000/g 2000 开合夹爪
4录动作序列：逐条 save 命名 pre_grasp / gripper_open / grasp_down / gripper_close / lift / back_work
5导出 YAML：yaml → pick_and_place.yaml → colcon build --packages-select car1_arm_controller 安装生效
# 交互菜单常用命令（在 interactive_mode 提示符下输入）
work            # 5 关节齐回工作位 PWM [1500,1100,2200,1850,1500]
s 1 1520        # 1 号舵机单独设为 1520μs（中位+20，微调神器）
g 1000          # 夹爪闭合端；g 2000  # 夹爪张开端
save pre_grasp   # 把当前 5 路 PWM 存为命名动作（内存态）
yaml            # 导出 pick_and_place.yaml（EXP-03 回放要用）

# 可选：串口助手逐字节抓帧
cutecom --device /dev/ttyUSB0 --baud 1000000

# 导出后必须重装，install/ 才会拿到新 YAML
colcon build --packages-select car1_arm_controller
⚠️ 动作只活在内存里save 存的序列退出 interactive_mode 即丢，唯一持久化途径是 yaml 导出；且 YAML 在包 share 目录里，不 colcon build，EXP-03 的 action_player 就找不到它。

09重点与易错点

💡 本实验最大重点安全窗 500~2500μs 是铁律：超出范围轻则舵机撞机械限位，重则堵转发热打齿轮 —— 堵转损失不在质保范围。任何手动输入 PWM 前先心算它落在哪。
⚠️ 常见坑现象 → 解法
Permission denied打不开 /dev/ttyUSB0 → sudo chmod 666 /dev/ttyUSB0 或加入 dialout 组重新登录
找不到设备ls 无 ttyUSB0 → dmesg | grep tty 看实际插入名，或换线/换接口
串口被抢占脚本与 bringup 同开 → 应答乱码或直接失败 → 先 bash cleanup_ros.sh
PWM 越界输入 3000μs 手臂顶死 → 严格执行 500~2500 窗口，先试 1520 这种近中位值
yaml 后找不到文件action_player 报文件不存在 → 检查 install/ 是否生成，必须 colcon build 重装
退出后动作丢失重开脚本 save 列表空了 → 正常现象，持久化只能靠 yaml 命令
  • 串口打开日志显示 /dev/ttyUSB0 @ 1000000，无 Permission denied
  • work 后 5 关节与夹爪同步到达 [1500,1100,2200,1850,1500] 对应姿态
  • s 1 1520 只动 1 号舵机，说明 ID 寻址正确
  • 六条 save 全部命名成功，yaml 导出后 install/share 下存在新 YAML
  • 能口头解释：为什么这条路线"不依赖 ROS2 启动任何节点"，以及它与 EXP-03 ROS2 路线的分工

10总结与思考

✅ 完成成果
裸机驱动 5 臂 1 爪

pyserial 直连总线，菜单调试、单点微调、序列录制、YAML 导出全通过。

🧠 原理收获
协议三件套

0xAA55 帧头定界、func/len/data 载荷、CRC8 查表校验；PWM↔弧度一条公式打通软硬。

🛠 技能收获
串口工程能力

权限授权、设备排查（dmesg）、串口互斥清场（cleanup_ros.sh）、cutecom 抓帧。

❓ 排障思路
排查自底向上三层

线与权限（ls/dmesg）→ 波特率与帧（cutecom 原始字节）→ 才轮到上层逻辑。

📝 思考题 1五个关节 50Hz 持续刷新只用掉约 1.4% 的 1Mbps 带宽 —— 如果总线上挂 10 个舵机并把频率提到 100Hz，带宽还够吗？请估算，并说明超出带宽会先出现什么症状。（提示：单帧约 7 字节）
📝 思考题 2CRC8 能发现"传输错字节"，却拦不住"命令本身写错"——比如你把 1520 误敲成 15200（越界值）。协议层和应用层各应该加什么防线？对照本页安全红线与下一章的限位表回答。
