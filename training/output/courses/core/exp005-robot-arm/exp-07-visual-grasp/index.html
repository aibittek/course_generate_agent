EXP-07 · 第 3 章 · 综合性 · 8 学时

视觉动态抓取

课程大一统：深度相机看世界、HSV 找颜色、反投影定三维、TF 换算到基座、IK 反解、状态机执行——visual_grasp.launch.py 一条命令拉起 5 节点，人机协同的 start/confirm/skip/abort 服务把"看见→确认→抓起"变成可运营的流水线。

⭐⭐⭐ · HSV+深度+TF · 8 学时

01问题引入

EXP-06 的坐标是尺子量的——物体一挪就抓空。要让机械臂"看到"物体，需要把一帧彩色图像变成 base_link 下的 3D 坐标，再交给你已经熟悉的 IK+抓取链路。这中间横着三座桥：

  • 颜色桥（HSV）：图像成千上万像素，哪些属于目标？光照一变 RGB 全乱，HSV 才稳。
  • 深度桥（反投影）：像素 (u,v) 只有二维，加上深度图的 d 才能还原相机坐标系里的 (X,Y,Z)。
  • 坐标桥（TF）：相机装在夹爪上随臂晃动，相机系的点必须实时换到 base_link 才能抓。

本实验 8 学时：一条 launch 拉起全栈，rqt 三栏盯着它看，四个人机服务管着节奏，最后拿红色物体（30~50mm）做成功率验收。

02原理通俗讲解

HSV 分色像用"色相环"筛豆子。RGB 是红绿蓝三盏灯的混合亮度，灯一暗全都变样；HSV 把"什么颜色（H）"、"多纯（S）"、"多亮（V）"拆开——只圈定 H 的范围，屋内灯稍亮稍暗都不影响筛选。inRange 就是拿一个区间筛子过一遍像素，命中的涂白成掩膜。

深度反投影像"由近及远钉钉子"。已知像素在画面偏右 100 像素、深度 0.5m：乘内参（fx≈614）一除，就知道它在相机右侧约 8 厘米、正前方半米——(u,v,d)→(X,Y,Z) 就是这一除。深度图单位是 uint16 的毫米，用前必须 /1000，这是最经典的翻车点。

TF 像"随军翻译"。相机说"在我右前方 30cm"（camera_depth_optical_frame 系，X右/Y下/Z前，REP-103），底座听不懂；tf_buffer.transform 一换算，底座就知道"在base_link 前方多少"。相机装在手上，臂一动翻译表就更新——这就是 TF 的实时性。

look-then-move 是"看准了再伸手"。观察（OBSERVE）→ 有人按确认（CONFIRM）→ 猛抓（PICK）→ 回怠速（IDLE）。光看不确认就动是鲁莽，确认了快动是果断——五态循环把二者拆开。

形态学开闭
先擦后补的橡皮擦

开运算（先蚀后胀，5×5 核）擦掉小噪点；闭运算（先胀后蚀）补上掩膜窟窿，让轮廓完整。

安全熔断
面积 < 500 像素不抓

轮廓太小按噪声处理，宁可 skip 也不夹空气——防误抓的第一道闸。

04实验目标

  • 理解视觉抓取端到端原理：HSV 检测 → 深度反投影 → TF 变换 → IK → 状态机，五模块各司其职。
  • 独立完成一站式启动 visual_grasp.launch.py 并跑通"start → 观察 → confirm → 抓取"动态闭环。
  • 能调 HSV 阈值适配新颜色物体（hsv_tuner.py），检测成功率 >95%。
  • 能调 gripper_depth 适配 30~50mm 物体，并解释 look-then-move 与眼在手下压失视野问题的对策。
  • 掌握四服务人机节奏与重复抓取处理（目标已抓走时自动 skip，避免夹空气）。

06动画讲解：观察—确认—抓取三乐章

动画 9 秒一循环：左框里绿色虚线框住红色目标并提取质心，经 TF 换算到 base_link；右上状态机光点在 OBSERVE(绿)→CONFIRM(黄)→PICK(红)→IDLE(蓝) 间移动；下方机械臂在 PICK 段伸出、合爪、带物回位——"看准了再伸手"的节奏一目了然。

07互动讲解：HSV 掩膜调参台 + 反投影验算

互动台 · 换色适配 + (u,v,d)→(X,Y,Z) 验算
默认红目标 = 两段并集：主段 H∈[0,15] ∪ 副段 [160,180]（红卡在 H 环两端），S≥100、V≥80（launch 实参 [0,100,80]）；本台窗口只模拟主段。反投影内参：fx=fy=614、cx=320、cy=240；深度 uint16 单位 mm，须 /1000，有效窗 0<d≤2.0m。

先点"判掩膜窗口"：H 区间与预设完全一致报 ok，部分重叠报 warn（会漏检边缘色阶），完全无关报 bad。再点"反投影"：输入质心像素与深度毫米数，按 X=(u−cx)·d/fx, Y=(v−cy)·d/fy, Z=d 算相机系坐标——和你在 rqt Mask 栏看到的白色团块互为印证。若报"深度无效"，对照讲义"深度单位混淆：uint16 是 mm 不是 m"与 0<d≤2.0m 窗口。

# 步骤 1 · 一站式启动（visual_grasp.launch.py 内含 5 个 NodeAction）
ros2 launch car1_app visual_grasp.launch.py
# [INFO] [visual_grasp_node]: State IDLE, waiting for /visual_grasp/start
# 分阶段启动时序（t=0/5/8/12/14s 点）：先相机出流 → 检测节点 → 状态机 → 服务就绪

# 步骤 2 · 三栏可视化 + 调参（rqt_image_view 分别订阅）
#  左栏 /visual_grasp/rgb_annotated   中栏 /visual_grasp/depth_overlay   右栏 /visual_grasp/mask
python3 hsv_tuner.py     # 实时拖阈值看 mask；yellow 20-40 / red 0-10 / blue 100-130 / green 40-80

# 步骤 3 · 反投影自测（fx=614, cx=320, cy=240；深度 uint16 mm）
# u,v,d = 320, 240, 500 → X=(u-cx)*d/fx, Y=(v-cy)*d/fy, Z=d/1000；深度窗 0 < d ≤ 2.0m
# 标定物实测：1m 距离误差预期 ±2-3cm；超差先查 camera_info 内参是否更新

# 步骤 4 · TF 链与时序
ros2 run tf2_tools view_frames      # … → link5 → tcp_link → camera_depth_optical_frame
ros2 run tf2_ros tf2_echo base_link camera_depth_optical_frame

# 步骤 5 · 人机协同四服务（Trigger 类，命令体留空）
ros2 service call /visual_grasp/start   std_srvs/srv/Trigger "{}"
# 日志：[INFO] State: IDLE -> OBSERVE → Detected red object at pixel (320, 240) → OBSERVE -> CONFIRM
ros2 service call /visual_grasp/confirm std_srvs/srv/Trigger "{}"   # 确认后进入 PICK
ros2 service call /visual_grasp/skip    std_srvs/srv/Trigger "{}"   # 放弃本目标（重复抓取也自动 skip）
ros2 service call /visual_grasp/abort   std_srvs/srv/Trigger "{}"   # 中止回 IDLE
# 步骤 6 · 换色验收（以抓 30~50mm 红色物体为例）
# 1) hsv_tuner.py 把 H 区间改为 0~10（红），保存到参数 yaml
# 2) 桌面摆放红色物体，start → OBSERVE <1s 出框 → confirm → 观察 PICK <8s
# 3) 拿走物体再 start：轮廓面积 <500 应被熔断 / 检测为已抓取自动 skip（误抓率 <5% 的来源）
# 4) 参数调优：gripper_depth 适配 30~50mm 物体；需要免确认直连时加 wait_for_confirmation:=false
ros2 launch car1_app visual_grasp.launch.py wait_for_confirmation:=false
# 验收指标：HSV 检测成功率>95% · 单周期<15s · 抓取成功率>85%

09重点与易错点

难点预警——眼在手下压失视野：相机装在腕部，机械臂 DESCEND 下压时目标会滑出视野甚至贴得太近失焦。对策即 look-then-move 的本义：观察阶段锁定 base_link 坐标，抓取段只信这份额定坐标，中途不再追着实时像素跑（需要复看就抬回观察位再 OBSERVE）。
坑现象对策
深度单位混淆反投影差 1000 倍D435/HP60C 深度 uint16 单位是 mm，用前 /1000；有效窗 0<d≤2.0m
内参不对反投影误差超 2-3cm检查 camera_info 内参是否更新；重跑标定/确认 fx≈614 cx≈320 cy≈240
检测不到目标Mask 全黑放宽 HSV（lower 减小、upper 增大）；补光照
误检背景Mask 大片白收紧 HSV + 提高最小轮廓面积阈值（>500）
坐标系方向错抓取整体偏 90°REP-103：optical 系 X右/Y下/Z前；用 tf2_echo 核对链路每一跳
空抓/夹空气PICK 落空目标被拿走应触发面积熔断或自动 skip；确认 wait_for_confirmation 语义
launch 起不全某节点假死盯 5 个 NodeAction 启动时序（t=0/5/8/12/14s），相机流先就绪再放检测
  • 交付四件套：换色检测成功率 >95%、单周期 <15s、整体成功率 >85%、误抓 <5%。
  • 三栏图像必须都看过才收工：rgb_annotated（框）、depth_overlay（深度着色）、mask（二值真相）。
  • 留档一组"失败样本"截图 + 当时 HSV/深度/TF 日志——调试能力比一次成功更值钱。

10总结与思考

三座桥
HSV · 反投影 · TF

颜色→掩膜→像素质心→毫米→米→base_link。

五节点一键
visual_grasp.launch

相机+检测+状态机+服务同起，时序自管。

人机四服务
start/confirm/skip/abort

看→点头→抓→回，重复目标自动 skip。

验收指标
95% / 85% / 5%

检测率、成功率、误抓率三线齐守。

思考题 1：把 S 阈值下限从 100 降到 30 会让更多像素进入掩膜——检测率会上升还是误检率会上升？结合"开运算 5×5 去噪"和"最小面积 500"设计一组你自己的调参顺序（先调谁、后调谁、每次依据什么栏判断）。
思考题 2：look-then-move 在物体被人挪动的场景里会抓空。若要升级为"持续跟随"，五态循环哪里要改？把眼在手下压失视野的约束、TF 实时更新能力、以及 EXP-06 的分步移动一起纳入你的方案草案。
