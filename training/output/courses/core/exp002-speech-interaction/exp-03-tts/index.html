EXP-03 · 第 1 章 · 设计性 · 4 学时

TTS 语音合成：让机器人开口说话

机器人听懂了，还得用自然的人声回答。本实验用"打字员查字典"的类比，带你理解文字变声音的三步过程，然后动手合成一句话、播放出来、调语速与音量听变化。

难度 ⭐⭐ · 4 学时 Matcha-TTSVocos 声码器 dB 与增益RTF 实时率

01问题引入：只会"听"不会"说"的机器人

前两个实验让机器人能听、能转成文字。但如果它回答时屏幕上只打印一行字——用户就得盯着一台会说话的机器看字幕，交互感瞬间归零。语音输出要解决三个问题：

1读不对："2026年9月24日"该念"二零二六年九月二十四日"还是逐位蹦数字？数字、日期、英文缩写要先"正读"
2算得慢：一句 10 秒的话算了 30 秒，对话根本没法进行——合成速度必须跟上说话速度（这就是 RTF 要 < 1 的原因）
3放不对：合成好的语音从喇叭出来变成"快放 2 倍"，或者干脆没声音——采样率 / 声道 / 硬件开关没对齐
💡 一句话理解TTS 的任务就是把文字变成声音，而且要快、要清晰、要自然。本实验会依次撞上这三个问题，并逐个解决。

02原理通俗讲解：从文字到声音的三级跳

生活比喻：编辑 → 谱曲 → 演唱。想象你要把一篇歌词变成一个真实的人声：

1文字变音素 = 编辑查字典：把每个汉字查到对应拼音（严格说是"音素"，发音的最小单位），同时把"2026"改写成"二零二六"这种能读的形式
2音素变频谱 = 谱曲定旋律：为每个音素定出力度、高低、长短，画成一张"时间 × 频率"的强度图（梅尔频谱）。它规定每一时刻各频率该有多响
3频谱变波形 = 歌手发声：按这张谱把空气真的推动起来，得到一串采样点（PCM 波形），送进喇叭就响了
概念编辑/歌手类比本实验的模型
文本规范化 + 音素化编辑查字典，改写数字与缩写rule_fsts（number-zh / date-zh / phone-zh）+ lexicon.txt
声学模型（音素 → 频谱）谱曲，决定旋律与节奏Matcha-TTS（model-steps-3.onnx，基于 flow-matching）
声码器（频谱 → 波形）歌手真的唱出来Vocos（vocos-16khz-univ.onnx，频域神经声码器）
语速控制整体演唱的快慢--speed，伸缩每个音素的时长
🔍 为什么要分三步，而不是一步到位直接从文字跳到波形，模型要同时学会"语言规则 + 声学细节 + 波形生成"，一件事都学不精。先定怎么读、再定怎么唱、最后真的发声——三段各管一摊，每段都能独立替换和调试。你用 ls 看到的那个 acoustic_model 和 vocoder 两个文件，就是这条分界线的物理体现。

为什么"音量百分比"和 dB 不是一回事

这是本实验最容易含糊的一个点。人耳对响度的感知接近对数关系，所以音频设备用 dB 描述增益，代码里把 0~100% 的滑块换算成 dB：

dB = 20 × log₁₀(pct / 100)

百分比换算 dB听感
100%0 dB（源码直接返回 0.0）满档，不失真
50%约 −6 dB声压减半，听起来"轻一档"，绝不等于"小一半"
10%约 −20 dB明显变小，但还听得见
0%−96 dB（源码用这个值近似静音）当作静音处理
⚠️ 别想当然① 0% 不是把 0 直接传给 amixer——那样行为不确定，源码约定用 −96dB 代表静音。② dB 换算说的是硬件音量旋钮；另一条路径 --gain 是数字增益，直接乘在采样点上，两者作用位置完全不同（下面第 03 节有图）。

03关联知识点

模型
Matcha-TTS 声学模型

输入音素序列，输出梅尔频谱。基于 flow-matching，推理步数少、参数小（约 25M），CPU 上单句 200~400ms。文件是 model-steps-3.onnx——名字里的 3 就是推理步数。

模型
Vocos 声码器

不在时域逐点生成波形，而是在频域预测每帧的复数频谱，再用逆短时傅里叶变换还原波形。音质稳定、对采样率更鲁棒。文件是 vocos-16khz-univ.onnx（16kHz 通用版）。

文本
rule_fsts 文本规范化

一组有限状态转换器（FST）规则，把"2026/9/24"转成"二零二六年九月二十四日"。tts_test.py 默认加载 phone-zh + date-zh + number-zh 三个。

硬件
amixer 与四路控制

setup_playback() 同时设置 Output 1、Output 2、PCM 三路增益到同一个 dB 值，再打开 Speaker / spk switch 功放使能。少开一路就是"调了没反应"。

信号
float32 → int16 量化

模型输出是 [-1, 1] 的浮点数，写 WAV 必须量化成 16 位整数。乘 32767（不是 32768，否则 +1.0 会溢出翻转），且先 clip 再乘。

通路
mono → stereo 复制

ES8388 的 I2S 总线是硬件双声道。喂单声道文件时按立体声节拍读，等于只读了半个文件、剩下一半是 0 → 听感是"2 倍速 + 断续"。解决：把 mono 复制成 (L, R)。

增益
clip 硬削峰（源码用的就是这个）

play_audio() 里是 (samples * gain).clip(-1.0, 1.0)。超过 ±1 的部分被一刀切平，会产生高次谐波 → 破音。tanh 是更温和的替代（渐近压缩），但本仓库源码并未使用它。

性能
RTF 实时率

RTF = 合成耗时 ÷ 音频时长。< 1 才够用，CPU 上典型 0.25~0.40；> 1 说明算得比说得慢，交互会卡。

04实验目标

  • 理解 TTS 三级跳：文字 → 音素/频谱 → 波形，并能指出每个阶段对应哪个文件
  • 用 tts_test.py 合成并播放第一句机器人语音，听感清晰、不是 2 倍速
  • 用 --speed 调语速，说清 1.3× 和 0.8× 的听感差别与边界（>1.5 吞字、<0.6 拉扯）
  • 读懂 pct_to_db，能手算出 50% → −6dB，并说明"为什么不是线性"
  • 会看 RTF 判断合成速度是否达标；解释"为什么 RTF 达标仍可能听不清"
  • 能复现并修好两个必踩故障：2 倍速播放、扬声器无声
  • 能说清 --gain（数字路径）与 --playback-volume（硬件路径）的区别

06动画讲解：文字 → 音素 → 谱 → 波形

看一句"今天是2026年9月24日"的旅程：文字先被"查字典 + 正规化"变成音素 → 音素排成频谱 → 频谱还原成声波 → 经硬件音量与数字增益后从喇叭播出。

动画 3-1｜文字经 rule_fsts 正规化 + 查词典变音素 → Matcha 排成梅尔谱 → Vocos 还原波形 → 经数字增益与硬件 dB 音量后从喇叭播出（4 秒循环）
🔍 两条增益路径，别混着调数字增益 --gain：在 Python 里把采样点乘一个倍数，作用在"写文件之前"，默认 2.0，调太大直接 clip 破音。硬件音量 --playback-volume：通过 amixer 设声卡寄存器（dB），作用在"功放之前"。排错顺序是：先确认硬件路（Speaker 开关有没有开、dB 是多少），再动数字路——反过来会越调越糊。

09重点与易错点

🎯 本实验重点① 三级跳链路（正规化 → 声学模型 → 声码器）；② 两条增益路径（数字 clip / 硬件 dB）的作用位置；③ RTF 的算法与达标线；④ mono→stereo 的必要性。四条都能讲清，TTS 就算拿下了。
⚠️ 常见坑现象 → 解法
2 倍速快放声音像按了快进、断续 → mono 文件喂给立体声 I2S 通路。用 tts_test.py（内部 write_wav_stereo）或 audio_test.py --mode play（自动转换），别用 aplay 直接播
扬声器完全无声合成成功但一点声音都没有 → Speaker / spk switch 功放开关没使能。手动执行 amixer -c 0 sset 'Speaker' on 再播
音量调了没反应--playback-volume 改动无效 → 控制项名字对不上（不同板卡名字不同）。先 amixer scontents 查真实名字；setup_playback 里的四路必须都设
PCM 压低后语音含糊为了"小声一点"把 PCM 调到 −20dB，结果听不清 → PCM 属于数字域，压它等于减少有效位。要小声请调 Output 1/2
--gain 4.0 破音出现"嘶嘶"的谐波失真 → 源码用 clip(-1,1) 硬削峰。降到 1.5~2.0；若要更响请走硬件音量
数字读法错"2026"被逐位念成"二零二六"以外的怪读法 → 确认 rule_fsts 加载了 number-zh.fst / date-zh.fst
中文乱音合成出听不懂的音 → lexicon.txt 缺中文条目或编码非 UTF-8，换中文版词典
config 校验失败TTS config validation failed → 模型路径含中文/空格，或某个 onnx 文件缺失。config.validate() 会逐个检查
RTF 突然飙高从 0.3 跳到 1.5 → CPU 温度降频，或别的进程抢 CPU；top 确认后关掉无关进程
交互模式 speed 改不回试了很多档位后回不到默认 → 直接输入 speed=1.0，或重启程序
极短文本合成失败少于 3~4 个字时 Vocos 对静音段敏感 → 文本补足到 4 字以上，或在句尾加点
