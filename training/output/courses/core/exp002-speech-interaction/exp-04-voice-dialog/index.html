EXP-04 · 第 2 章 · 设计性 · 8 学时

端到端语音对话：让机器人接得住话

把唤醒、识别、理解、回答、播报串成一个能聊天、能被打断的完整循环。本实验整合前面三个实验的模块，让机器人做到"喊它 → 它听 → 它想 → 它说"。

难度 ⭐⭐ · 8 学时 三态状态机 防回声 流式分句 打断 barge-in

01问题引入：把"听、想、说"串成一句话有多难

到这里你已经有了三个零件：能听见叫它（EXP-01）、能听懂句子（EXP-02）、能开口说话（EXP-03）。可是把三个脚本直接拼起来，机器人并不像一个能聊天的伙伴，倒像三个各干各的实习生：

1它自己跟自己聊
喇叭刚放出的回答，又被自己的麦克风听了进去，当成"你在说话"。
→
2它不肯停
回答念到一半你想插话，它非要念完最后一句才理你。
→
3它反应慢
要等大模型把整段话写完才开口，第一句就得等好几秒。

这些问题没有一个出在单个模块上——识别是对的、合成也是对的——出在模块之间怎么交接：

看到的现象缺少的那个机制
机器人自问自答，把自己的话当成用户输入防回声：说话的时候要"捂住耳朵"
插话无效，必须等它念完打断：随时可以插话，立刻闭嘴
首句响应慢，"想到才说"流式分句：大模型说一句，喇叭播一句
💡 本节要点端到端语音对话的难点不在"换个更大的模型"，而在安排谁在什么时刻干活。这也是从"模块演示"走向"能用的产品"的分水岭。

02原理通俗讲解：三个房间轮流用麦克风

生活比喻：机器人只有一间录音棚。棚里只有一支麦克风和一个喇叭，所以同一时刻只能有一个角色在里面干活。门口挂着一块牌子，写着"现在轮到谁"——这块牌子就是状态（state）。

1IDLE（待机）· 守门的人
竖着耳朵只等一句话：叫"小飞小飞"。别的动静都当没听见。
→
2LISTENING（聆听）· 做记录的人
先"哎"一声（提示音），然后专心把你说的话记下来，直到听出你停下来了。
→
3SPEAKING（说话）· 念稿的人
把想好的答案一句句念出来；念的时候耳朵还留着一只，听你有没有插话。

牌子同一时刻只写一个名字，所以流程永远不会"串台"——这就是三态状态机的全部含义。

四个必须懂的小机制

🔇 防回声
说话时捂住耳朵

你对着电话大声说话，听筒里的声音会绕回来。机器人也一样：提示音和它自己的回答会绕回麦克风，被识别成"用户说话"。做法是播提示音前后把音频缓冲清干净，再开始认真听。

✂️ 流式分句
说一句，吐一句

不等大模型把整段写完。它一边想，我们一边按句号逗号切开：切出一句就合成一句、播一句。第一句几秒内就能听到，不用干等。

✋ 打断
允许插话

念稿的时候，守门的人没有下班——唤醒词仍在监听。一旦又听到"小飞小飞"，立刻停止播放，回到聆听状态听你要说什么。

🔁 回到待机
念完把牌子翻回去

不管这段回答是正常念完、被打断、还是出错，最后都必须把牌子翻回 IDLE，否则下一次喊它就没反应了。

整条链路（记住这五个词就够了）：

1拾音　麦克风一直采，声音进缓冲队列
→
2唤醒　听到"小飞小飞"才开工
→
3识别　ASR 把你的话变成文字，你说停了它就收尾
→
4理解 + 回答　大模型边想边吐字
→
5合成 + 播放　按句切给 TTS，一句句从喇叭出来
🎯 核心直觉状态机回答的是"我现在该干什么"，流式回答的是"内容怎么不停地流过去"。两件事叠加，才有"边想边说、随时能打断"的对话感。
📌 进阶（先记名字，跑通再看代码）真实源码里还有几个工程细节：清缓冲要做两轮（中间停 0.2 秒等尾巴回声灌完）、播放器常驻不反复重启、大模型超时要主动放弃。它们解决的问题都是上面四个概念，不影响你先跑通。

03关联知识点

🔄 状态机
三态切换

IDLE / LISTENING / SPEAKING，由 state 一个变量决定。任何时刻只处于一个状态，每个状态只做一件事。

🔇 防回声
清空音频缓冲

播提示音时麦克风还在采，回声会混进下一轮识别。清缓冲 + 稍等片刻，让回声先流干净。

✂️ 流式
按句切分

大模型边生成、TTS 边合成。句号、问号、逗号都是切点，切出一句就送一句。

✋ 打断
barge-in

播报期间唤醒词仍在监听，命中就停播、放弃当前回答，回到聆听。用户插话不需要等。

04实验目标

  • 能说出三个状态的名称与切换条件，并解释为什么"同一时刻只能有一个状态"
  • 跑通 voice_interaction.py --mic-array，完成一轮完整的"唤醒 → 提问 → 听到回答"
  • 观察流式分句的效果：第一句回答在几秒内响起，而不是等整段生成完
  • 成功完成一次打断：回答中途说唤醒词，机器人 1 秒内闭嘴并回到聆听

步骤 3：喊唤醒词 → 说一句 → 听回答

# 对着六麦阵列清晰地说：
"小飞小飞"     → 听到"叮"的提示音
"今天北京天气怎么样？" → 停顿一下，等它开口

# 程序侧应看到三轮日志（加 --debug 更详细）
# [Main] IDLE → LISTENING
# [ASR]  今天北京天气怎么样？
# [Main] LISTENING → SPEAKING
# [LLM]  我没有实时查询天气的能力…
# [Main] SPEAKING → IDLE
⏱ 重点观察第一句回答应该在你停嘴后几秒内响起，而不是等整段文字生成完——这就是流式分句的效果。说完话要停一下（约 1 秒），让程序判断你讲完了。

步骤 4：中途打断

# 让它回答一段较长的话，念到一半时再说一次："小飞小飞"
# [KWS] 打断: 小飞小飞
# [Main] SPEAKING → LISTENING (打断)
# 提示音再次响起，等你说话

预期输出：喇叭立刻安静（1 秒内），随后重新提示你说话。再问一句新问题，能正常回答，说明状态没有卡住。

09重点与易错点

⚠️ 排错思路先问一句"它现在卡在哪个状态"，再去看那个状态对应的日志。90% 的问题不是模型错，而是时序没对齐。
现象原因怎么办
机器人自问自答 / 把自己的话当输入（回声） 提示音或回答的声音绕回麦克风，缓冲没清干净 等提示音播完再开口；确认清缓冲做了两轮；仍出现就把"播完后再等一会儿"的时长调大
说完没反应，一直停在聆听 没检测到"你说完了"（端点）／麦克风没收到声音 说完整句子后停顿约 1 秒；检查 arecord -l 与录音电平；约 5 秒没人说话它会自动回待机，重喊一次唤醒词即可
打断失效，必须等它念完 播报时把唤醒监听关掉了，或打断标志没在新一轮开始前复位 确认 SPEAKING 期间唤醒词仍在监听；打断后进入下一轮前先清掉打断标志
  • 三个状态的名字和切换条件要能一口气说出来，排错时才有抓手。
  • 打断时"先发停止信号，再关播放器"——顺序反了会漏掉一小段声音。
  • 无论正常念完、被打断还是出错，最后都要回到 IDLE，否则下一次喊它没反应。

四个概念

三态状态机管"谁在干活"，防回声管"别听见自己"，流式分句管"别干等"，打断管"随时能插话"。

从"听见字面"到"听懂意图"

现在它只是把话原样交给大模型。下一个实验让大模型正经做意图识别和槽位提取，真正听懂你要它干什么。

💭 思考题

1. 三个人共用一间录音棚，如果没人规定"现在轮到谁"，会发生什么？请用这个比喻解释：为什么必须有一个 state 变量，而不能让唤醒、识别、播报三段代码各跑各的？

2. 打电话时对方一直说个不停，你会怎么办？机器人要做到"能被打断"，必须同时满足两个条件——听得见（播报时仍监听唤醒词）和停得下（立刻停止播放）。如果只保留第一个会怎样？只保留第二个又会怎样？
