EXP-01 · 第 1 章 · 设计性 · 4 学时

六麦阵列唤醒：机器人耳朵的第一课

本实验回答一个生活问题：你喊"小飞小飞"，机器人怎么知道你在叫它？背后是三件事——六个麦克风靠"时间差"算出方向、专用声卡芯片认出唤醒词、代码里 3 秒冷却防止连声重复触发。我们跑通一个 GUI，亲眼看到波束方向随你站的位置转动。

难度 ⭐⭐ · 4 学时 六麦阵列 TDOA 定向 唤醒词 · 防抖 AIUI 协议 · pyserial

01问题引入：机器人怎么知道"你在叫它"

对着智能音箱喊一声"小飞小飞"，它灯带一转、应声而答；可要是两个人隔着房间聊天，它却不该随口插嘴。这个"该醒才醒"的问题，拆开是三连问：

1叫没叫？——麦克风时刻都在收音，怎么从嘈杂环境里认出"小飞小飞"这四个字
2谁在叫？——房间里多人说话，怎么判断声音来自哪个方向
3叫了几遍？——一句话尾音会重复触发，怎么避免 1 秒内醒来 5 次
💡 思路前两个问题交给阵列板载的声卡芯片实时解决：它在芯片内部完成"拾音 + 定向 + 认唤醒词"，一旦命中就通过 USB 串口发一条消息给主机。主机只负责读消息、做防抖、调度后续动作——专业的事交给专业的芯片。第三个问题（防抖）反而是主机这一侧的软件活，也是本实验要你亲手改的地方。

02原理通俗讲解：一只耳朵定向，两只耳朵分工

生活比喻：蒙眼听人喊你。蒙上眼睛，你仍能下意识转头找到喊你的人。机理很朴素：声音到两耳有先后，大脑靠这点时间差算出方向。六麦阵列就是把"两只耳朵"扩成六只，绕成一圈，方向分辨得更细。

1定向 = 六只耳朵对表：6 个麦克风沿圆周均匀排布，同一句话到达每个麦的时刻略有先后。这个微小时间差叫 TDOA（到达时间差），芯片积累一段时间后反推出声源所在的角度（0~360°）与最靠近声源的波束编号（beam 0~5）
2唤醒词 = 认自家门铃：芯片提取声音特征，比对内置的"小飞小飞"声纹模板——就像门铃只认自家那声"叮咚"，别人按门铃不开门
3防抖 = 挂门挡：门铃刚响过就挂上门挡，短时间内重复的喊声一律忽略。本实验的"门挡"是代码里一个 3 秒时间窗 + 一把 非阻塞锁
概念生活类比本实验对应
TDOA / 波束蒙眼听声，靠两耳时间差转头ivw 事件里的 beam（0~5）与 angle（0~360°）
唤醒词检测 KWS门铃只认自家叮咚ivw 唤醒事件（默认"小飞小飞 / 小飞同学 / 芝麻开门"）
防抖 debounce挂门挡，短时间内不再响应3 秒时间窗 + wakeup_lock.acquire(blocking=False)

一条消息怎么从芯片走到你的屏幕

阵列插在 USB 口上，主机看到的不是"一个麦克风"，而是两样东西：一个 串口（负责传命令和事件）和一个 声卡（负责传连续音频）。本实验只用串口那一路。

层做什么你能验证的方式
物理层USB 线把阵列接到主机；芯片是沁恒 CH340/CH343 系列 USB 转串口（VID 0x1a86、PID 0x55d4）lsusb 看到 1a86:55d4
设备层系统注册成 /dev/ttyACM0（也可能是 ttyACM1），波特率 115200、8N1ls -l /dev/ttyACM*
协议层讯飞私有 AIUI 协议：以 0xA5 为同步头，7 字节定长头 + JSON 载荷 + 1 字节校验跑 GUI，日志里能看到解析出的 beam / angle
事件层消息类型 0x04 的事件里，eventType=4 就是"唤醒"喊唤醒词看到 [WAKEUP] 日志
🔍 串口是什么，为什么要"打包"串口（UART）就像一条只允许一个字节一个字节排队通过的窄门。既然是无头无尾的字节流，接收方怎么知道一帧从哪开始、到哪结束？靠三件事：同步头（看到 0xA5 才认为是一帧的起点）、长度字段（后面还有多少字节）、校验和（收完算一遍，对不上就丢掉）。这三个词，就是第 03 节要讲的"帧结构"。

03关联知识点

硬件
讯飞 XFM-DP 六麦环形阵列

6 麦环形布局 + 板载唤醒固件，USB 一线接入（同时暴露串口与声卡）。串口负责命令与事件，声卡负责音频流——这是两个独立通道，别混为一谈。

算法
TDOA 定向（输出 beam / angle）

靠到达时间差反推方向，芯片输出 beam（最靠近声源的那只麦，0~5）与 angle（0~360° 顺时针方位角）。角度约定见下方说明。

协议
AIUI 帧结构 + 校验和

帧 = 同步头(1) + 用户ID(1) + 类型(1) + 长度(2，小端) + ID(2，小端) + 载荷(n) + 校验(1)，共 7+n+1 字节。校验和 = (~sum + 1) & 0xFF。

机制
3 秒防抖 + 非阻塞锁

先比较"距上次唤醒是否超过 3 秒"，再用 acquire(blocking=False) 抢锁；抢不到说明上一次还在处理，本次直接丢弃。

工程
跨 read 拆帧与容错

一次 read 可能只收到半帧，所以要用一个 rx_buffer 累积。三处容错：丢弃同步头前的垃圾字节、长度异常判为伪同步头、校验失败跳过一个字节重找。

可视化
Tkinter Canvas + 队列刷新

接收线程只负责把事件 put 进 queue，主线程用 after() 定时取出重绘。Tkinter 不是线程安全的，跨线程直接改界面会崩。

⚠️ about angle：别按"生活直觉"读这个角度源码注释与图形工具里，angle 的 0° 取在正下方，并顺时针递增（6 只麦各占约 60°，与 beam 编号对应）。所以 beam=4 / angle≈300° 指向的是左上方，不是屏幕坐标系的"右上方"。做实验时以 GUI 箭头方向为准：站在阵列左侧喊一声，看箭头指向哪、数字读多少，把这个对应关系记在实验报告里，比背角度约定更靠谱。

06动画讲解：声波 → 波束成形 → 唤醒事件

下图从左到右展示一个唤醒周期：声波抵达六个麦克风（时间差高亮）→ 波束定向算出角度 → ivw 唤醒消息经串口飞向工控主机 → 防抖时间窗内忽略重复触发。

动画 1-1｜左：声波依次点亮六个麦克风（时间差即方向）；中：波束主瓣对准声源；右：ivw 唤醒帧经串口进入主机，防抖期内重复唤醒被拦截（4 秒循环）
🔍 一个必须澄清的误解"波束成形"这个名字容易被理解成"芯片合成一个指向性麦克风"。在本实验里你看到的 beam / angle 是芯片算出来的方向标签，不是你可以任意调整的可调参数——你改不了它，只能读它。真正能在代码里改的是防抖窗口、唤醒词、GUI 的绘制方式。

步骤 2｜手算一次校验和（理解"为什么能发现错误"）

python3 - <<'PY'
# 取一帧真实字节（从步骤1的输出里抄一段，长度不完整就凑到帧尾）
frame = bytes.fromhex("a5 01 04 20 00 12 00")

# 校验和 = (~sum(frame[:-1]) + 1) & 0xFF
body = frame[:-1]
expected = (~sum(body) + 1) & 0xFF
print(f"len(body)={len(body)}  expected_checksum=0x{expected:02x}")
print(f"实际帧尾=0x{frame[-1]:02x}  → {'一致' if expected == frame[-1] else '不一致（这帧不完整）'}")
PY

09重点与易错点

🎯 本实验三重点① 六麦阵列靠 TDOA 时间差定向，输出 beam / angle 两个标签；② 唤醒词像门铃只认自家叮咚，识别在芯片里完成；③ 3 秒时间窗 + 非阻塞锁，是主机这一侧防止连声误触发的手段。把这三件事想通，实验就成功了一半。
⚠️ 常见坑现象 → 解法
串口权限不足Permission denied: /dev/ttyACM0 → sudo chmod 666 /dev/ttyACM0，或加入 dialout 组后重新登录（只执行 usermod 不重登不生效）
设备号漂移重插后 ttyACM0 变 ttyACM1 → 用 ls -l /dev/serial/by-id/ 找稳定软链，别把设备号写死
串口被占用程序报"无法打开串口" → sudo lsof /dev/ttyACM0 找到占用进程（上一步的 cat、串口助手）先关掉
唤醒不触发阵列被遮挡 / 音箱自唤醒干扰 / 唤醒词不是内置那三个 → 阵列平放、离音箱 1m 以上，正对阵列正常音量喊"小飞小飞"
唤醒太容易触发环境噪声被误认 → 提高唤醒阈值（set_wake_word 里的 threshold，默认 "900"），或改用更长的唤醒词
GUI 报 no display远程/无桌面环境 → 用 --headless，或 xvfb-run / ssh -X
校验和频繁失败USB 线过长或质量差（>3m 易受干扰）→ 换短线；或改用带外接电源的 HUB（阵列供电不足也会丢帧）
  • lsusb 可见 1a86:55d4，GUI 能正常打开
  • 绕阵列走动，Angle 随方位连续变化（0~360° 回绕正常），并已记录"实际方位 ↔ beam/angle"对应表
  • 喊唤醒词出现唤醒日志；1 秒内连喊两次只触发一次回调
  • 能默写一帧 AIUI 消息的字段顺序，并手算过一次校验和
  • 能用自己的话向同伴讲清"防抖 = 挂门挡"和"锁 = 只让一个人进门"的类比

EXP-02 拿到文字

唤醒只是开门。门后的声音还要靠声学模型转成文字——那就需要打开阵列的另一条通道：声卡。

📝 思考题 1如果房间里两个人同时喊"小飞小飞"，阵列会唤醒几次？3 秒防抖能解决"同一个人连喊"的问题，能解决"两个人同时喊"的问题吗？如果不能，该在哪一层加什么机制？
