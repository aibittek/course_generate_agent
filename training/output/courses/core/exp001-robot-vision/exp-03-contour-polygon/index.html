多边形轮廓：把"一团像素"简化成"几个顶点"

上个实验我们已经能挑出目标区域了，但那只是一堆白色像素 —— 一堆点没法用。这个实验要把它压缩成几个顶点坐标：三角形给我 3 个点，四边形给我 4 个点。有了坐标，机器人才能算"往哪走、差多少"。

难度 ⭐⭐ · 4 学时 二值化凸包 approxPolyDP质心

01这个实验解决什么问题

CORE IDEA · 一句话原理

轮廓有几千个点太啰嗦，用一条"松紧带"把它勒紧，几千个点就变成几个顶点。

打个比方：就像你要跟朋友描述一个形状 —— 说"这里有 3847 个像素点"没人听得懂，说"这是个三角形，三个角大概在这儿"一下就懂了。approxPolyDP 干的就是这个"精简描述"的工作。

为什么机器人需要顶点坐标？举个具体的例子：

任务需要什么拿不到会怎样
抓取三角形积木三个角在哪，才能定抓取角度只能知道"大概在画面中间"，抓歪
沿地上的线巡线线的中心在哪，偏左还是偏右只能知道"有线"，不知道该往哪拐
判断工件是不是正方形四个顶点的坐标，量边长和角度判断不了，只能看面积

共同点：都需要"结构化的坐标"，而不是"一堆像素"。这个实验就是把像素变成坐标。

本实验的目标：画面里放三角形、四边形、圆形，程序各自找出来，标出顶点数、画出中心点、还在终端打印面积。

02三分钟讲懂：从一团像素到几个顶点

四步"层层瘦身"：像素 → 边界 → 凸包 → 顶点。每一步都在减少数据量。

图 5-1｜瘦身过程。注意第③步的"松紧带"：它会把凹进去的地方绷直，所以凸包永远是个凸多边形。

四步分别叫什么、干什么

函数中文干什么
threshold二值化把灰度图按一个分界线切成纯黑纯白。adaptive 模式会按局部区域自动算分界线，适合光照不均。
findContours找轮廓沿着白色区域走一圈，把边界点收集起来。RETR_EXTERNAL 表示只要最外层，不要里面的洞。
convexHull凸包把所有边界点用一根"松紧带"包起来。凹的地方会被绷直，结果永远是凸的。
approxPolyDP多边形逼近在凸包基础上，把"几乎成一条直线"的相邻点合并。参数 epsilon 决定合并的松紧程度。
🔍 epsilon 是什么？为什么它最关键epsilon = 允许多大的偏差。想象你用直尺去量一条曲线：epsilon 小 = 尺子贴着曲线走，点很多、很准；epsilon 大 = 尺子跨得远，点很少、但形状失真。
本实验的算法是 epsilon = approx_epsilon × 轮廓周长。配置里写 0.02，意味着"允许偏差是周长的 2%"。这个比例很聪明 —— 大物体和小物体都能用同一个参数。
一句话记住：轮廓 = 沿着边走一圈，凸包 = 绷紧松紧带，approxPolyDP = 把接近直线的点合并。三个函数，一个目的：少给点数据，但别丢形状。

03先认识 4 个词

二值化 threshold

把图切成只有黑和白。这是所有传统视觉流程的第一步 —— 先分黑白，再谈形状。

凸包 hull

把一堆点用最小的凸多边形包起来。凹的地方会被绷直，所以结果一定没有凹角。

epsilon

逼近的"容差"。越大越简化（顶点少），越小越贴合（顶点多）。

质心 centroid

形状的面积中心（不一定是顶点之一）。巡线、抓取都要用它 —— 它是"目标在哪"的最佳答案。

invert 这个参数是干什么的？选读 30 秒

invert: false 表示"亮的是目标，暗的是背景"；改成 true 就是"暗的是目标，亮的是背景"。

怎么判断该用哪个？看你画面上要找的东西是深色还是浅色：白色的纸片在黑桌面上 → 用 false；黑色的胶带在白地板上 → 用 true。

配置注释里写了"板上实测暗底亮物场景用 false" —— 意思是这个实验默认按"深色桌面 + 浅色工件"调好了。如果换到白桌子上，必须改成 true，否则一个轮廓都找不到。

04它吃什么、吐什么

INPUT · 喂进去
相机画面 / 图片

有清晰形状的场景。实验里要放三角形、四边形、圆形积木或纸片。

→
OUTPUT · 吐出来
每个形状的：顶点坐标 + 顶点数 + 面积 + 质心

画面黑底 + 彩色轮廓 + 顶点标注；终端每帧打印一行 顶点数 / 面积。这些数字就是机器人做决策的输入。

# 关键配置（config/line_config.yaml）
preprocess:
  threshold_mode: adaptive    # binary | adaptive
  threshold_value: 50
  invert: false               # ← 亮物暗底用 false，暗物亮底改 true
  morph_kernel: 3

contour:
  min_area: 100               # 小于这个面积的轮廓直接丢掉（滤噪）

polygon:
  approx_epsilon: 0.02       # ← 最该调的那个数
  use_hull: true              # 先凸包再逼近

06你该看到的画面

画面 A · 正常
黑底 + 彩色多边形

每个形状被描出彩色边，顶点上标着序号，形状中心有个十字或圆点（质心）。这种"黑底彩色"模式是为了看清楚轮廓本身。

画面 B · 圆形
顶点数很多（8 以上）

圆没法用少量直线段描述，所以逼近后会剩很多顶点。程序按"顶点数 ≥ 8 就当作圆"来分类。

画面 C · 一片空白
一个轮廓都没有

先查 invert 对不对，再查 min_area 是不是太大，最后查光照是否均匀。

🔍 为什么用"顶点数"分形状？因为这是最省事的办法：3 个顶点是三角形，4 个是四边形，很多就是圆。但它很不严谨 —— 一个画歪的正方形可能被逼近成 5 个顶点。想要更准，得量边长和角度。本实验刻意用简单规则，是为了让你把注意力放在"逼近"这件事上。

07改一个参数看变化

这个实验最值得玩的就是 approx_epsilon。拖一拖，看顶点数怎么变 —— 这是理解"逼近"最快的方式。

⚡ 参数实验台 · epsilon 如何改变顶点数
0.020

三个典型 epsilon 值

epsilon顶点数适合什么
0.005很多（15+）想要精确轮廓，比如测量不规则缺陷的形状。几乎每条小起伏都保留。
0.02适中（4~8）默认值。能分出三角形 / 四边形 / 圆，是工程上的常用起点。
0.10很少（3~4）只想粗分形状类别。圆也会被压成四五边形 —— 这时候"按顶点数分类"就失效了。

调参思路：先设 0.02 看效果，如果顶点数明显偏多（一个四边形出现了 7、8 个顶点），说明噪声多或者 epsilon 太小，往上调；如果圆的顶点数掉到 4、5 个，说明 epsilon 太大，往下调。

epsilon 的本质是一个"要不要计较"的阈值。真实图像总有毛刺，epsilon 就是告诉程序"拐这么小的弯就别算了，忽略掉"。

08踩坑速查

现象原因怎么办
换成白背景后一个轮廓都没有invert 没改，还在找"亮的区域"暗底亮物用 false，亮底暗物用 true
一个四边形被标成 7 个顶点epsilon 太小，把边缘毛刺也算成拐点了把 approx_epsilon 从 0.02 调到 0.04
圆形只认成 4 个顶点epsilon 太大，圆被压成四边形了把 epsilon 调小到 0.01 左右
满屏都是小轮廓min_area 太小，把噪点也当目标了从 100 提到 300~500
目标被切成好几块光照不均，adaptive 阈值分块了换 threshold_mode: binary 并手调 threshold_value
轮廓边缘坑坑洼洼没有做形态学平滑把 morph_kernel 从 3 提到 5（但别太大，会吃掉小目标）
💡 排查口诀先看有没有轮廓，再看顶点对不对。没轮廓 = 二值化问题（invert / 阈值 / 光照）；有轮廓但顶点数不对 = epsilon 问题；轮廓碎成好几块 = 形态学/阈值模式问题。

09进阶（可选）

进阶 1 · 用面积和周长区分形状约 30 分钟

"按顶点数分类"太粗糙。更靠谱的办法是算 圆度：

圆度 = 4π × 面积 / 周长²

完美的圆，圆度 = 1。正方形约 0.785，细长条会更小。用它判断"是不是圆"比数顶点稳定得多。

代码里形状的面积和周长都已经算好了（contourArea / arcLength），加几行就能试。

进阶 2 · 从质心偏移算转向指令约 40 分钟

这是"巡线"真正需要的一步。质心的 x 坐标相对画面中心的偏移量，直接决定该往哪拐：

offset = (质心x - 画面中心x) / (画面宽/2)   # 归一化到 -1 ~ +1

角速度 = -k × offset       # 正偏移（偏右）→ 负角速度（左转）

k 是比例系数，从 0.5 开始试。这个"偏移 × 系数 → 控制量"的结构，就是最简单的比例控制器（P 控制）。

注意方向别搞反：物在右边，车要往右转才追得上 —— 但车右转的角速度是负的。第一次调都要试错几次。

进阶 3 · 为什么用凸包而不是直接用轮廓选读 50 秒

因为真实图像里，目标边缘很少是光滑的。手指挡住一点、反光、阴影，都会在轮廓上咬出一个小凹口。

如果直接对原始轮廓做逼近，这些小凹口会被当成真实的拐点保留下来，顶点数就不准了。凸包先把所有凹口"绷平"，再逼近，形状判断就稳定多了。

代价是：如果目标本身就有真实的凹角（比如一个 L 形工件），凸包会把它吃掉变成一个矩形。所以配置里留了 use_hull 开关 —— 判断凸形状时打开它，识别凹形状时必须关掉。

10随堂小测

Q1你把浅色纸片从黑桌子挪到白纸上，程序突然一个轮廓都找不到了。改哪个参数？
把 min_area 调小
把 invert 从 false 改成 true
把 approx_epsilon 调大
对。invert: false 是找"亮的区域"。白纸上纸片和背景都亮，就分不出来了。改成 true 变成找"暗的区域" —— 但纸片本身也是亮的，所以更准确的说法是：换到白纸场景后，得改成"找和背景不同的那块"，通常需要用颜色而不是灰度。
Q2一个方方正正的四边形，程序报了 7 个顶点。最该怎么调？
把 epsilon 从 0.02 调到 0.005
把 epsilon 从 0.02 调到 0.04 左右
把 min_area 调大
对。顶点多说明程序把边缘的小毛刺都当成了拐点。epsilon 是"允许多大偏差"，调大就会合并更多相邻点，顶点数下降。调小反而更糟。
Q3为什么在逼近之前要先算凸包？
因为凸包算得快，能提速
因为真实轮廓上有很多小凹口（阴影、遮挡），凸包先把它绷平，顶点数就稳定了
因为凸包能算出面积
对。凸包的作用是"消除假凹角"。但注意：如果目标本身就是凹形状（L 形、C 形），凸包会把它吃成矩形 —— 所以配置里留了 use_hull 开关。
