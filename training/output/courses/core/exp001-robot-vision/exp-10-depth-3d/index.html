深度相机：让机器知道"那东西离我多远"

前面所有实验都只知道"东西在画面的哪个位置"，但不知道"它在多远"。这个实验给机器人加上第三只眼 —— 深度相机。点一下画面上的任意像素，程序就能告诉你"这个点离你 43 厘米"，还能算出它在真实空间里的三维坐标。

01这个实验解决什么问题

CORE IDEA · 一句话原理

普通相机只给你方向（在画面哪个位置），深度相机还给你距离。有了这两样，就能算出三维坐标。

打个比方：你在房间里听到有人喊你名字。光靠耳朵，你只知道"声音从右前方向来"。如果对方同时告诉你"我离你 3 米"，你就能准确指出他在哪。深度相机就是那个会说距离的相机。

为什么机器人必须有深度？看三个真实任务：

任务只有 2D 会怎样有了深度
机械臂抓杯子知道杯子在画面中间，但不知道伸多远 —— 可能抓空，可能撞翻算出杯子的 (X, Y, Z)，直接过去
小车避障看到前面有个东西，不知道 30cm 还是 3m —— 该停还是该走？小于 50cm 就停，稳
3D 建模只能得到一张照片，没有立体信息每个像素都变成一个空间点，拼成点云
本实验的目标：双栏看到彩色图和深度图；点画面上任意一点，程序报出"距离多少米 + 三维坐标 (X, Y, Z)"。

02三分钟讲懂：怎么从一张图算出距离

核心只有一个公式，而且很好理解。先把"相机怎么把三维世界拍成二维图"想清楚，反着推就是答案。

图 8-1｜上半是"拍照"，下半是"反推"。本实验做的就是下半那个反向过程。

反投影公式，逐个字母看懂

📐 三个公式 X = (u − cx) × Z / fx
Y = (v − cy) × Z / fy
Z = 深度值 ÷ 1000（相机给的单位是毫米，换成米）
符号叫什么本实验的实际值 / 含义
u, v像素坐标你点的那一点在画面里的行列号（0~640, 0~480）
Z深度深度相机直接测出来的，不是算出来的。单位毫米 → 除以 1000 变米
fx, fy焦距（内参之一）这块相机标定出来的值：fx=608.40、fy=611.21
cx, cy主点（内参之一）光轴打在画面上的位置：cx=328.30、cy=226.46。不是正好 320/240，因为装配有误差
X, Y横 / 纵坐标算出来的结果，单位米。X 向右为正，Y 向下为正
⚠️ 关键认知：Z 不是算出来的很多人以为深度是"算"的。不是。深度相机有一路专门的红外发射+接收（或用结构光），直接测量每个点的距离。反投影公式只是把这个测量值配合像素位置，换算成三维坐标。没有深度相机的普通相机，永远算不出绝对距离。

算一遍给你看

假设你点了画面正中心偏右一点的位置 (u=400, v=240)，深度相机测到 Z = 0.5 米：

# 已知内参
fx = 608.39958    fy = 611.20714
cx = 328.30096    cy = 226.46483

# 反投影
X = (400 − 328.30) × 0.5 / 608.40 = 0.0589 米   ← 往右 5.9 厘米
Y = (240 − 226.46) × 0.5 / 611.21 = 0.0111 米   ← 往下 1.1 厘米
Z = 0.5 米                     ← 前方 50 厘米

结果：那个点在你前方 50cm、右边 5.9cm、下方 1.1cm 的位置。机械臂可以直接朝这个坐标伸过去。

一句话记住：像素告诉你"朝哪个方向看"，深度告诉你"看多远"，内参告诉你"镜头的几何长相"。三者合起来，就能从一张照片定位空间中的一点。

03先认识 4 个词

深度图 depth

一张只有距离信息的图。每个像素存的不是颜色，而是"这个点离我多少毫米"。用 16 位无符号整数（uint16）存，最大 65 米。0 表示"测不到"。

内参 intrinsics

相机的"身份参数"：焦距 fx/fy + 主点 cx/cy。每台相机出厂都不一样，必须标定才知道。

反投影

从 2D 像素 + 深度，反推出 3D 坐标的过程。就是上面那三个公式。

点云

把所有像素都反投影一遍，得到几万个三维点。用专业软件看，能看出物体的立体形状。

深度图为什么用伪彩色显示？选读 30 秒

因为深度值（0~65535）直接显示成灰度图，人眼根本看不出差别 —— 近处和稍远处都是一片黑。

所以把它映射到 JET 色表：蓝 = 近，青 → 绿 → 黄 → 红 = 越来越远。这样一眼就能看出远近关系。配置里 colormap: jet 就是干这个，也可以改成 gray 看灰度版。

注意：伪彩色只是给人看的。程序内部用的还是原始的毫米数值。

04它吃什么、吐什么

INPUT · 喂进去
HP60C 两路画面

彩色（RGB，普通相机）+ 深度（uint16 毫米）。两路从同一个 ROS2 话题来。

→
OUTPUT · 吐出来
双栏画面 + 点击处 (X,Y,Z)

左栏彩色 + 右栏伪彩深度。点一下，终端和一个信息框显示该点的距离与三维坐标。

# 关键配置（config/depth3d_config.yaml）
depth:
  scale: 0.001           # 毫米 → 米（÷1000）
  invalid_value: 0        # 0 = 测不到（平台事实）
  colormap: jet
  display_scale: 0.666    # 显示时缩到 2/3 → 点击坐标要除以它还原

cam3d:
  fx: 608.39958          # ← 内参，反投影用的
  fy: 611.20714
  cx: 328.30096
  cy: 226.46483
  width: 640
  height: 480

source:
  mode: ros              # ros | image

server:
  port: 8080
  stream_name: depth.mjpg

06你该看到的画面

画面 A · 双栏正常
左彩色 右伪彩

右栏颜色随距离连续变化（蓝→绿→黄→红）。平滑的渐变 = 深度测量正常；如果右栏大片纯色或跳变，说明有问题。

画面 B · 黑色区域
深度 = 0

这些是"测不到"的地方：玻璃、镜面、太远、太近、或者物体表面太黑吸收了红外。黑色不是"距离为 0"。

画面 C · 边缘模糊
物体轮廓处颜色渐变

这是深度相机的固有特性 —— 物体边缘处红外光会有一部分打到背景上，测出的深度是"混着的"。所以边缘的深度值不可靠。

🔍 为什么黑色区域不是"距离 0 米"？深度值 0 是一个约定，表示"这个像素没有有效测量"。如果程序把 0 当成"距离 0 米"，反投影算出来的点会全部堆在相机位置上 —— 这就是点云图里常见的"一团乱点"来源。正确处理：跳过 Z=0 的像素。

07改一个参数看变化

这个实验最值得玩的是把内参故意改错，看坐标怎么跟着错。亲眼看到"内参错了会怎样"，你才会重视标定。

⚡ 参数实验台 · 输入 u, Z，拖动 fx 看 X 怎么变
400
0.50
608

改错内参会有什么后果

改错哪个现象实际影响
fx 改大同样的像素算出更小的 X（点被拉向中间）机械臂会抓偏 —— 实际在右边，算出来在中间
cx 改大所有 X 整体往负方向偏移（系统性偏移）每个点都偏一点，看起来"都没错但就是抓不准"
cy 改错Y 坐标系统性偏移高度放不准，抓取高度差几厘米

另一个值得试的改动：display_scale。它现在是 0.666，意味着画面显示时缩到了 2/3。如果程序忘记"把点击坐标除以它还原"，你点画面上的 (400, 240) 会变成 (600, 360) —— 读到的深度就完全不对了。这是这个实验最隐蔽的坑，因为画面看起来正常，只有数值不对。

内参是"硬事实"，不是"可调参数"。改内参不会让效果变好，只会让结果整体偏移。标定数据必须和相机一一对应。

08踩坑速查

现象原因怎么办
一键都是"距离 0 米"或无效点到了深度=0 的像素（玻璃、镜面、太远）换一个实体表面点；程序应提示 invalid 而不是算成 0
读到的距离明显不对点击坐标没按 display_scale 还原窗口坐标 ÷ 0.666 才是原图坐标
右栏深度图全黑深度通道没有数据（只开出彩色路了）确认 ros2 launch ascamera hp60c.launch.py 已起且带深度路
右栏一片纯色没变化场景里没有远近层次（比如对着一面墙）放个东西在不同距离，比如一只手往前伸
物体边缘深度跳变严重深度相机固有特性（边缘混光）正常现象。做测量时避开物体边缘，取内部区域的中值
刚启动第一帧是黑的相机还在预热程序已内置 rgb.mean()<5 跳过首帧，等一秒就好
改了话题连不上话题名被 remap 了保持 /ascamera_hp60c/camera_publisher/rgb0/image，严禁 remap
💡 排查口诀先看右栏有没有层次，再看点击数值对不对。右栏没有远近变化 = 采集问题（深度路没数据）；有层次但数值不对 = 换算问题（display_scale 或内参）。

09进阶（可选）

进阶 1 · 生成一张点云图约 40 分钟

把画面里每个像素都反投影一遍，得到 30 万个三维点（640×480）。存成 .ply 或 .xyz 文件，用 MeshLab 或 CloudCompare 打开，就能转着看立体形状。

for v in range(480):
    for u in range(640):
        Z = depth[v,u] / 1000.0
        if Z == 0: continue                      # 跳过无效
        X = (u - cx) * Z / fx
        Y = (v - cy) * Z / fy
        points.append((X, Y, Z))

注意两个性能问题：① 纯 Python 双循环很慢，实际要用 NumPy 向量化；② 30 万个点里可能有大量噪点，通常要按深度范围过滤或降采样。

进阶 2 · 抠掉背景，只算桌面的高度约 30 分钟

一个很实用的技巧：深度图可以直接当"分割用"。

比如要找一个桌上的物体，先测出桌面的深度（比如 0.8m），然后把深度 < 0.78m 的像素全部取出来 —— 这些就是"比桌面高的东西"。不需要任何 AI 模型。

这个思路在工业上非常常用：如果场景固定、光照可控、物体总是比传送带高，深度阈值比任何深度学习方案都更快更可靠。

进阶 3 · 为什么深度相机测不到玻璃和镜子选读 1 分钟

HP60C 这类深度相机用的是红外结构光或 ToF：发出一束红外光，等它反射回来，用"飞了多久"或"花纹变形多少"算距离。

玻璃为什么不行？红外光直接穿过去了，没反射回来 —— 相机等不到回波，只能给 0。

镜子为什么不行？光被整片反射到别处去了，回到相机的方向是错的 —— 测出来的是一个"虚像"的距离，甚至更远。

黑色物体为什么不行？黑色吸收红外，回波太弱，信噪比不够。

所以工业上做 3D 检测时，被测物表面通常要处理：喷哑光粉、贴哑光胶带、或者改用激光三角测量。这些"物理层面的对策"，往往比调算法更有效。

10随堂小测

Q1反投影公式里的 Z 是从哪来的？
用 X 和 Y 算出来的
深度相机直接测量出来的，不是算的
从图片亮度推测的
对。这是最关键的认知。深度相机用红外/结构光直接测距，反投影只是把这个测量值配合像素位置换算成三维坐标。普通相机没有绝对距离信息，所以只能拍到 2D。
Q2深度图上显示 0 的像素，代表什么？
距离为 0 米，就在镜头前
这个像素测不到有效深度
最深的地方
对。0 是"无效"的约定值，常见于玻璃、镜面、太远、太黑。如果程序把 0 当成真距离去反投影，会算出一堆堆在相机位置的乱点 —— 点云图里那种"糊成一团"就是这么来的。
Q3显示窗口缩放到了 2/3，你在窗口里点了 (300, 150)，原图坐标是多少？
(300, 150)
约 (450, 225) —— 要除以 0.666
约 (200, 100) —— 要乘以 0.666
对。显示时缩小了，读取时就要放大还原：原坐标 = 窗口坐标 ÷ display_scale。忘记这一步的现象很隐蔽：画面看起来完全正常，只是读出的深度值不对 —— 因为它取的是另一个位置的像素。
