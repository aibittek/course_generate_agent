手指动作控制

全课程的收官实验：一只手掌，21 个关键点，MediaPipe Gesture Recognizer 的四模型级联—— 检测手在哪、摆好 21 个点、算出嵌入向量、分类 8 种手势。再用拇指-食指夹角连续控制特效强度， 把"捏合旋钮"变成真实交互。理解输入契约，是这个实验真正的分水岭。

难度 ⭐⭐ · 4 学时 四模型级联 8 类手势 + 8 类 canned gesture 58 项单测 :8084/hand.mjpg

01问题引入：比一个"OK"，灯就该换色

智能家居 demo 里最常见的桥段：主人对着摄像头比个手势，灯光切换、窗帘开合。 听起来简单，但拆开看，摄像头不知道"这是 OK"——它只有一张像素图。 从像素到"语义手势"，中间隔着一整条推理流水线，而且这条流水线上有四个模型排队干活。

本实验沿用官方 Gesture Recognizer 的级联结构，做两件事：

  • 离散手势：8 类 canned gesture（握拳、五指张开、点赞、比心、OK……）识别
  • 连续控制：拇指与食指的夹角 → 0~255 → 5 档特效强度（颜色/阈值/模糊/色相/增强）

你会遇到本课程最隐蔽的一类坑：模型吃得下什么格式的输入，是契约，不是常识。 一格归一化搞错，模型不报错、不崩溃，只是安静地给你垃圾结果。

先立规矩 特效循环按键 'f' 需要 --display 打开本地窗口并保持窗口焦点—— 遥控 MJPEG 流时键盘事件打不进去，这不是 bug。

02原理通俗讲解：四级流水线，每人只拧一颗螺丝

把整条流水线想成快递分拣线。每个工位只干一件事，干完扔给下一工位： 先找到包裹在哪（不管内容）、再把包裹拆开摆平、然后给内容称重拍照、最后由鉴定师判类别。 任何一工位拿到的包裹摆放姿势不对，最后的鉴定结论就是错的——而且没人会报错。

1hand_detector：192×192 输入，框出手在哪（blazeface 风格：2016 个锚框 + NMS IoU 0.3，特写时 union_bbox 合并多框）
2hand_landmarks_detector：224×224 输入，框内摆正（detection2roi 旋转方形 ROI，dscale=2.6、θ=π/2，再用逆仿射把结果映回原图）→ 输出 21 个关键点
3gesture_embedder：还是 224×224，但输入归一化坐标（x、y、z 每个都除以 224）→ 输出 128 维嵌入向量
4canned_gesture_classifier：128 维向量 → 8 类手势（float 输入，无 mean/std 标准化）

生活类比：三个"翻译腔"错了会怎样

契约 ①
检测与关键点：float32 [0,1]

uint8 原图直接塞进去，模型按"值域 255 倍"的输入理解，输出的坐标、presence 全部离谱。 指纹现象：presence 掉到 1e-9 量级，检测数量变成 0。EXP-09/10 的老坑在这里同样成立。

契约 ②
embedder：x/y/z 全部 ÷224

最容易漏的是 z——它不跟着放大，很多人只归一化 x、y。z 漏归一会让嵌入向量范数飙到 ~10.5（正常约 3.3）， 分类器看到陌生分布，所有手势统统判成 None，连报错都没有。

契约 ③
分类头：float，无 mean/std

前几级都做了归一化，你自然想"这个应该也要"——错了。它就是要原始浮点。 归一化习惯不能跨模型照搬，每个模型的预处理属于它自己的文档。

检测-跟踪状态机
稳帧的窍门

上一帧 presence ≥ 0.5 就跳过 palm 检测，直接用上帧 21 点生成 ROI（跟踪模式）； 一旦丢失立即回退全图重检。省算力，也让关键点不闪烁。

夹角连续量
angle(4,0,8)

拇指尖(4)、手腕(0)、食指尖(8) 三点夹角，余弦定理算出 [0°,70°] 映射到 [0,255]。 捏合=拧旋钮，比离散分类更细腻的交互。

计数 fingersUp
经典的粗判

四指看 tip.y < pip.y（指尖高过第二关节），拇指看两侧夹角 >150°。 8 类手势之外你还可以用"伸了几根手指"做简易命令。

为什么是 8 类"罐头"手势 canned = 罐头/预制。这 8 类（None / Closed_Fist / Open_Palm / Pointing_Up / Thumb_Down / Thumb_Up / Victory / ILoveYou）是官方模型预置的类别，开箱即用；想加自定义手势，要在 128 维嵌入空间上另接 KNN—— 嵌入把"手势长什么样"变成了可比较的数，这就是级联第 3 级存在的意义。

03关联知识点

仿射 ROI 对齐
把歪斜的 ROI 摆正再推理

手掌可能旋转出任意角度，detection2roi 算出旋转方形 ROI，warpAffine 摆正后模型只需学"端正的手"； 推理完再用逆矩阵映回原图。与 EXP-09/10 同源，三个实验共用这一套几何肌肉记忆。

NMS 与多框合并
一张图几只手都得留住

blazeface 风格 2016 锚框 + NMS(IoU 0.3)。手占满画面时多个框共同框住整只手， union_bbox 取并集避免"多框各管半只手"的错位。

嵌入向量（Embedding）
把"像不像"变成距离

21 个点 → 128 维数。同类手势的向量彼此靠近，分类器只做最近邻式判决； 自定义手势也能基于同一空间扩展，无需重训主干。

fp16 量化推理
四个模型全部 fp16

NPU 上半精度是速度与精度的平衡点。也正因为 fp16 数值范围特性，归一化错误造成的分布偏移 会被放大得更彻底——契约错误的后果更"干净利落"地全错。

签名与验证
convert 两个开关

与 exp-09/10 一致：--check 打印各模型输入输出形状确认契约； 确认无误再 --all --dtype fp16 批量转 RKNN。先看签名再转换，顺序不能反。

连续 vs 离散交互
两种控制范式

8 类手势是开关型（选哪个命令），夹角/计数是模拟型（调多大参数）。 好的体感界面两者配合：手势定模式，夹角调大小。

上排是四模型接力，绿色光点表示张量流动；③ 号 embedder 标红警示——z 漏除以 224 会让嵌入范数从 3.3 飙到 10.5， 下游全判 None。下排是 ② 级内部的 ROI 往返：歪手进、正手算、21 点再带回原图——这一去一回， 靠的是同一对仿射矩阵的正与逆。

切换三个模型的输入配置，观察流水线在哪一级坏掉、以什么方式坏掉； 再拖动拇指-食指夹角，看 5 档特效强度与离散手势的配合。

🧪 四模型契约检查 + 捏合夹角 → 特效强度
初始化完成，调整输入契约观察流水线…

三个必看场景：

  • 只把 ① 改成 uint8：presence 指纹数量级骤降，检测框直接消失——EXP-09 的老朋友
  • 只把 ③ 改成"z 漏除"：嵌入范数 3.3 → ~10.5，8 类手势全部塌向 None，前面两级完全正常
  • 夹角从 0 拉到 70：映射值线性铺满 0~255，再切 5 档强度；若 'f' 窗口无焦点则提示当前档位不生效

09重点与易错点

易错点 本实验的坑几乎全是"不报错的错"。判断线索不是 traceback，而是特征指纹： presence 的数量级、嵌入向量的范数、检测框是否出现——记住这几个数，排障速度翻倍。
#坑现象原因与解法
1①② 输入契约错检测框不出现 / detections=0，静默失败必须 float32 [0,1]；uint8 直喂 presence 会掉到异常量级，先 --check 看签名
2单手多框打架一只手画出好几个框，21 点错位NMS IoU 0.3 没生效或漏了 union_bbox 特写合并；确认后处理顺序
321 点与画面对不上点画在手旁边忘了 invertAffineTransform 逆映射——摆正坐标系里算的点没映回原图
4跟踪漂移手移动后框慢慢滑走presence ≥ 0.5 才可跳过 palm 检测；置信度低时不许偷懒，必须回退全图
5③ z 漏归一化恒定输出 None，其余全部正常x、y、z 都要 ÷224；z 漏除导致嵌入范数 ~10.5（正常 ~3.3），此指纹可直接定位本坑
6'f' 键无反应特效类型不循环--display 未开、或焦点不在本地窗口（MJPEG/远程无效）；改 config 指定类型
7fingersUp 计数不准张开 5 指只数出 3拇指看两侧夹角 >150°、四指看 tip.y < pip.y；临界抖动时加迟滞
8rclpy / PYTHONPATH 报错ModuleNotFoundError 或跑了旧配置PYTHONPATH=car1_hand_control:$PYTHONPATH 保留原值；改 config 后 colcon build --symlink-install
  • 能默写四模型级联及各自输入形状，指出哪一级最容易漏 z 归一化
  • 看到"detections=0"能立刻怀疑 ①② 的 [0,1] 契约；看到"恒定 None"能立刻怀疑 ③ 的 z
  • 能解释检测-跟踪状态机两个方向的触发条件
  • 能手算 angle(4,0,8)：余弦定理 → [0°,70°] → [0,255] → 5 档
  • 58 项单测全绿，并知道其中哪些是契约负样本用例
  • 知道 'f' 键的焦点前提，远程场景有配置文件替代方案

10总结与思考

十二个实验走完，我们从"框出一个缺陷"一路走到了"捏一下手指调参数"。本实验收束了三条主线：

级联思维
四个小模型接一条线

检测、定位、嵌入、分类各司其职——大而全的端到端不是唯一解，可替换、可单独升级的流水线在工程上更常见。

契约意识
输入格式是 API 的一部分

值域、维度、归一化、坐标系，错一处不报错只给垃圾。用 --check 签名和特征指纹（范数/presence）把静默失败变成可诊断失败。

控制闭环
离散定模式 + 连续调参数

8 类手势选命令、夹角调大小、fingersUp 做兜底——与 exp-11 的规则引擎一样，最终落点都是"人的意图 → Twist/参数 → 机器动作"。

思考题

1. 级联里第 ③ 级（embedder）的输入是前一级的 输出坐标，自己却要做一次 ÷224 的归一化。为什么不能让第 ② 级直接输出"已经归一化好"的坐标，把这个契约消灭在上游？ 提示：从"模型文件的来源（官方预训练、不可改）"与"模块复用"两个角度想。

2. 捏合夹角是连续量、8 类手势是离散量。 如果要做一个"三指旋转控制云台朝向"的功能，你会怎么组合检测到的 21 个点？ 夹角、fingersUp、甚至是嵌入向量——哪一种信息最适合表达"旋转了多少度"这种连续且有方向的量？

课程到此收官：检测（CH1）、理解（CH2）、跟踪与三维（CH3）、人体感知与交互（CH4）—— 同一套 OpenCV + 深度学习 + ROS2 的工具箱，四种不同的问题。剩下的路，由你的摄像头继续走。
