01这个实验解决什么问题

CORE IDEA · 一句话原理

4 个模型接力：找手 → 找 21 个点 → 压成 128 维指纹 → 分类成 8 种手势。

打个比方：就像流水线上的四道工序。第一道找出"手在画面哪一块"，第二道在那一块里定位 21 个关节，第三道把这 21 个点压成一组数字（"这只手的特征"），第四道拿这组数字去比对"最像哪个手势"。

手势识别看起来简单，做起来难。难点在"手"这个东西：

难点为什么难
手很小在 640 画面里可能只有 100×100，而且经常在动
姿态太多手指有 20 多个自由度，能摆出无数种形状
容易混淆"比耶"和"OK"、"张开手掌"和"四指"差别很小
背景干扰桌上有别的东西、手上有戒指手环

所以把它拆成四步：每一步只解决一个小问题，四个串起来解决大问题。

本实验的目标：对着镜头比"耶"，屏幕显示 Victory；张开手掌显示 Open_Palm；还能用拇指食指的夹角控制画面特效。

02三分钟讲懂：四个模型怎么接力

图 12-1｜四个模型 + 一个状态机。状态机是"性能优化"，模型本身还是那四个。

四个模型各干什么

模型大小干什么
hand_detector.rknn约 3MB在整图里找出手的方框。输入 192×192，其实就是 BlazeFace 的思路改的
hand_landmarks_detector.rknn约 6MB在框里找出 21 个关节。输入 224×224
gesture_embedder.rknn约 450KB把 21 个点压成 128 维向量（这只手的"指纹"）
canned_gesture_classifier.rknn约 90KB拿 128 维向量去选择题：8 类里最像哪个

为什么不直接用 21 个点判断手势

理论上可以（就像 EXP-11 用几个关节判断举手）。但对 8 种手势来说，规则会变得非常复杂：

做法优点缺点
手写几何规则
（比角度、比距离）		不用额外模型、可解释8 种手势要写几十条规则；换个角度看就失效；加新手势要重写
embedding + 分类器
（本实验做法）		分类器只有 90KB；加新手势只要重新训最后那一小段；对角度变化更鲁棒多两个模型、推理链路更长

这就是"把规则交给数据"的典型场景。手势形状太复杂、太灵活，与其手写规则，不如丢给神经网络去学。但注意：前面 21 个点还是用模型找的，那部分没法用规则替代。

🔍 "Embedding" 到底是什么就是把高维信息压成一组低维数字（128 个），让"相同的东西"在这组数字上距离近，"不同的东西"距离远。

本实验里，21 个点有 63 个数（21×3），看起来压成 128 个数是"变多"了。但实际上 63 个数里有很多冗余（手指是连着的，关节位置有关联）。embedding 的作用不是减少数量，而是把它转换成"更容易分类"的表示。这 128 个数字是分类器专门"要什么就给什么"的形式。
记住这个结构：找手 → 找点 → 压成数字 → 分类。"先粗后细、层层缩小处理范围"是这个实验的主线，也是 EXP-08（人脸）和 EXP-07（跟踪）用过的同一个套路。

03先认识 4 个词

21 关键点

每只手 21 个点：1 个手腕 + 5 个指根 + 15 个指节（每指 3 个）。编号固定，第 4 号永远是大拇指尖。

Embedding

把输入转换成一个"特征向量"，让相似的东西在向量空间里靠近。常用于检索、分类、比对。

Softmax

把一堆分数变成"加起来等于 1 的概率"。输出 Victory 0.94 / Open_Palm 0.03 / ... 就是这么来的。

presence

"这只手还在框里吗"的置信度。低于阈值就认为丢了，状态机会回退到全图重新找。

8 种手势分别是哪些？选读 30 秒

MediaPipe 的手势分类器支持这几类：

名称什么样
Open_Palm五指张开
Closed_Fist握拳
Pointing_Up食指指上
Thumb_Up点赞
Thumb_Down倒赞
Victory比"耶"
ILoveYou伸出拇指、食指、小指
None都不像（兜底）

注意 None 这个类 —— 它是很重要的设计。如果没有它，模型遇到不认识的手势也会硬选一个最接近的，那就会误判。有了 None，它可以坦率地说"这个我不认识"。

04它吃什么、吐什么

INPUT · 喂进去
有手的画面

4 个模型文件都在 models/。max_hands: 2 表示最多同时处理两只手。

→
OUTPUT · 吐出来
左手特效 + 右手骨架 + 状态栏

左栏：加了特效的画面 + FPS。右栏：黑底手骨架 + 手势名 + 一个竖条仪表。状态栏：FPS / Hands / Fingers / 当前特效。

# 关键配置（config/hand_control_config.yaml）
model:
  detector_model: models/hand_detector.rknn
  landmark_model: models/hand_landmarks_detector.rknn
  embedder_model: models/gesture_embedder.rknn
  classifier_model: models/canned_gesture_classifier.rknn
  max_hands: 2                     # 最多几只手
  min_detection_confidence: 0.5
  min_tracking_confidence: 0.5

server:
  port: 8084                        # 本实验用 8084
  stream_name: hand.mjpg

# 按 'f' 键可以循环切换 5 种画面特效
⚠️ 四个模型的输入格式各不相同这是本实验最容易踩的坑：
· ①手掌检测 ②21点：float32 RGB，[0,1]（要 /255）
· ③embedder：输入是归一化张量（x/y/z 全部除以 224）
· ④分类器：float，不做归一化

四个模型四种格式，改错一个整条链路就废了。好在代码里已经封装好了 —— 你只要别手动改预处理就行。

    依次试这 8 种手势，看识别对不对：

    ✋ 张开手掌 → Open_Palm ✊ 握拳 → Closed_Fist ☝️ 食指指上 → Pointing_Up 👍 点赞 → Thumb_Up 👎 倒赞 → Thumb_Down ✌️ 比耶 → Victory 🤟 爱你 → ILoveYou 🙃 其他 → None
  3. 用手指夹角控制特效（最有意思的一步）约 6 分钟

    这个功能不需要手势分类 —— 它只算拇指尖和食指尖的夹角，然后把这个角度映射成一个数值，用来控制特效强度。

    # 拇指尖 = 第 4 号点，食指尖 = 第 8 号点
# 用这两个点和指根构成向量，算夹角（余弦定理）
角度 = arccos( (a·b) / (|a|×|b|) )

# 映射成 0~255 的控制量
值 = 255 × (角度 / 最大角度)

    操作：张开手掌，然后慢慢把拇指和食指捏到一起。看右栏那个竖条仪表从 255 掉到 0。

    拇指食指张开 → 仪表 255（满格） 慢慢捏合 → 仪表 逐渐下降 捏在一起 → 仪表 0

    这是本实验最"物理"的一段：不是让模型判断"这是什么手势"，而是用几何公式算出"这两根手指夹角多少度"。规则和模型各管一段，配合起来用。

三步跑完，你走完了一条 4 模型级联的完整链路。这是整门课里最长的流水线，也是把所有知识点串起来的一次总复习。

画面 C · 状态栏

例如 FPS: 11 Hands: 1 Fingers: 2 [原始]。Fingers 是伸出的手指数，和手势分类是两套独立逻辑。

🔍 为什么"手指数"要单独算因为"比耶"这个手势的名字是模型给的，但"伸出了 2 根手指"这个信息模型不直接输出。程序是用 21 个点的几何关系算出来的（指尖离手腕更远 = 伸出了）。

这种"模型给语义 + 几何算细节"的组合很常见：模型擅长判断"是什么"，几何擅长算"多少"。

07改一个参数看变化

这个实验最值得动的是跟踪状态机的阈值。它直接决定了"帧率"和"稳定性"的取舍。

nano config/hand_control_config.yaml
model:
  max_hands: 2                     # 改 1 看看
  min_detection_confidence: 0.5     # 手掌检测门限
  min_tracking_confidence: 0.5      # 21 点 presence 门限 ← 关键
⚡ 参数实验台 · presence 阈值与状态机行为
0.50

阈值高低的取舍

min_tracking_confidence行为结果
0.2（低）很容易认为"手还在"，几乎不重新全图找帧率高，但手移出框后模型还在硬猜 —— 会乱标
0.5平衡默认值。手正常移动时稳定，移出画面时能及时回退
0.8（高）经常认为"手丢了"，频繁全图找帧率降，但跟踪位置更准确（不会漂移）

另一个值得试的改动：max_hands 从 2 改成 1。只处理一只手，帧率会明显上升 —— 因为每多一只手，就要多跑一遍 ②③④ 三个模型。这就是"模型数量 × 每帧推理次数"的成本关系。

这个阈值控制的是"多信任上一帧"。信任度高 → 快但可能跑偏；信任度低 → 慢但准。和 EXP-07 的 max_age 是同一类取舍。

现象原因怎么办
找不到手势名，一直是 None手势不在 8 类里，或者手离镜头太远靠近镜头；对照第 03 节那 8 种手势试
手骨架在画面里但没手势名embedder 或 classifier 的输入格式错了这两个模型的归一化方式和前两个不同，别手动改预处理

按 f 没反应没有本地窗口（--display）按键只在本地窗口有效；MJPEG 推流看不了按键
浏览器打不开 :8080/hand.mjpg端口记错本实验是 8084，流名 hand.mjpg
💡 排查口诀看右栏：有没有骨架？有没有手势名？
没骨架 → ①② 出问题（找手 / 找点）；
有骨架没名字 → ③④ 出问题（embedding / 分类）；
有名字但不对 → 手势本身不在 8 类里，或角度太偏。
四段链路，一段一段往下切，定位很快。

09进阶（可选）

进阶 1 · 用手指数字做一个"计数开关"约 30 分钟

状态栏里的 Fingers 是程序算出来的伸手指数。用它做一个简单的交互：

if Fingers == 5 and 稳定 10 帧:
    开灯 / 启动 / 触发某个动作
if Fingers == 0 and 稳定 10 帧:
    关灯 / 停止

注意"稳定 10 帧"这个条件 —— 不加的话，手一抖就反复触发。这和 EXP-11 的去抖是同一个问题。

进阶 2 · 把手势映射成小车指令约 40 分钟

把 EXP-11 的控制链路搬过来，只是"输入"从身体动作换成了手势：

✋ Open_Palm   →  停止
☝️ Pointing_Up →  前进
👍 Thumb_Up    →  左转
👎 Thumb_Down  →  右转
✌️ Victory     →  原地转圈

做法：写一个字典把手势名映射到 (linear, angular)，然后在主循环里发布。 和 EXP-11 完全一样的套路 —— 这说明控制层的代码是可以复用的，只有"感知"部分在变。

安全提醒：先在 turtlesim 上验，且一定先关掉发布开关。

进阶 3 · 想加一个新手势怎么办选读 1 分半

这正是"embedding + 分类器"这个设计的好处 —— 你只需要重训最后那个 90KB 的小分类器，前面三个模型完全不用动。

流程：

  1. 采数据：做新手势，录几百张。用现成的 ② 21 点模型提取坐标（不用重训它）。
  2. 做特征：用现成的 ③ embedder 把每组 21 点变成 128 维向量。
  3. 训分类器：拿"128 维向量 → 手势标签"做一个小分类任务。几百条数据、几分钟就能训完。
  4. 转换部署：把新分类器转成 RKNN，替换掉 canned_gesture_classifier.rknn。

对比一下：如果是手写几何规则，加一个手势要重新设计角度阈值、要处理各种角度下的情况；如果是一个大端到端模型，要重训几个 GB 的模型。这种"分层设计"让改动成本降到最低。

这就是工程上说的"把易变的部分隔离出来"。这个原则比任何算法都更通用 —— 你在 EXP-05 的映射表里也见过一次。

10随堂小测

Q1为什么是 4 个模型接力，而不是训练一个"端到端"的大模型直接输出手势？
因为端到端模型不存在
因为分层设计让每步只解决一个小问题，改一处不影响其他；加新手势只要重训最后那个 90KB 的小分类器
因为 4 个模型加起来更小
对。4 个模型加起来约 10MB，而一个端到端模型要想同时"找手 + 定位 + 分类"，通常大得多也慢得多。更重要的是可维护性：加手势、换背景、调精度，每次只动一小块。
Q2状态机里的"跳过手掌检测"是干什么的？
为了省内存
上一帧已经知道手在哪，就用 21 点预测位置，省掉一次全图检测来提速
为了支持更多手势
对。手在连续帧之间不会瞬移，所以可以用上一帧的位置估算这一帧。省掉一次推理，帧率就上来了。代价是：一旦手真的丢了，得靠 presence 掉下阈值才能发现并回退 —— 所以要设好这个阈值。
Q3右栏画出了手骨架，但手势名一直是 None。问题出在哪一段？
① 手掌检测
② 21 点关键点
③ embedding 或 ④ 分类器 —— 前两段已经成功了
对。能画出骨架说明 ①② 都成功了（找到手、找到点）。问题在后半段：要么 128 维向量算得不对（输入格式），要么分类器认不出这个手势。按链路分段排查是最快的定位方法。
