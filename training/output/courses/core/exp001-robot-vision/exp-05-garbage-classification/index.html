EXP-05 · 第 2 阶段 · 目标检测与分类 · 设计性 · 4 学时

垃圾分类：20 个小类怎么变成 4 个大桶

上一个实验学会了"圈框"，这次要更进一步：模型认出了"矿泉水瓶"，但垃圾桶只分 4 种颜色 —— 中间这层翻译谁来做？本实验用一个 20 类的检测模型加一张映射表，把细类自动归到四大类，并在浏览器里实时看它分。

难度 ⭐⭐ · 4 学时 YOLOv5 检测头20 → 4 类映射 多线程推理池

01这个实验解决什么问题

CORE IDEA · 一句话原理

模型先认出细类（矿泉水瓶），再用一张映射表翻译成大类（可回收物）。

打个比方：就像超市收银员扫码，扫出来是"XX 牌 500ml 矿泉水"，但系统记账只记"饮料类"。扫码是识别，归类是查表 —— 本实验干的就是这两件事。

真实的垃圾分类机器人面临一个尴尬：

  • 视觉模型能认出的是具体物体 —— 矿泉水瓶、香蕉皮、废电池、纸巾……几十上百种。
  • 但垃圾桶只有四个：可回收物、厨余垃圾、有害垃圾、其他垃圾。

如果直接训一个"四大类"的分类器，会很难训 —— 因为"可回收"这个类别里既有瓶子又有纸箱，长得毫无共同点。更聪明的做法是：让模型专心认具体物体（它擅长这个），归类交给一张表（确定性的、可维护的）。

大类（垃圾桶）英文键里面有哪些细类（举几例）
可回收物recyclable塑料瓶、易拉罐、纸箱、玻璃瓶、旧衣服
厨余垃圾kitchen_waste果皮、菜叶、剩饭、蛋壳、茶渣
有害垃圾hazardous_waste电池、灯管、药品、油漆桶
其他垃圾other_waste纸巾、烟头、陶瓷碎片、一次性餐具
本实验的核心不是"训练一个更强的模型"，而是"用一层薄薄的翻译，把模型能力接到业务需求上"。这是工程里最常见的做法。

02三分钟讲懂：认出垃圾后归到哪一类

整条流水线四步，比上个实验多了中间那张"映射表"。

图 2-1｜左边是"识别"，右边一步是"归类"。分清楚这一点，出错时就知道该查哪儿。

这四步对应的技术名词

步骤术语一句解释
② 缩放letterbox和上个实验一样：等比缩放到 640，补灰边，别拉变形。
② 检测YOLOv5 式检测头输出 3 个尺度，每格 3 个预设框，每框 25 个数字 = 4 坐标 + 1 置信度 + 20 类分数。3 × 25 = 75 就是这么来的。
③ 解码anchors 解码网络给的坐标是"相对格子中心的偏移"，要加上锚框尺寸才还原成真实框。这部分在本实验里是手写展开的，可以逐行读。
④ 映射20 → 4 类查表读 category_map.txt，把细类编号翻译成大类编号。一行一个映射，改起来极简单。
全程推理池（RKNNPool）板子有几个 NPU 核就开几个线程同时算，帧率比单线程高。配置里的 tpes 就是这个数。
记住这句：模型负责"看清是什么"，代码负责"该扔哪个桶"。别把业务规则塞进模型里，否则垃圾分类标准一改，你就得重训模型。

03先认识 4 个词

锚框 anchor

事先摆好的几个"标准大小的框"。网络只需说"在这个框基础上宽一点、高一点"。YOLOv8 取消了它，YOLOv5 还留着。

检测头 head

网络最后那几层，专门输出框和类别。3 个尺度 = 3 个检测头，分管大中小目标。

映射表

一张纯文本对照表，细类编号 → 大类编号。改它不用改代码，不用重训。

推理池 pool

同时开几个线程一起推理。板上有几个 NPU 核，就开几个线程刚好。

为什么用 3 个尺度？选读 40 秒

因为物体大小差别很大。把 640 的图分成 80×80 的细格子，适合找小东西（一个电池）；分成 20×20 的粗格子，适合找大东西（一个纸箱）；中间 40×40 管不大不小的。

三个尺度同时预测，最后合在一起做 NMS 去重。这就是为什么网络有 9 个输出张量（3 尺度 × 3 张量）。

INPUT · 喂进去

OUTPUT · 吐出来

四个大类名在配置里写死，方便对照：

model:
  category_names:
    "1": recyclable        # 可回收物
    "2": kitchen_waste     # 厨余垃圾

05三步跑起来

  1. 进目录，认识三个文本文件约 2 分钟

    这个实验比上个多几张"配置纸"，先看一眼，后面调试心里有数。

    cd ~/ros2_ws/src/xflz_eai_car1/vision/02_garbage_classification
ls models/ config/ images/
head config/labels.txt
head config/category_map.txt
    models/: garbage_yolov5_20cls.rknn ← 约 9MB config/: anchors.txt category_map.txt garbage_config.yaml labels.txt labels.txt ← 20 个细类名，一行一个 category_map.txt ← 细类 → 大类 编号对照

    要看懂的就这两个文件：模型吐出 labels 里的第几行，category_map 把它翻成几号桶。

  2. 单图推理：确认模型能认出东西约 20 秒 
    python src/app.py --image images/1.jpg --save out.jpg
    recyclable plastic_bottle 0.91 [212,148,318,402] recyclable carton_box 0.84 [96,210,188,352] ... saved -> out.jpg

    每行三段：大类 · 细类 · 分数。如果大类全是 other_waste，要么映射表没读到，要么模型认错了 —— 看第 08 节。

  3. 实时 + 多线程：看帧率怎么涨约 3 分钟

    先起相机（和上个实验一样，两个终端都要 source + DOMAIN_ID=2）：

    # 终端 1
source /opt/ros/humble/setup.bash && source ~/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=2
ros2 launch ascamera hp60c.launch.py
    # 终端 2：先单线程跑一遍
cd ~/ros2_ws/src/xflz_eai_car1/vision/02_garbage_classification
python src/app.py --ros --tpes 1
    avg_fps ≈ 6~8 ← 单线程，只用 1 个 NPU 核 http://<板子IP>:8080/garbage_cam.mjpg

    按 Ctrl+C 停掉，再开 3 线程：

    python src/app.py --ros --tpes 3
    avg_fps ≈ 15~18 ← 3 线程，多个 NPU 核一起用

    浏览器打开 http://<板子IP>:8080/garbage_cam.mjpg，把瓶子、纸盒举到镜头前看它分。

--tpes 就是"开几个线程推理"。把它从 1 改到 3 看帧率变化，你就亲手验证了"多核并行"—— 这比看任何原理图都直观。

06你该看到的画面

画面 A · 正常
标签里有两层信息

每个物体一个框，框上方写着 大类 细类 分数 三个信息。这是本实验刻意做的"双层标注"。

画面 B · 分数不高
0.3~0.5 之间摇摆

物体太小、太远、或侧着放时会这样。把物体拿近一点，分数通常上到 0.7 以上。

画面 C · 大类全不对
翻译错了

细类看着对，但大类全是"其他"。多半是映射表路径没读对 —— 看第 08 节第 1 条。

🔍 这个模型只认 20 种垃圾不是 20 个大类，是 20 个具体物体类别。你拿一支笔、一个水杯给它看，它会给出"最接近的"答案 —— 通常错。这不是 bug，是它的能力边界。

07改一个参数看变化

本实验最值得动手改的是"线程数"和"分数阈值"。前者改帧率，后者改准确度。

nano config/garbage_config.yaml
infer:
  score_thr: 0.25    ← 改这个：0.10 更容易报，0.55 更保守
  nms_thr: 0.45

pool:
  tpes: 2             ← 改这个：1 / 2 / 3，看帧率差多少
  core_mask: auto     ← 别动！这块板子上改成 round_robin 会卡死
⚡ 参数实验台 · 线程数与帧率的关系
1

为什么线程不是越多越好

因为 NPU 核数是固定的。开超过核数的线程，多余线程在抢核，上下文切换的开销反而拖慢整体 —— 和 4 个工人抢 3 台机器是一个意思。

调参的判断标准：线程数看帧率上限（不超过核数），分数阈值看你要偏"别漏"还是偏"别错"。

08踩坑速查

现象原因怎么办
大类全是 other_waste映射表没读到，或细类编号和表对不上核对 config/category_map.txt 路径，行数应 = 20
模型文件找不到配置里的模型路径是相对配置文件所在目录的路径写 ../models/xxx.rknn，不是 models/xxx.rknn
板上跑起来卡死 / 不动core_mask 改成了 round_robin保持 auto。这块板子上轮转会撞核
帧率没随线程数提升线程数超过核数，或有别的实验在抢 NPU先把 tpes 设 3；确认其他实验已退出
同一个瓶子被圈两个框NMS 阈值太高，重叠框没去掉把 nms_thr 从 0.45 降到 0.35 试
终端刷满 rknnlite 警告版本提示，不影响功能忽略。真正报 ERROR 才是问题
💡 排查口诀先查"细类对不对"，再查"大类对不对"。细类就错了 → 模型/图片/阈值的问题；细类对但大类错 → 一定是映射表的问题。分开查，一次就中。

09进阶（可选）

进阶 1 · 亲手改映射表，换个归类约 15 分钟

打开 config/category_map.txt，找到某个细类的编号，把它的目标大类改成另一个数字，重跑单图推理，看输出里大类名字变了没有。

练习很小，但它演示了一件重要的事：业务规则的改动，可以完全不碰模型和代码。这就是"配置与代码分离"。

进阶 2 · 接入机械臂做分拣联动约 1 小时

真实产线上，分类结果要变成动作。思路：检测到某个大类的框后，把框中心坐标换算成机械臂抓取位置，调用机械臂接口。

本实验只做到"识别 + 显示"。要做联动，需在主循环里加一段"结果 → 指令"的分支。注意设冷却时间，否则同一个物体每帧都触发一次抓取。

进阶 3 · 试试直接训 4 类，看看为什么不推荐约 2 小时

你可以试试直接训"可回收 / 厨余 / 有害 / 其他"四类，对比效果。大概率会发现准确率明显低于"20 类 + 映射"方案。

原因：同一个大类内部物体外观差异太大（塑料瓶和纸箱都是可回收，却毫无共性），模型很难归纳出"可回收"这个抽象概念。

这是本实验最重要的一课：有些问题不该交给模型。能用一个 if 或一张表说清的事，就别动用神经网络。

10随堂小测

Q1模型认出了 plastic_bottle，但画面标成 other_waste。最该先查什么？
重新训练模型
category_map.txt 里这个细类映射到几号
换一个更好的相机
对。细类认对了说明模型没问题，问题在"翻译"。查映射表里 plastic_bottle 对应编号是不是 1（可回收）。
Q2为什么不干脆训一个四分类模型，省掉映射表？
因为四分类模型跑得慢
因为同一大类内部物体外观差异太大，模型很难学
因为四分类模型不能用 NPU
对。"可回收"里有瓶子和纸箱，没有共同外观特征。模型擅长区分"看起来像什么"，不擅长理解"按规则归类"。确定性规则交给代码更可靠、更好维护。
Q3线程数从 1 加到 3 帧率涨了，加到 4 反而降。为什么？
代码有 bug
线程数超过 NPU 核数，多余线程在抢核
模型太大装不下
对。并行度不能超过物理单元数。核数配满刚好，多出来的线程要等核空闲，切换开销让整体更慢。
