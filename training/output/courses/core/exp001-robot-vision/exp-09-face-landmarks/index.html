人脸关键点检测

MediaPipe FaceMesh 的板端复刻：128×128 检测器先找脸，192×192 关键点模型再在每张脸上"点"出 468 个坐标——从五官轮廓到眼睑纹理，一张脸被结构化成一张可计算的网。

难度 ⭐⭐ · 4 学时 双 RKNN 级联 468 关键点 109 项单元测试 MJPEG :8081/face.mjpg

01问题引入：框出人脸，然后呢？

门禁摄像头能框出人脸，但"框住"回答不了任何业务问题：他有没有看镜头？眼睛是睁是闭？嘴角上扬了几度？——这些都需要脸内结构的坐标。人脸关键点检测就是把一张脸细化成 468 个点的网格：双眼 36 个点勾出眼睑开合，4 个嘴角点算出笑意，100 多个轮廓点拟合出脸型朝向。

本实验移植 MediaPipe FaceMesh 到实验箱 B2 的 NPU。真正的工程含量在细节里：检测模型要求 float32 RGB 归一化输入，喂错一个量纲，896 个锚框全部漂移、检测直接全军覆没——而且不抛任何异常。109 项单测就是为了把这些"静默错误"钉死。

🎯 本实验的三级流水线检测（谁是脸）→ 仿射对齐（把歪脸摆正到 192×192）→ 关键点（468 点）+ presence 置信度 → 逆映射回原图。

02原理通俗讲解：先找人，再"描脸"

把它想成证件照摄影师的工作流。第一步喊住人（检测）；第二步搬椅子转下巴，把头摆正（仿射对齐）；第三步按标准模板描点（关键点）；第四步把描好的纸举回原位置对齐（逆映射）。每一步都有自己的"契约"：

🔎 检测器
128×128 / 896 锚

face_detection_short_range.rknn（584KB）吐出 [1,896,16] 框 + [1,896,1] 分数。score 先 +100 再 sigmoid（score_clipping 防溢出），NMS IoU=0.3 去重。

📐 仿射对齐
detection2roi

从人脸框推出旋转方形 ROI（dscale 缩放、θ 旋转），warpAffine 摆成 192×192 标准照——关键点模型只认"摆正的脸"。

🕸 关键点模型
468×3 + presence

face_landmark.rknn（1.6MB）输出 conv2d_21 [1,1,1,1404] = 468 点 × (x,y,z)，外加 presence 头——detection2roi→roi_affine→warpAffine 是它的标准入口三件套。

↩ 逆映射
M⁻¹

192×192 上的归一化坐标乘回仿射矩阵的逆，落回 640×480 原图。忘了它，所有点会挤在左上角。

🗃 拓扑
FACEMESH_CONTOURS

468 点之上还有边表（478 拓扑索引 → 124 条边），画网格时索引 >437? 实为 >467 的要跳过——那是模板冗余索引，越界即崩。

🎚 core_mask
0=AUTO

推理核心选择：0 自动 / 1 CORE_0 / 2 CORE_1 / 4 CORE_2。部署时留 AUTO，排障时手动钉死核心对照帧率。

⚠️ 本课第一契约：float32 RGB [0,1] NHWC检测模型的输入是归一化的浮点。直接喂 uint8（0~255）→ 896 锚框的回归全乱 → 检测一张脸都出不来，但进程毫无报错。调试口诀：检测全废先查归一化，网格锯齿再查 warp。

06动画讲解：468 点网格的级联诞生记

三级级联：① 128×128 检测，896 个锚框依次闪烁后 NMS 收敛成蓝框 → ② 仿射对齐，歪着的橙框（-16° 摆动动画）被转正成 192×192 标准 ROI → ③ 关键点模型点亮 468 点（眼、鼻、嘴、轮廓次序脉动），按拓扑描出眉线与眼形，presence 置信度守门。最后一步（图外）是乘 M⁻¹ 落回原图。

核心代码：检测后处理四件套：

# 1) 归一化契约（最先检查的一行）
blob = img[..., ::-1].astype(np.float32) / 255.0   # BGR->RGB, 0..1
boxes, scores = rknn_det.inference(blob)

# 2) 896 锚解码 + score 修正
score = 1.0 / (1.0 + np.exp(-(raw + 100.0)))       # score_clipping_thresh=100
keep  = nms(boxes, scores, iou_thr=0.3)            # 去重

# 3) detection2roi -> warpAffine 摆正 192x192
M = roi_affine(boxes[0], dscale=1.0, rotation=0.0)
face192 = cv2.warpAffine(rgb, M, (192, 192))

# 4) 关键点推理 + 逆映射回原图
pts_norm, presence = rknn_lm.inference(face192)
if presence < 0.5: continue                        # 低质量直接丢
pts468 = (pts_norm.reshape(-1, 3)[:467] @ np.linalg.inv(M).T)

09重点与易错点

  
⚠️ 排障顺序 = 流水线顺序① 模型都加载了吗（rknnlite ModuleNotFoundError）→ ② 检测有框吗（查归一化）→ ③ 框有了但点乱跳吗（查 warp/逆映射）→ ④ 人多只出一个吗（查 NMS IoU / num_faces）。按级次排查，不要跳步。

  

    
现象根因处理

    
ModuleNotFoundError: rknnlite板端环境未激活/装错端用板端 rknn 运行时环境

    
检测框一张都没有uint8 直喂，归一化契约破float32 /255 RGB [0,1]

    
网格锯齿状错位warpAffine 参数或缺逆映射核对 roi_affine 与 M⁻¹ 成对

    
MJPEG 8081 打不开端口冲突/路径错核对 :8081/face.mjpg，他课在 8080

    
多人只画出 1 张脸NMS 过狠或 num_faces=1IoU 0.3 实测；配置改 num_faces=2

    
ros.rgb_topic 收不到帧话题被 remap / 域不一致勿 remap；配合 ROS_DOMAIN_ID 检查

    
presence 常态 <0.5 全丢弃糊图/过曝或契约瑕疵查图源；确认输入 BGR→RGB 顺序

    
拓扑索引越界崩溃用了 >467 的冗余模板索引FACEMESH_CONTOURS 画边前过滤

    
PYTHONPATH 导入一片失败覆盖而非追加必须 ...:$PYTHONPATH 尾缀

📝 思考题 1照相馆拍歪脸可以让人转正，仿射对齐却只能靠人脸框估计旋转——当人低头到 60° 时，192×192 的"摆正"还成立吗？结合 presence 头的语义，说明系统靠什么机制拒绝这类劣质帧而不输出垃圾点。

  
📝 思考题 2468 点每点带 (x, y, z)，其中 z 是相对脸平面的深度。头姿 SolvePNP 至少需要几个点、什么条件的点才能有唯一解？如果全部 468 点几乎共面，z 通道的信息量到底是多少——这对"用 z 判断鼻子高度"意味着什么？
