EXP-10 · 第 4 篇 · 设计性 · 4 学时

骨骼关键点检测

单模型一口气吐出全身 33 个关键点：从鼻尖到脚踝，每个点带 (x, y, z, visibility) 四元组。红点绿线一连，一具会动的火柴人就站在了画面里——这也是 EXP-11 体感控制的骨架来源。

难度 ⭐⭐ · 4 学时 pose_landmark_full 33 关键点 / 35 边 45 项单元测试 MJPEG :8082/pose.mjpg

01问题引入：让机器看懂"人怎么站着"

健身教练视频里，学员的动作是否标准；课堂上学生是否伏案睡觉；工厂里工人有没有弯腰钻进机械臂的运动范围——这些判断的原料都不是"有没有人"，而是人体各关节点的几何关系。33 个关键点把人变成一张可计算的骨架图：肩髋四点框出躯干朝向，肘腕三点算出关节角度。

本实验把 MediaPipe Pose 的 pose_landmark_full 模型转成 RKNN 跑在板端。与 EXP-09 的"检测 + 关键点"两级级联不同，这里是单模型直出——没有独立检测器，输入一张 256×256 字母框就直接回家 33 点。代价是输入契约更苛刻且与人脸模型截然相反：一个要 /255 浮点，这个要 mean/std 量化后的 uint8 直喂——混了就骨架乱飞。

🎯 本实验三件事① 记住 33 点索引表与 35 条连接边；② 分清 visibility 与 presence 双门限；③ 逆映射把归一化坐标落回原图，给 EXP-11 当输入。

02原理通俗讲解：一张"会自我评分"的火柴人图纸

把模型输出想象成施工队交的图纸，每个点不仅标了位置，还自带质检标签。33 个点每个都是四元组 (x, y, z, vis)：x, y 是归一化坐标（0~1），z 是相对躯干深度，vis 是"我这个点可不可靠"的自评分——被裤兜遮住的髋、被桌子挡住的踝，模型自己会打低分。渲染前 vis<0.5 的点直接跳过不画，宁可缺一条腿也不画错一条腿。

📦 单模型 256×256
免检测器

pose_landmark_full（tflite→RKNN fp16）内部自带粗定位，输出 [33, 4] + presence。比双模型少一级，延迟更稳。

📪 字母框 letterbox
灰边 114

长边缩放到 256、短边补 114 灰边（不拉伸变形）。信息全在"边框记录"里，逆映射时要先剔除 pad。

🔢 归一化契约
mean 127.5 / std 128

uint8 直接喂，预处理公式在模型转换时烘焙进去了：手动再 /127.5−1 就双重归一化——presence 从 0.998 暴跌到 0.055 的经典事故。

↩ 逆映射
px=(norm×256−pad)/scale

归一化点乘回 256、减 letterbox pad、除缩放比——三步与前处理严格互逆，坐标才不漂。

🕸 35 条边
POSE_CONNECTIONS

0 鼻、11/12 双肩、13/14 双肘、15/16 双腕、23/24 双髋、25/26 双膝、27/28 双踝……红线一连成人形。

🎚 双门限
vis & presence

presence<0.5 → 整帧返回空（没人）；单点 vis<0.5 → 只丢该点。两级语义不同，别混在一个 if 里。

⚠️ 与 EXP-09 是镜像契约人脸检测器要 float32 [0,1]；骨骼模型要 mean/std 归一化的 uint8。同一套代码里两个模型，两套预处理——共用一个前处理函数是本课最常见的串课事故。排障信号极特征化：presence 0.998 → 0.055 即为双重归一化实锤。

2
静态图片入口：

PYTHONPATH=car1_pose_landmark:$PYTHONPATH python3 -m pose_landmark_core.demo_image --config config/pose_config.yaml --save out.jpg
[pose] presence=0.99  pts=33  vis<0.5 skipped=2  -> out.jpg


    
3
核心后处理：契约 + 双门限 + 逆映射：

# 1) 前处理：字母框 + uint8 直喂（勿再 /255！）
img, scale, pad = letterbox(img, 256, pad_val=114)
out = rknn.inference(img)                # mean/std 已在模型内

# 2) 双门限：presence 管整帧，vis 管单点
lm, presence = out["landmarks"], out["presence"]
if presence < 0.5: return []             # 整帧无人，空结果

# 3) 逆映射归一化坐标回原图
kept = []
for i, (nx, ny, nz, vis) in enumerate(lm):
    if vis < 0.5: continue               # 被遮挡的点宁缺勿错
    px = int((nx * 256 - pad[0]) / scale)   # 与前处理三步严格互逆
    py = int((ny * 256 - pad[1]) / scale)
    kept.append((i, px, py, vis))


    
4
绘制：红点 r=6 + 绿线 2px：

# 35 条连接边来自 POSE_CONNECTIONS 常量表
for a, b in POSE_CONNECTIONS:
    if has(a) and has(b):
        cv2.line(out_img, pt[a], pt[b], (0, 255, 0), 2)
for i, px, py, vis in kept:
    cv2.circle(out_img, (px, py), 6, (0, 0, 255), -1)   # 红点

09重点与易错点

  
⚠️ 本课第一杀手：双重归一化presence 0.998 → 0.055 是教科书级事故指纹——模型内部已做 mean 127.5/std 128，外部禁止再 /127.5−1 或 /255。其次是 pydantic (rclpy) 导入：PYTHONPATH 只给本包不带上 :$PYTHONPATH，rclpy 直接 ImportError。

  

    
现象根因处理

    
presence 0.998 → 0.055 全帧空手动二次归一化uint8 直喂，前处理函数删掉浮点版

    
骨架整片乱飞/错位逆映射与 letterbox 不配对(norm×256−pad)/scale 三步核对

    
侧身时点位残缺vis 正常低（被挡）属预期；调低 vis 门限对照

    
画面无人却画满一团presence 门限失效presence<0.5 必须返回空

    
ImportError: rclpyPYTHONPATH 覆盖丢失末尾补 :$PYTHONPATH

    
帧率远低于预期HIK 量大/核心没考上core_mask 调试；核对 fp16 转换

    
跨实验 pytest 互相污染同名 conftest/模型路径在本工程目录内跑，勿全仓直跑

    
UVC 相机画面异常强制 YUYV（NOVATEK）用 hp60c.launch.py 统一拉流

🔬 验证方法
指纹定位
presence 数值断崖 = 归一化事故；错位 = 逆映射事故，看数就知道病根。

  

  
📝 思考题 1检测"举手投降"动作只需左腕 y 小于左肩 y——但人在画面里下蹲时，腕也会低于肩。结合布尔诺（布尔逻辑：真值表先画满"举手/下蹲/弯腰"三动作对 6 个点位的组合）说明单条不等式为什么不够，至少需要几重条件才能消歧？

  
📝 思考题 2vis=0.3 的右腕被跳过后，骨架右侧"断臂"。若下游 EXP-11 依据双腕位置判动作，断臂帧会误判成什么？提出两种比"直接丢点"更聪明的策略（提示：时间上前一帧插值、空间上镜像补全），并说明各自的失效场景。
