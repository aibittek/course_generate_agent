EXP-08 · 第 3 篇 · 设计性 · 4 学时

深度信息与 3D 检测

平面照片终于长出了"第三只眼"：HP60C 双目相机左右分屏显示 RGB 与深度伪彩，点击任意像素读出真实毫米深度，并反投影成相机坐标系下的 3D 点。

难度 ⭐⭐ · 4 学时 HP60C 双栏深度 uint16 毫米深度 24 项单元测试 :8080/depth.mjpg 纯 CPU

01问题引入：照片里的"远"是多远？

前几课里我们框人、抠人、跟踪人，但所有输出都扁平地压在像素平面上——画面里"小孩"比"远处的大人"像素更高，你能判断谁更近吗？人类靠双眼视差本能地感知远近，摄像头却只给颜色。要让机器人避障、量距、抓取，必须把 (u, v) 像素升级成 (x, y, z) 米制坐标。

HP60C 深度相机直接输出一张与 RGB 对齐的深度图：每个像素存的不再是颜色，而是"该点离镜头多少毫米"。但毛细坑不少：深度值是 uint16 毫米（不是米！）、0 表示无效、读图必须保 16 位、点击坐标还得除以显示缩放——每一步踩错，测距就差着 1000 倍或偏出半米。

🎯 本实验要建立的空间观① 深度图 = 与 RGB 同尺寸的"距离照片"；② 内参 (fx, fy, cx, cy) 是像素与米之间的桥；③ 一次点击 = 一次针孔反投影。

02原理通俗讲解：给每张照片配一张"高度成绩单"

把深度图想成给场景拍的另一张照片，只不过底片上记的不是颜色，而是距离。近处的物体"分数"低，远处的高；测不到的地方留 0（缺考）。理解它只需要三步常识：

🌧 单位是毫米
309 = 0.309 米

深度是 uint16 存毫米。工程里统一只在最后一步 z = depth × 0.001 换算——中途混用两种单位，误差是灾难性的 1000 倍。

🕳 0 是"缺考"
invalid_value=0

反光、太近、超出量程的像素深度为 0。任何统计（min/max 归一化、求均值）必须先剔除 0，否则 0 会被当成"贴在镜头上"参与计算，画面一朵黑花。

🌈 伪彩 = 人眼代理
jet colormap

深度图人眼看不出远近，先 min-max 归一化到 8bit 再 applyColorMap(jet)：蓝远红近，一眼扫出空间层次。归一化时 0 值被屏蔽。

🌉 内参是桥
fx fy cx cy

相机就是针孔模型：光线穿过"针孔"落在像素 (u, v)。反过来，已知 z 和 (u, v)，射线方向就唯一确定，除以焦距减主点即得 x, y——这就是反投影。

反投影公式配一次具体数值更好记：点击 (u, v) 读到 z=309mm，内参 cx=328.3、fx=608.4： x = (u − cx) × z / fx = (269 − 328.3) × 0.309 / 608.4 ≈ −0.039 m——一个小小的负号告诉你：这点在镜头中线左侧 3.9 厘米。y 同理（v 减 cy 除 fy），右手系、单位米。

⚠️ 显示坐标 ≠ 传感器坐标为了流畅预览画面被缩到 display_scale=0.666，双栏右屏还要先减去左屏宽度。鼠标事件拿到的是"屏幕坐标"，必须先还原回 640×480 原始坐标才能查深度图——忘了这步，点左上角读右下角的深度。

03关联知识点

数据结构
16bit 读图

必须 cv2.imread(p, IMREAD_UNCHANGED)——默认 8 位读取会把 309mm 截成 53，误差隐蔽致命。

ROS
≈25Hz 话题

深度流与 RGB 来自 ascamera 同步发布；配置 source.mode=ros / display 本地预览两用。

前置课
EXP-01/06

检测框中心 + 框内深度中值 = 目标的 3D 定位；人或物的"距离属性"随帧可得。

出口
点云

全图逐像素反投影即得点云；测距仪、越界告警、机械臂抓取位姿都是直接延伸。

  • 配置文件：config/depth3d_config.yaml（depth.scale=0.001、invalid_value=0、colormap=jet、source.mode=ros、stream_name=depth.mjpg）。
  • 工程位置：vision/08_depth_3d_detection/；24 项单测覆盖读图、归一化、反投影三段。
  • 首帧保护：rgb.mean() < 5 的黑帧会被跳过，避免初始化瞬间污染统计。

06动画讲解：一次点击的反投影之旅

点击红色圈选像素 (269, 324) → 从深度图查得 z=309mm（青色标注）→ 穿过针孔（橙点）按内参 fx/fy、cx/cy 解算方向 → 在米制相机坐标系中点亮黄点 (-0.039, 0.046, 0.309)。注意 x 为负：点击位置在光轴左侧。整条链尺子只换一次（mm→m），位置还原靠先除 display_scale 再减左栏宽。

# 必须 IMREAD_UNCHANGED，否则 309mm 被 8bit 截断成 53
depth = cv2.imread("depth_0001.png", cv2.IMREAD_UNCHANGED)
assert depth.dtype == np.uint16            # 单位：毫米！

# 0 是无效值，归一化前先屏蔽
valid = depth > 0
dmax = depth[valid].max()
norm = np.zeros_like(depth, np.float32)
norm[valid] = depth[valid] / dmax           # min-max 归一化(已在0..1)
u8   = (norm * 255).astype(np.uint8)        # applyColorMap 只吃 8bit
color = cv2.applyColorMap(u8, cv2.COLORMAP_JET)


    
3
双栏显示 + 鼠标坐标还原：

# 拼接：左 RGB | 右 伪彩，display_scale=0.666 缩放预览
canvas = np.hstack([rgb_s, depth_s])

def on_mouse(evt, x, y, flags, param):
    if evt == cv2.EVENT_LBUTTONDOWN:
        half = canvas.shape[1] // 2            # 右栏先减左栏宽
        if x >= half: x -= half
        # 屏幕坐标 -> 传感器 640x480 坐标
        u = int(x / display_scale); v = int(y / display_scale)
        z_mm = int(depth[v, u])                # 直接查 uint16
        if z_mm == 0: print("invalid (z=0)"); return
        z = z_mm * 0.001                        # 只在此处换算成米
        X = (u - CX) * z / FX; Y = (v - CY) * z / FY
        print(f"Click ({u}, {v}): z = {z_mm} mm ({z:.3f} m) "
              f"xyz=({X:.3f}, {Y:.3f}, {z:.3f}) m")

09重点与易错点

  
⚠️ 本课最大的坑：所有错误都不报错mm/m 混用、8bit 截断、坐标不还原、0 当 0mm——四类错误全都能"正常跑"，只有数值荒谬。上板前先在样例数据上对源讲义的基准输出：Click (269, 324): z = 309 mm xyz=(-0.039, 0.046, 0.309) m。

  

    
现象根因处理

    
数值差 1000 倍mm 与 m 混用全链路用 mm，仅反投影处 ×0.001

    
深度图全黑/花屏默认 8bit 读取截断 uint16IMREAD_UNCHANGED + 断言 dtype

    
点击读数错位屏幕坐标未还原（display_scale/右栏偏移）先减半宽再 ÷0.666

    
归一化后一片死黑0 值参与 max 或 min-max 被 0 拉爆valid 掩码屏蔽 invalid_value=0

    
x/y 整体平移几厘米内参 cx/cy 用了别的分辨率标定核对 640×480 出厂内参

    
偶发全黑帧进入统计初始化首帧未过滤rgb.mean()<5 跳帧（已有保护勿删）

    
远程显示卡顿全分辨率伪彩推流确认 display_scale≈0.666 生效

    
深度数据滞后/断流话题频率与缓存配置ROS 模式核对 ~25Hz 与 source.mode=ros
