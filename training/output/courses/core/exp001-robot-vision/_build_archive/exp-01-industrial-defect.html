工业表面缺陷检测：让 AI 替你盯钢板

这是整门课的第一课，也是最重要的一课。你不需要会训练模型、不需要懂 NPU —— 只要跑通三条命令，就能亲眼看到一个 6MB 的小模型在板子上以 13 FPS 圈出钢板上的裂纹和划痕。跑通之后，后面 11 个实验都是同样的套路。

难度 ⭐⭐ · 4 学时 YOLOv8RK3576 NPU int8 量化13 FPS
① 检测（本课）② 分类③ 颜色④ 二维码 ⑤ 轮廓⑥ 分割⑦ 跟踪⑧ 3D ⑨ 人脸⑩ 骨骼⑪ 体感⑫ 手势

01这个实验解决什么问题

CORE IDEA · 一句话原理

目标检测 = 让电脑在照片上画出方框，并说清框里是什么。

打个比方：就像你拿红笔在照片上圈出"这里有裂纹、这里有划痕"——AI 干的是同一件事，只不过它一秒能圈 13 张照片，而且不会眼花。

钢铁厂的质检线上，冷轧钢板飞快通过，质检员要在 0.1 秒内看清表面有没有六种缺陷：

英文名中文长什么样
crazing裂纹细密的网状浅裂
inclusion夹杂嵌进去的黑色异物块
patches斑块大片颜色不均的区域
pitted_surface麻点密密麻麻的小坑
rolled-in_scale氧化皮压入压进去的暗色氧化层
scratches划痕一条一条的直线划伤

人盯两小时就开始漏检。漏掉一块有缺陷的钢板让它流进冲压车间，可能就是一整批汽车零件报废。所以我们要让机器替人看。

本实验的完整目标：一张钢板图进去 → 屏幕上红框圈出每处缺陷、标上类别和置信度。就这样，别的都是细节。

02三分钟讲懂：AI 怎么"看"出缺陷

整个流程只有四步，从上到下走一遍就懂了。不用记公式，记住每步在干什么就行。

图 1-1｜一帧钢板照片在检测器里的完整旅程。这四步就是本实验全部的原理。

这四步分别叫什么

步骤术语为什么必须这么做
①→②letterbox 等比缩放模型只吃 640×640。如果硬拉成方的，裂纹会被拉长变形，模型就认不出了。等比缩放 + 补边才能保持形状。
②→③NPU 推理把图片交给板子上的专用芯片（NPU）算，比 CPU 快好几倍。这是它能在板子上跑到 13 FPS 的原因。
③→④NMS 去重网络很"啰嗦"，同一条划痕会圈十几个框。NMS 的规则是：留下最有信心的那个，跟它重叠太多的都删掉。
④→屏幕unletterbox 反缩放框是在 640 图上算出来的，要按原图比例换算回去，框才会落在正确位置。这一步做错，框会整体偏移。
只要记住这句：缩进去 → 算一遍 → 挑最像的 → 缩回来。整门课所有 AI 视觉实验，走的都是这个套路。

03先认识 4 个词

下面这四个词会在后面每一步反复出现。现在花一分钟认全，后面就不用反复查了。

置信度 score

模型有多确定"这里是划痕"。0.87 表示它挺有把握。通常低于 0.25 的框会直接丢掉。

IoU 重叠率

两个框重叠了多少。完全重合 = 1，完全不沾 = 0。用来判断两个框是不是指同一个东西。

NMS 去重

一串操作：按分数排序，留下最高的，把跟它 IoU 超过 0.45 的同类框全删。结果是一处缺陷一个框。

mAP50 准确率

整个模型考多少分。本实验的模型考了 0.732（满分 1.0）。这个数字是模型的"成绩单"。

还想知道 YOLOv8 这个名字是什么意思？选读 30 秒

YOLO = You Only Look Once，"只看一眼"。名字本身就是它的卖点：早期的检测方法要在同一张图上扫好几遍，YOLO 只看一遍就能同时给出所有框 —— 所以它快，能实时。

v8 是第 8 代，n 是 nano（最小号）。本实验用的 yolov8n 只有 300 多万参数，模型文件 6MB —— 小而快，刚好适合板子。同系列的 s/m/l/x 越大越准也越慢。

你不需要现在理解它的网络结构（CSPDarknet、PAN-FPN、DFL 那些）。跑通了、有手感了再回来看，会顺很多。

04它吃什么、吐什么

看清输入输出，你才知道出错该往哪儿找。

INPUT · 喂进去
一张钢板照片

可以是图片文件（images/1.jpg）、视频、USB 摄像头，或者板载 HP60C 相机的实时画面。

→
OUTPUT · 吐出来
若干条检测结果

每条 = 类别 + 置信度 + 框的四个坐标。例如：scratches 0.87 [120,64,338,102]

吐出来的东西有三种看法，实验里都会用到：

怎么看命令长什么样你得到什么
存成图片加 --save out.jpg一张带红框的图，可以直接贴进实验报告
浏览器看实时加 --ros网页上滚动的视频流（MJPEG），手机也能看
终端打印任何模式都有文字列表，能看到分数和坐标
检测器只输出文字框，不负责画图。画成红色方框是我们后面的代码干的 —— 所以看起来"框错了"，可能是画错了，也可能真是算错了。

05三步跑起来

全部在板子上执行。复制 → 粘贴 → 回车即可，三个步骤从简单到复杂。

  1. 进目录，先看模型在不在约 1 分钟

    所有实验的代码都在同一个地方，先确认你的位置对不对。

    cd ~/ros2_ws/src/xflz_eai_car1/vision/01_industrial_defect_detection
ls models/
ls images/
    defect_yolov8n_int8.rknn ← 模型（约 6MB） defect_yolov8n_int8_calib.txt 1.jpg 2.jpg 3.jpg 4.jpg ← 4 张测试用缺陷图

    看不到这两个东西？说明目录不对或文件没拷全，回到上一步检查路径。

  2. 单图推理：先跑最简单的约 10 秒

    拿一张图跑一遍，把结果存成 out.jpg。这是验证"模型能不能用"最快的方式。

    python src/app.py --model models/defect_yolov8n_int8.rknn \
       --image images/1.jpg --save out.jpg
    fps=10.0 inclusion 0.826 (181,0,279,302) inclusion 0.763 (96,430,214,641) saved -> out.jpg

    终端打印的每一行就是一处缺陷：类别 + 置信度 + 左上右下坐标。看到这类输出，模型就跑通了。

    ⚠️ 一定要带 --save out.jpg。不带的话程序会弹窗等你按键，SSH 远程连过去会卡住。

  3. 打开实时检测：让相机对着东西动起来约 2 分钟

    需要两个终端。第一个终端起相机（一直开着别关）：

    # 终端 1：启动相机驱动
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=2
ros2 launch ascamera hp60c.launch.py

    第二个终端跑检测（也要 source、也要同一个 DOMAIN_ID）：

    # 终端 2：实时缺陷检测
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=2
cd ~/ros2_ws/src/xflz_eai_car1/vision/01_industrial_defect_detection
python src/app.py --model models/defect_yolov8n_int8.rknn --ros

    然后在同一局域网的浏览器打开下面这个地址（把 IP 换成板子的 IP）：

    http://<板子IP>:8080/defect.mjpg
    frame 30 avg_fps=13.2 frame 60 avg_fps=13.0

    浏览器里应该出现滚动的画面，上面叠着红色方框。板端实测约 13 FPS —— 这个数字是这块板子的真实水平。

三条链路都通了，这个实验的主体就完成了。如果第 2 步就跑通，你已经拿到了 80% 的分数 —— 剩下的是调参和理解。

06你该看到的画面

知道"正常"长什么样，才知道"异常"是哪里出的问题。下面是三种正确的画面。

画面 A · 单图
红框紧贴缺陷

框的边界应该贴着缺陷的外沿，框上方或旁边标着类别名和分数。框明显偏出缺陷很远 → 看第 08 节第 1 条。

画面 B · 实时流
框跟着物体走

移动钢板，框应该跟着一起动。框稳定、不闪是正常的；框疯狂跳说明画面太暗或太糊。

画面 C · 乱框（正常！）
对着台面也会乱圈

这个模型只认识"钢板缺陷"。你拿它拍桌面、拍手，它会硬套出一些框 ——这不是 bug，是它没学过这些东西。

🔍 为什么拍桌面也会出框？训练时只给它看过钢板缺陷图。遇到没见过的场景，它仍然会努力"找到一个最像缺陷的区域"。这在 AI 里叫域偏移（domain gap） —— 模型只认它学过的那一类画面。想让它在别的场景好用，得用那个场景的数据重新训练。

07改一个参数看变化

不动代码，只改配置里的两个数字，你就能亲手感受"漏检"和"误检"的拉扯。这是目标检测里最重要的手感。

用编辑器打开配置文件：

nano config/defect_config.yaml
# 找到 infer 这一段，改 score_thr 的值
infer:
  imgsz: 640
  score_thr: 0.25   ← 改这个（0.25 → 0.05 或 0.60）
  iou_thr: 0.45      ← 或改这个（0.3 / 0.7）
⚡ 参数实验台 · 拖动滑块，看框怎么变
0.25

两种改法，两种后果

改成什么你会看到什么时候该这么改
score_thr: 0.05
（调低）		框变多，漏掉的弱小缺陷被抓回来了，但同时冒出一堆假框质检要求"一条都不能漏"时。宁可多报，让人工复核。
score_thr: 0.60
（调高）		框变少，留下的都很确定，但细小的划痕消失了误报太多、产线老是误停线时。宁可少报，也得报得准。
iou_thr: 0.30去重更狠，密集的缺陷可能被合成一个一般不用动。默认 0.45 是工程上试出来的甜点位。
这就是调参的本质：召回（别漏）和精确（别错）天生互相拉扯，你只能选一个偏向。产线上真正要问的是 —— 漏掉一个和误报一个，哪个代价更大？

08踩坑速查

按"我看到的症状"找对应行。左边是你遇到的，右边是该做的。

现象原因怎么办
框的位置整体偏移，形状却是对的 缩放的补边量 pad 前后没对上，反缩放时少减了 框"形对但位置漂"就查 padding —— 这是本实验第一大坑
框的位置对，但类别全错 / 分数都很低 颜色通道顺序搞反了（BGR 送给了要 RGB 的模型） 框"形都不对"就查 RGB / BGR 顺序
报 need 4dims input 模型要 4 维输入 [1,H,W,3]，你给了 3 维 用 np.newaxis 补一维
报 core mode not supported NPU 核心参数传了空值 显式写 core_mask=0（自动选核）
浏览器打不开 :8080/defect.mjpg 端口被其他实验占了，或者 IP 填成了 localhost 先关掉占用 8080 的进程；IP 要用板子的局域网地址
--ros 跑起来一直黑屏 相机没起，或者两个终端的 ROS_DOMAIN_ID 不一样 先起相机驱动；两个终端都写 export ROS_DOMAIN_ID=2
环境里找不到 rknnlite NPU 推理只能在这块板子上跑，PC 上装不了 换到板子上执行；或先用 .onnx 模型在 PC 上验证流程
画面上出现一堆"问号方块" OpenCV 画字不支持中文 窗口里的文字统一用英文 —— 这不是乱码 bug
💡 排查口诀先看模型，再看输入，最后看输出。① 模型文件在不在、多大；② 送进去的图是不是 640×640 的 RGB；③ 出来的框坐标在不在画面范围内。三步走完，九成的坑都能定位。

09进阶（可选）

基础三步跑通之后再看这里。做不完不影响成绩，做了有加分。

进阶 1 · 用 onnx 和 rknn 各评一次分，比较差多少约 30 分钟

同一个模型有两种格式：.onnx 是原始浮点版（准但慢），.rknn 是压缩后的 int8 版（快但会掉一点精度）。跑两次评测就能量化"为了快牺牲了多少准"。

python src/eval_map.py --backend onnx   # 浮点基准
python src/eval_map.py --backend rknn   # int8 实测

验收线：两者 mAP50 的差 ≤ 3%。超过 3% 说明量化做得不好。

注意：这两个分数只能在同一份权重下互相比较，用来衡量量化损失。不能拿它跟别人的模型比谁强。

进阶 2 · 把检测结果变成质检报表约 40 分钟

在 src/app.py 的主循环里，把每帧的检测结果按类别累加起来，每 100 帧打印一次统计：

scratches: 12 处
inclusion: 3 处
patches: 1 处

这就是"缺陷统计 + 质检报告生成"，是产线上真正在用的形态。思路：找到返回 detections 列表的那一行，在它后面加累加逻辑。

进阶 3 · 想自己训练一个模型（需要 PC + 显卡）约 3 小时

完整链路：准备数据集 → PC 上训练 → 导出 ONNX → 转成 RKNN → 拷到板子上跑。四个脚本都已经写好了，在 scripts/ 目录里。

三个硬性前提，缺一不可：

  • 必须用仓库里那个改过的 ultralytics（RKNN 优化 fork）。用官方版导出的 ONNX 不是 9 个输出，转到 RKNN 就解不出来。
  • 标注必须是 YOLO 归一化格式（类别 cx cy w h，全是 0~1 的小数）。写错了训练"能跑完"，但 mAP 趋近 0。
  • 量化校准图要贴近真实产线画面。用错场景的图去校准，等于拿错尺子量。

本实验的模型已经交付在 models/ 里，不重训也能完成全部实验内容。

10随堂小测

三道题，点选项就会告诉你对不对。答错不用慌，说明该回去看哪一节。

Q1你把 score_thr 从 0.25 调到 0.70，最可能发生什么？
检测框变多，能抓到更多小缺陷
检测框变少，细小划痕容易漏掉
框的位置会整体偏移
对。score_thr 是"及格线"，调高等于要求模型更有把握才报。代价是信心不足的弱小缺陷被过滤掉 —— 漏检增加。框位置偏移跟这个参数无关，那是缩放/padding 的问题。
Q2检测框的形状是对的，但整体往右下偏了几十像素。最该怀疑哪一步？
相机没对焦
模型训练不够
缩放的补边量对不上 / 反缩放时忘了减
对。"形对位漂"= 缩放链路的问题。模型输出的是 640 图上的坐标，要通过 (坐标 − pad) / scale 换算回原图。pad 算错或忘了减，就会整体系统性偏移。
Q3你把相机对着自己的手，画面上出现了一堆乱框。这说明什么？
模型坏了，要重新训练
模型只学过钢板缺陷，没见过手，属正常现象
相机驱动有问题
对。这叫域偏移。模型的能力边界就是它的训练数据 —— 只见过六类钢板缺陷，遇到别的画面就会硬套。想让它在你的场景好用，要用那个场景的数据重训。
两项反思题（写进实验报告，不算分但老师会看）约 15 分钟

反思 1　把图直接拉成 640×640（不补灰边）会有什么后果？提示：裂纹被横向压缩了，网络见过的"裂纹特征"变成了什么样？

反思 2　质检要求"一条裂纹都不能漏"，但误报也会让产线误停线。你会怎么设计一个两头兼顾的方案？提示：能不能用两档阈值 —— 高分自动判、低分转人工复核？
