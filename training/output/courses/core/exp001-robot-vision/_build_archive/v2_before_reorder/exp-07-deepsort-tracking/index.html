多目标跟踪：让"同一个人"在视频里一直是 3 号

检测每帧都在跑，但每帧都是独立的 —— 这一帧的 3 号，下一帧可能变成 7 号。跟踪要解决的就是这件事：把跨帧的框串成"轨迹"，让每个人从头到尾一个 ID。更难的是：人被挡住几秒再出现，还得认出是同一个。

难度 ⭐⭐⭐ · 4 学时 Kalman 预测匈牙利匹配 ReID 外观12~15 FPS
① 检测② 分类③ 颜色④ 二维码 ⑤ 轮廓⑥ 分割⑦ 跟踪⑧ 3D ⑨ 人脸⑩ 骨骼⑪ 体感⑫ 手势

01这个实验解决什么问题

CORE IDEA · 一句话原理

每一帧都做一道"连线题"：把这一帧的框，接到上一帧的哪条轨迹上？

打个比方：就像看球赛时盯着一个球员。球跑得再快、被别的球员挡住一下，你还是知道"那个人"是谁 —— 因为你记得他刚才在哪、也记得他长什么样。DeepSORT 用的就是这两条线索。

先看清问题：如果没有跟踪，会怎样？

帧检测结果问题
第 1 帧框 A 在人身上还行
第 2 帧框 B 在人身上这是同一个人的框吗？不知道
第 3 帧框 C 在人身上完全不知道这 3 个框是不是一个人

下游任务全都依赖"ID 稳定"：
人流统计要数"经过了几个人"，ID 一跳就多算一个人；
行为分析要判断"这个人停了多久"，ID 变了就断了；
跟人走要一直跟同一个目标，ID 变了就跟丢了。

本实验的目标：画面里三个人各有一个固定编号，来回走动、互相交叉、短暂遮挡之后，编号都不变。

02三分钟讲懂：怎么给同一个人一直贴同一个号

DeepSORT 每帧只做四件事。理解了这四件事的顺序，你就理解了这个算法。

图 7-1｜四步循环。其中第②步同时用位置和外观两条线索 —— 这是 DeepSORT 里的 "Deep"。

两条线索分别是什么

线索一 · 位置
他刚才往哪个方向走、多快

用 Kalman 滤波推算"这一帧他应该在哪个位置"。人在画面里是连续移动的，所以这个猜测通常八九不离十。

+
线索二 · 外观
他穿什么衣服、体型什么样

用 ReID 模型把每个人的框压缩成一个 512 维的"指纹向量"。同一个人的指纹很接近，不同的人差得远。

把两条线索合成一个"代价"（越小越像），再交给匈牙利算法找全局最优配对：

# 概念示意，不是真实代码
代价 = 0.2 × 位置距离  +  0.8 × 外观距离
#     ↑ 权重小，因为人会突然转弯   ↑ 权重大，因为衣服不会突然换

被挡住了怎么办

情况程序怎么处理靠的是哪个参数
人走进树后，看不见了轨迹不删除，继续用 Kalman 猜位置，编号保留max_age: 70（最多等 70 帧）
人从树后出来凭外观指纹认出是同一个，恢复原 IDReID + max_dist: 0.2
等太久没出现超过 70 帧就删掉这条轨迹max_age
刚出现的新目标先观察 3 帧，稳定才给正式编号n_init: 3
一句话记住：先猜位置（Kalman），再看长相（ReID），然后整体配对（匈牙利）。猜错位置时靠长相救回来，长相相似时靠位置区分开 —— 这就是两条线索的意义。

03先认识 4 个词

轨迹 track

一条"命的记录" —— 包含一个 ID、一串历史位置、一个外观指纹。匹配上就更新，太久没匹配上就删除。

Kalman 滤波

一套"用历史推测现在"的数学方法。不神秘：用上一帧的位置 + 速度，推这一帧的位置。

匈牙利算法

解决"怎么配对总代价最小"的经典算法。3 条轨迹配 3 个检测，有 6 种配法，它负责挑最优那一种。

ReID

Re-Identification，重识别。把一个人的图像压成一个特征向量（指纹），用来判断"是不是同一个人"。

为什么叫"级联"匹配（cascade）？选读 50 秒

因为匹配是分批做的，不是一次性做完：

先让"最近一帧刚出现过的轨迹"去匹配（它们最可靠），匹配完剩下的检测，再让"已经丢失 1 帧的"去匹配，然后是丢失 2 帧的……按"新鲜度"从新到旧一轮一轮来。

为什么这么设计？假设有两条轨迹同时竞争一个检测：一条是刚刚还在的目标，一条是丢了 30 帧的。应该优先给刚出现的那个 —— 因为丢太久的那个可能早就离开画面了。级联匹配就是这个优先级的体现。

04它吃什么、吐什么

INPUT · 喂进去
视频 / 相机流

配置里 classes: [2]，只跟踪 COCO 第 2 类（car 车）。改成 0 就是跟踪人。

→
OUTPUT · 吐出来
带 ID 的框 + 轨迹线

每个框标着 ID:3，后面拖一条尾巴（历史轨迹）。--save 还能存成标注视频。

两个模型缺一不可：

模型文件大小干什么
yolov8n.rknn约 6MB检测：每帧找出所有目标的框（COCO 80 类）
deepsort.rknn约 11MBReID：把每个框压成 512 维指纹，用来认"是不是同一个人"
 
# 关键配置（config/track_config.yaml）
detect:
  classes: [2]          # 2=car；改成 [0] 就跟踪人；[] = 全部
  score_thr: 0.25

tracker:
  mode: deepsort         # deepsort | sort（切 sort 可对照体验差异）
  max_dist: 0.2          # 外观差异门限，越小越严格
  max_age: 70            # 丢多久之内还保留编号
  n_init: 3              # 连续命中几帧才给正式编号
  min_confidence: 0.6    # 低于这个分数的检测不进跟踪

05三步跑起来

  1. 先确认两个模型都在约 1 分钟 
    cd ~/ros2_ws/src/xflz_eai_car1/vision/07_multi_object_tracking
ls -lh models/
    yolov8n.rknn 约 6MB ← 检测 deepsort.rknn 约 11MB ← 外观指纹（ReID） coco_classes.json 80 个类名

    两个缺一个就跑不起来。缺 deepsort.rknn 时程序会自动退回 sort 模式（只用位置线索），效果会明显变差 —— 这个对比正好是下面的关键练习。

  2. 实时跟踪，看 ID 稳不稳约 5 分钟

    终端 1 起相机：

    source /opt/ros/humble/setup.bash && source ~/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=2
ros2 launch ascamera hp60c.launch.py

    终端 2 跑跟踪：

    cd ~/ros2_ws/src/xflz_eai_car1/vision/07_multi_object_tracking
python src/app.py --ros
    frame 30 tracks=2 ids=[1, 2] avg_fps=14.2 frame 60 tracks=2 ids=[1, 2] avg_fps=13.8

    看 ids=[1,2] 这一段：只要人没有离开画面，这个列表就应该一直是同样的数字。如果变成 [1,2] → [3,4] → [1,2]，说明 ID 在跳，跟踪出问题了。

    浏览器：http://<板子IP>:8080/track.mjpg

  3. 做遮挡实验：这是本实验的核心约 8 分钟

    这一步必须做，因为它才对得起"DeepSORT"这个名字。

    操作：先确认配置里是 mode: deepsort。让一个目标在画面里走动，然后用手或纸板把它整个挡住 2~3 秒，再拿开。

    挡住期间：框消失，但 ID 还"记着"（等它回来） 拿开后： ID 恢复原来的数字 ✅ deepsort 正常 拿开后： ID 变成了一个新数字 ✗ 需要检查

    现在改成 mode: sort 再重复一次同样的动作：

    nano config/track_config.yaml
# tracker.mode: deepsort → sort
    sort 模式：挡住再出现 → ID 几乎必然变成新号码 ❌

    为什么？因为 sort 只有位置线索。人消失了几秒，位置完全没法推测（可能从任何方向出来），只能当新目标处理。而 deepsort 记得他的外观指纹，所以能认出来。

    这个对比实验做一次，比读十遍文字说明都管用。

三步跑完你不仅跑通了跟踪，还亲手验证了"外观特征"到底解决了什么问题。这是本实验最有价值的收获。

06你该看到的画面

画面 A · 正常
框 + ID + 轨迹尾巴

每个目标一个框，角上标 ID:3，框后拖着一条彩色细线（它走过的路径）。ID 颜色通常固定，方便追踪。

画面 B · 新目标
先"观察"再给号

刚出现的目标前几帧可能没编号（n_init: 3 在观察）。稳定 3 帧后才出现正式 ID —— 这是防误报的设计。

画面 C · ID 跳变
同一个人的号变了

说明匹配失败。常见原因：目标太快（max_iou_distance 太小）、遮挡太久（max_age 不够）、或两个人穿得太像。

🔍 为什么配置里默认跟踪"车"而不是"人"？classes: [2] 对应 COCO 的 car 类。实验室里最容易找到的移动目标是玩具车，而且在桌面上移动轨迹稳定，比人更好演示。改成 [0] 就跟踪人，你可以两种都试。

07改一个参数看变化

max_age 是最直观的一个：它就是"丢失之后还等你多久"。拖一拖，看遮挡恢复能力怎么变。

⚡ 参数实验台 · max_age 与遮挡恢复
70

三个参数各管什么

参数调大调小什么时候改
max_age
默认 70		更能抗长时间遮挡很快删掉旧轨迹遮挡多（货架后、人群里）就调大；画面干净就调小
n_init
默认 3		更不容易误报（要观察更久）新目标更快给编号画面噪声多就调大；要快速响应就调小
max_dist
默认 0.2		外观匹配更宽松（容易认错人）更严格（可能认不出同一个人）一般不动。0.2 是 DeepSORT 论文的推荐值
调参的取舍永远是同一个形状：放宽 = 更宽容但容易认错，收紧 = 更严格但容易跟丢。没有正确答案，只有适合你场景的答案。

08踩坑速查

现象原因怎么办
同一个人的 ID 一直在跳去重/匹配失败 —— 常见于目标移动太快或遮挡频繁确认 mode: deepsort 且 deepsort.rknn 存在；调大 max_age
遮挡后不恢复原 ID遮挡时间超过 max_age，轨迹被删了把 max_age 从 70 提到 100 以上
画面里明明没人却有一堆 IDn_init 太小 / min_confidence 太低n_init 设 3，min_confidence 保持 0.6
框变小 / 框在飘min_confidence 设太低，弱检测进了跟踪保持 0.6 以上；配置注释里明确说 0.3 会乱飘
车被识别成别的类别classes 只写了想要的类，但模型带 80 类确认 classes: [2] 符合你要跟的目标；跟踪人改 [0]
帧率只有个位数ReID 计算开销大（每个框都要算一次指纹）配置里 workers 设 3；减少画面里同时跟踪的目标数
没有 deepsort.rknn 也能跑程序自动回退到了 sort 模式这是容错设计，不是 bug。但效果会差 —— 补齐模型文件
💡 排查口诀先看 ID 稳不稳，再看目标有没有跟丢。ID 频繁变 = 匹配问题（外观/位置门限）；目标整个消失 = 检测问题（min_confidence 或 score_thr）。这两类问题查的方向完全不同，先分清楚。

09进阶（可选）

进阶 1 · 做一次人流统计约 40 分钟

在人流统计里，"经过"的定义是：某个 ID 的框中心，从画面左侧穿过中线到了右侧。

维护一个集合 seen = set()
每帧遍历所有 track：
    如果 track.id 不在 seen 里，且 中心x > 中线x：
        count += 1
        seen.add(track.id)

关键在于那个 seen 集合 —— 它保证同一个 ID 只被数一次。这就是"ID 稳定"为什么这么重要的最直接例子：ID 一跳，同一个人就被数成两个。

进阶 2 · 把轨迹存成 CSV 做分析约 30 分钟

每帧把 (帧号, ID, 中心x, 中心y) 写一行到文件，就得到一份轨迹数据。之后可以画轨迹热力图、算平均速度、看停留时间。

注意：这是离线分析的典型做法。板上算力紧张，一般不实时做这些 —— 先存下来，回头慢慢算。

进阶 3 · 为什么不能只用一个更强的检测器解决 ID 问题选读 1 分钟

初学者常有的困惑：如果把检测器做得特别准，是不是就不需要跟踪了？

不能。因为检测器天生是"无记忆"的 —— 它每次只看一帧，输出的是"这一帧有什么"。它没有"上一帧有什么"这个概念，所以根本无从知道"这个框是不是上次那个"。

跟踪提供的正是这种跨帧记忆。这不只是精度问题，而是能力维度的缺失 —— 就像一个人视力再好，如果没有记忆，也认不出"刚才见过的那个人"。

所以跟踪的价值不在"更准"，而在"能维持身份"。这也解释了为什么跟踪是一个独立的研究方向，而不是检测的附属功能。

10随堂小测

Q1目标被挡住 2 秒后重新出现，deepsort 能恢复原 ID，sort 不能。为什么？
因为 sort 跑得更慢
因为 deepsort 有外观指纹，能认出"还是那个人"；sort 只有位置线索，遮挡后位置无从推测
因为 sort 的模型参数少
对。遮挡期间位置完全不可知（可以从任何方向出来），所以位置线索失效。这时唯一能依靠的就是"他长什么样"—— 也就是 ReID 的外观向量。
Q2n_init: 3 是什么意思？
最多跟踪 3 个目标
连续 3 帧都检测到，才确认为正式轨迹并给编号
初始化要花 3 秒
对。这是防误报的设计。如果某一帧闪了一下误检，程序不会马上给它编号 —— 要连续稳定 3 帧才认。
Q3画面里两个人穿一模一样的黑衣服并排走，跟踪容易出错。主要该调什么？
把 max_age 调到 200
这时外观线索变弱，要更依赖位置 —— 检查 max_iou_distance 是否够用，必要时收紧外观门限
换一个更大的检测模型
对。这是 DeepSORT 的经典弱点：外观相似时指纹区分不开，只能靠位置。所以配置里 max_iou_distance 的注释特意提到"0.7 移动中易丢轨迹" —— 位置门限太紧，移动快时就匹配不上了。两条线索的权重需要按场景权衡。
