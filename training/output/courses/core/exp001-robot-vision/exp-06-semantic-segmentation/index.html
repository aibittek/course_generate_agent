EXP-06 · 第 3 阶段 · 语义分割 · 设计性 · 4 学时

语义分割：不只框住人，还要把人的每一根头发抠出来

视频会议里的虚拟背景是怎么做的？它不是给人套一个方框，而是精确到每个像素地判断"这个点是人的皮肤还是背后的书架"。这个实验就干这件事：把人从画面里抠出来，然后换成黑背景、纯色背景、或者一张自定义图片。

01这个实验解决什么问题

CORE IDEA · 一句话原理

检测给的是一个方框，分割给的是一张黑白蒙版——蒙版上每个白色像素就是"这是人"。

打个比方：检测是"用便利贴框住照片里的人"，分割是"用剪刀沿着人的轮廓剪下来"。剪下来之后，你想贴到任何背景上都行 —— 这就是虚拟背景的全部原理。

来看两者的差别有多大：

任务输出是什么数据量能干什么
目标检测（EXP-04/02）4 个数字：框的左上右下极小知道"有人在画面里，大概在哪个位置"
语义分割（本实验）一张和原图一样大的黑白图几十万个像素知道"这一根头发是人的，这一片墙不是"

为什么需要精确到像素？因为很多任务是"框"做不到的：

  • 换背景：框内框外一刀切，人的轮廓会变成方的，一眼假
  • 测量面积：想知道伤口的面积，得知道它的边界
  • 避障：机器人要知道地面上哪些区域能走，哪些是障碍
本实验的目标：相机对着自己，画面里的人被完整抠出来，背景变成黑色 / 纯色 / 一张风景图。

02三分钟讲懂：从"框住人"到"抠出人"

分割模型比检测模型多输出一样东西：一张"模板图"。理解这张模板图，你就理解了分割。

图 6-1｜关键在第②③步：模型不直接画蒙版，而是给"32 个系数"去组合"32 张通用模板图"。这个设计叫 proto-mask。

为什么不直接让模型输出蒙版？

因为直接输出一张 640×640 的蒙版，数据量太大、算不过来。proto-mask 的思路是：预先准备 32 张通用的"形状积木"，每个物体只需要说出"用哪几块、按什么比例组合"（32 个系数），就能拼出自己专属的轮廓。

这就像画人头像：给你 32 种眼睛、32 种鼻子、32 种嘴型，你只要列出编号清单，就能描述任何一张脸 —— 而不用画出整张脸。

步骤术语干什么
框 + 类别检测头和 EXP-04 完全一样：找出人的位置和分数。
32 个系数mc（mask coefficients）每个检测到的物体配一组数，描述"它长什么样"。
模板图proto32 张 160×160 的灰度图，是模型学到的"通用形状"。
拼蒙版mc @ proto系数和模板图做加权求和，得到一张低分辨率蒙版，再放大到原尺寸。
二值化mask_thr算出来的蒙版是灰度（0~255），要按阈值切成黑白（0 或 1）。
合成Alpha 合成蒙版白的地方用原图，黑的地方用背景图。
一句话记住：分割 = 检测 + 蒙版。检测告诉你"有几个人、在哪"，蒙版告诉你"每一个像素算不算人"。两件事合起来，才能把人精确地剪下来。

03先认识 4 个词

掩码 / 蒙版 mask

和原图一样大（或按比例缩放）的黑白图。白 = 保留，黑 = 换成背景。

proto 原型

32 张通用"形状积木"，模型训练时学到的公共模板。所有物体共用它们。

Alpha 合成

图像叠加的标准做法：结果 = 前景×α + 背景×(1-α)。α 是蒙版（0 或 1）。

mask_thr

二值化阈值。算出来的蒙版是灰度，超过这个值就算"是人"。设太高 → 只剩核心区域；设太低 → 边缘糊到背景上。

为什么掩码是低分辨率再放大？选读 40 秒

32 张 proto 图是 160×160，而原图是 640×640。所以拼出来的蒙版只有原图的 1/4 大小，需要放大。

放大时边缘会变成模糊的过渡带（不是硬边），这其实是件好事 —— 稍微模糊的边缘看起来更自然，不像剪刀剪的。真实的抠图软件也都会对边缘做羽化处理。

04它吃什么、吐什么

INPUT · 喂进去
相机画面

640×640 RGB。模型是 yolov8n-seg.rknn（约 7MB），配置里只保留 classes: [0] 即 person 类。

→
OUTPUT · 吐出来
抠出来的人 + 新背景

三种背景模式可选：black（黑）、solid（纯色）、image（自定义图片）。

# 关键配置（config/seg_config.yaml）
model:
  rknn: models/yolov8n-seg.rknn
  classes: [0]          # 0=person；空列表 = 全部 80 类
  mask_thr: 0.5         # 蒙版二值化阈值

background:
  mode: black           # black | solid | image
  color: [0, 0, 0]        # solid 模式的颜色（BGR 顺序！）
  image: ""

pool:
  workers: 3              # 多线程推理，板上有几个核就开几个

05三步跑起来

  1. 先用一张现成图试，别急着开相机约 1 分钟

    实验自带 bus.jpg（COCO 的经典测试图，有行人）。先跑它最容易看到效果。

    cd ~/ros2_ws/src/xflz_eai_car1/vision/06_semantic_segmentation
ls models/ images/
python src/app.py --image models/bus.jpg --save out.jpg
    models/: yolov8n-seg.rknn yolov8n-seg.onnx images/: bus.jpg 和其他测试图 seg=1 person 0.92 mask_area=18420 saved -> out.jpg

    打开 out.jpg，看背景有没有被换掉。

  2. 切换三种背景模式约 3 分钟

    改配置里的 mode，各看一次：

    nano config/seg_config.yaml
    background:
  mode: black       # ① 全黑，最容易看出抠图边缘
  mode: solid       # ② 纯色，颜色在 color 里改（BGR）
  color: [0, 200, 0]  #    BGR → 这是绿色
  mode: image       # ③ 换成一张自己的图
  image: "images/bg.jpg"

    每改一次重跑一遍单图命令。先试 black 模式，因为纯黑最容易暴露问题 —— 边缘有没有毛边、有没有把背景残片带进来，一眼就看清。

  3. 实时模式 + 三线程加速约 4 分钟

    终端 1 起相机：

    source /opt/ros/humble/setup.bash && source ~/ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=2
ros2 launch ascamera hp60c.launch.py

    终端 2 跑分割。先设 pool.workers: 1 跑一遍记下帧率，再改 3 跑一遍对比：

    cd ~/ros2_ws/src/xflz_eai_car1/vision/06_semantic_segmentation
python src/app.py --ros
    workers=1 → avg_fps ≈ 20~40 workers=3 → avg_fps ≈ 40~60 ← 多线程把三个 NPU 核都用上了 浏览器：http://<板子IP>:8080/seg.mjpg

    对着镜头挥挥手、抓抓头发 —— 看边缘跟不跟得住。头发是最难的，如果头发边缘也抠得干净，说明效果很好。

三步跑完你就做出了一台"虚拟背景机"。下一步只是换个背景素材而已，核心原理已经全部走通了。

06你该看到的画面

画面 A · black 模式
人浮在纯黑里

人形完整，边缘略有过渡（正常）。如果边缘有明显的一圈"光晕"或背景残片，说明蒙版不够准。

画面 B · solid 模式
纯色背景

适合做证件照效果。注意 color 是 BGR 顺序 —— 想要红色（255,0,0 BGR）别写成 (0,0,255)。

画面 C · image 模式
换成风景照

背景图会被缩放到画面大小。人站在风景里，效果最接近视频会议的虚拟背景。

🔍 为什么这个实验比检测慢这么多？因为要算几十万个像素的蒙版。检测只输出几个框，分割要输出一整张图 —— 数据量差了几万倍。所以这里必须用多线程推理池来抢回帧率（3 个 worker 比 1 个快近一倍）。

07改一个参数看变化

mask_thr 是这个实验里最能"看出原理"的参数。拖它，你能看到蒙版从"碎片"变成"整块"再变成"糊出去"。

⚡ 参数实验台 · mask_thr 与掩码边缘
0.50

三种典型设置

mask_thr你会看到什么时候用
0.3（低）白区变大，人的边缘往外糊，头发丝都算进来了，但背景也沾了一点想要"完整包含"目标时，比如测量伤口面积
0.5适中，边界大致落在真实边缘上默认值，大多数场景够用
0.8（高）白区收缩，只剩身体核心，头发和手指边缘丢失只要"一定有把握的区域"时，比如确认"这里确实有人"

还有一个更值得玩的方向：把 classes 从 [0] 改成空列表 []。这样模型会把画面里所有 80 类东西都分割出来 —— 你会看到桌子、椅子、杯子各自被抠出来配上不同颜色。这能让你直观感受到"分割"和"检测"的差别有多大。

mask_thr 的本质是"有多确定才算"。和检测里的 score_thr 是同一类问题 —— 只是作用对象从"整个框"变成了"每个像素"。

08踩坑速查

现象原因怎么办
人抠出来了但边缘一圈"绿边/黑边"蒙版比实际轮廓大了一点，把背景边缘带进来了把 mask_thr 从 0.5 调到 0.6~0.7
人只剩个身体，头和手没了mask_thr 太高降到 0.4 左右
换背景后画面里出现了别人的残影蒙版把背景的一部分也判定成人了调高 mask_thr；确保背景不要太杂乱
帧率只有十几只开了 1 个 worker把 pool.workers 设成 3（板上有多核 NPU）
纯色背景颜色不对color 是 BGR 顺序，不是 RGB想要红就写 [0,0,255]，绿写 [0,255,0]
背景图片不显示路径是相对项目根目录的写 images/bg.jpg，并确认文件存在、尺寸不要太怪
人没被认出来（什么都没抠）人太小、太远，或者坐着被挡住靠近镜头，露出上半身；或把 score_thr 降到 0.15
💡 排查口诀先看"有没有蒙版"，再看"蒙版准不准"。没蒙版 = 检测失败（人太小 / 阈值太高）；蒙版有但边缘脏 = mask_thr 或分辨率问题。

09进阶（可选）

进阶 1 · 背景虚化（而不是替换）约 20 分钟

比换背景更自然的效果是把背景模糊掉——人清晰，背景柔化。很多视频会议软件用的就是这个。

背景部分 = cv2.GaussianBlur(原图, (25,25), 0)
结果 = 人物区域用原图 + 背景区域用模糊图

代码改动很小：在合成那一步，把"背景源"从新图换成"模糊后的原图"就行。

进阶 2 · 把蒙版存成透明 PNG约 20 分钟

把蒙版当作 Alpha 通道存进 PNG，就得到一张"透明背景的人像"。这是设计工作流的标准产物 —— 可以直接贴进 PPT 或海报。

BGRA = 原图 + alpha 通道（蒙版）
cv2.imwrite('cutout.png', BGRA)

注意必须用 .png，JPG 不支持透明。

进阶 3 · 为什么这个任务不能只用阈值解决选读 1 分钟

学过 EXP-01 的颜色阈值后，你可能会想：能不能用颜色把人的皮肤挑出来？

不行，原因有三个：

  • 衣服颜色什么都可能有 —— 红色衣服、蓝色衣服、格子衬衫，无法用一组 HSV 范围覆盖。
  • 头发不是皮肤色 —— 黑发、棕发、金发，而且和背景的深色区域分不开。
  • 背景里也有人 —— 一张海报上印着人，颜色阈值会把它一起挑出来。

分割模型学的是"语义"而不是"颜色"：它知道"这张椅子是椅子"，哪怕椅子是木色、灰色还是红色。这就是深度学习相对传统视觉的根本优势 —— 它理解的是概念，不是数值。

代价就是：慢、要模型、要数据。能不用就不用，不得不用时才用 —— 这是本课程反复强调的判断标准。

10随堂小测

Q1检测和分割最根本的差别是什么？
分割的模型更大
检测输出一个框，分割输出每个像素的归属（一张蒙版）
分割不需要相机
对。检测说"人在这个矩形里"，分割说"这 18420 个像素是人，其余都不是"。前者数据量几个数字，后者几十万个数 —— 这是它们速度差这么多的根本原因。
Q2人抠出来了，但边缘有一圈背景的残影。该怎么调？
把 mask_thr 调到 0.3
把 mask_thr 调到 0.6~0.7，让蒙版收紧一点
把 workers 改成 1
对。残影说明蒙版比真实轮廓大了一圈。提高阈值会让"白区"收缩，边缘收紧。反过来调低会让手指、头发都算进来 —— 让边缘更"糊"。
Q3想把背景设成红色，color 应该写什么？
[255, 0, 0]
[0, 0, 255]
[0, 255, 0]
对。OpenCV 的颜色顺序是 BGR（蓝绿红），不是 RGB。红色 = 蓝 0、绿 0、红 255 → [0,0,255]。这个坑几乎每个人都会踩一次。
