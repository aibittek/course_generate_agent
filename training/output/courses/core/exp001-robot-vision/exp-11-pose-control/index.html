肢体动作体感控制

把 EXP-10 拿到的 33 个骨骼关键点变成"方向盘"：站姿举手下蹲判定五个动作， 映射成 ROS2 Twist 速度指令，驱动小车或 turtlesim 里的海龟。视觉感知 → 规则决策 → 运动执行的完整闭环， 在这里第一次真正闭合。

难度 ⭐⭐⭐ · 4 学时 actions.py 五规则 Twist 映射 55 项单测 :8083/pose_control.mjpg

01问题引入：你和小车之间，可以没有遥控器

前面十个实验，摄像头一直在"看"，但看完了就完了——缺陷框出来、骨架画出来，然后停在画面上。 你可能早就在想：能不能让它动起来？我往左挥 hand，小车就往左拐？

这正是体感游戏（Kinect、Switch 运动环）背后的逻辑：摄像头成了控制器。 把这套逻辑移植到移动小车上，你就得到了一个"人形遥控器"——而且不用买遥控器， 任何一台 RGB 摄像头 + 一个跑着 ROS2 的小车就够了。

但"看起来能做"和"真的能跑"之间隔着三道坎，本实验逐一拆掉：

  • 怎么从 33 个点得出"他在举手"？——坐标比较，比你想的简单
  • 多个动作同时满足怎么办？——优先级设计，出事了怎么办（fail-safe）
  • 判定结果怎么变成电机转动？——Twist 消息 + 话题，最后接 turtlesim 验证
先立规矩 本实验的 control.publish_cmd_vel 默认是 false——这是刻意的安全设计。 第一次跑请务必先对 turtlesim 验证，别直接上真车；上真车前确认轮子悬空或场地空旷。

02原理通俗讲解：交警在路口看懂你的手势

想象路口的交警。他不是在"计算"你的动作，而是在按一张固定的优先级清单核对： "先看这个人是不是在拦车（停车手势）；不是？再看是不是左转手势；还不是……" 清单从最紧急的条目开始，一旦命中就执行，后面的条目看都不看。

我们的 actions.py 就是这位交警的清单，输入是骨骼点坐标，输出是五个动作之一：

1归一化：坐标本来就是 0~1，但要注意分数坐标系——左手 x 在 0.3 一侧，右手在 0.7 一侧
2取特征量：双髋的 y（判断蹲没蹲）、腕和肩的 y（判断举没举手）
3按优先级顺序逐条匹配：蹲 > 双手举 > 单手举 > 默认停止
4输出 Action：FORWARD / STOP / TURN_LEFT / TURN_RIGHT / BACKWARD
5映射成 Twist：linear.x 管前后，angular.z 管转向

生活类比：膝盖弯了就是"蹲"，手腕高过肩就是"举"

所有判定都是几何比较，没有机器学习，没有模糊逻辑：

下蹲
双髋 y > 0.72

y 越大越靠画面底部。髋部都快沉到画面底了，说明人蹲下去了 → 停车。放在最高优先级，因为"蹲下"最像"我要停"。

双手举起
双腕 y < 双肩 y − 0.08

手腕比肩还高出一截（留 0.08 的容差防抖）就是举手 → 前进。人类宣布"向前冲"的本能姿势。

单手举起
左举 → 左转；右举 → 右转

只举一只，车就往那只手的方向拐。注意"左手举"对应 TURN_LEFT，坐标系的左右一致性写单测锁死。

默认兜底
全不满足 → STOP

以及关键的 fail-safe：髋部不可见（遮挡、跑出画面）→ 直接 STOP。看不懂就停车，绝不猜。

为什么必须有优先级 假设你下蹲的同时胳膊还没完全放下，"蹲"和"举手"两条规则会同时满足。 没有优先级，程序就可能随机输出前进或停车——车在你蹲下（你以为它停了）时加速，这是安全事故。 优先级把"最安全的意图"排在最前，冲突时安全动作赢。

03关联知识点

geometry_msgs/Twist
运动的通用语言

linear.x 前后速度（m/s）、angular.z 转向角速度（rad/s）。几乎所有移动机器人的控制接口都认它，turtlebot、小车底盘、仿真海龟全是。本实验只用这两个字段。

发布/订阅（Pub/Sub）
松耦合的传话机制

节点往 /cmd_vel（或 /turtle1/cmd_vel）话题上"喊"一嗓子，谁听谁收到。发布者不知道也不关心谁在听——所以换真车还是换海龟，视觉端一行不改。

fail-safe（失效安全）
看不懂 = 停

感知系统必须设计"降级行为"。骨架缺失、关键点置信度低、摄像头被挡——所有异常的稳态输出都是 STOP，而不是保持上一帧动作。

速度限幅（clamp）
给失控加保险丝

无论判定逻辑多么正确，出口统一夹在 linear ±0.3 m/s、angular ±1.0 rad/s。算法有 bug？速度也上不去，最多走慢点而不是冲出去。

ROS_DOMAIN_ID
同一片"频道"才能通话

多套 ROS 环境共存时用域 ID 隔离。本实验系列约定 export ROS_DOMAIN_ID=2，与 ascamera、视觉节点保持一致，否则话题互相看不见。

cv2.putText 与中文
OpenCV 的显示短板

putText 不带 CJK 字体，画中文会显示一串问号。所以状态栏一律英文（FORWARD / STOP / TURN_LEFT）——不是偷懒，是务实。

步骤 2 · 读懂 actions.py 的判定链（核心代码骨架）

# actions.py —— frozen dataclass 保证判定结果不可被下游偷偷改写
@dataclass(frozen=True)
class Action:
    name: str        # FORWARD / STOP / TURN_LEFT / TURN_RIGHT / BACKWARD
    linear: float    # m/s
    angular: float   # rad/s

MIN_VIS = 0.5    # 关键点可见度门槛

def classify_action(landmarks_px, w, h) -> Action:
    # 1) fail-safe：任一髋不可见直接停（遮挡/出画）
    if hip_left.vis < MIN_VIS or hip_right.vis < MIN_VIS:
        return STOP

    hl, hr = _norm(hip_left, ...), _norm(hip_right, ...)
    sl, sr = _norm(shoulder...), ...
    wl, wr = _norm(wrist_left, ...), _norm(wrist_right, ...)

    # 2) 按优先级从高到低短路匹配
    if (hl.y > 0.72) and (hr.y > 0.72):        return SQUAT_STOP      # 下蹲→停
    if wr.y < sr.y - 0.08 and wl.y < sl.y - 0.08: return FORWARD        # 双手举→前进
    if wl.y < sl.y - 0.08:                      return TURN_LEFT       # 左手举→左转
    if wr.y < sr.y - 0.08:                      return TURN_RIGHT      # 右手举→右转
    return STOP                                                  # 3) 默认停

步骤 3 · Action → Twist 映射与限幅

# 映射表（只用 linear.x 与 angular.z 两个字段）
#   前进  linear=+0.2  angular= 0.0
#   后退  linear=-0.2  angular= 0.0
#   左转  linear= 0.0  angular=+0.8
#   右转  linear= 0.0  angular=-0.8
#   停止  0 / 0（常态输出）

# 车端出口统一限幅：无论规则层怎么算，最后都夹一刀
twist.linear.x  = clamp(twist.linear.x,  -0.3, 0.3)   # m/s
twist.angular.z = clamp(twist.angular.z, -1.0, 1.0)   # rad/s

09重点与易错点

易错点 本实验的故障几乎都在"判定对了但世界不对"：优先级顺序、坐标系约定、话题名、域 ID、编译没做—— 每一条都对应源讲义里被绊过的坑。
#坑现象原因与解法
1阈值未标定换个人/换个机位就开始误判0.72 / 0.08 是通用起点，按实际摄像头高度与取景重标（人体占画面比例变了）
2优先级顺序搞反蹲下时车反而前进R1 必须是"蹲→停"。把安全动作排在最前，冲突时安全赢
3关键点遮挡仍输出人跑出画面车还在动必须过 MIN_VIS=0.5 且髋不可见→Stop；任何异常分支收敛到 STOP
4状态栏中文乱码画面上一串 ????cv2.putText 不支持 CJK，状态栏用英文 FORWARD/STOP/TURN_LEFT
5topic echo 没输出人比划了，终端安静publish_cmd_vel 默认 false 必须开 true；或话题名被改成了 /cmd_vel 而你 echo 的是 /turtle1/cmd_vel
6话题不可见ros2 topic list 里没有目标话题所有终端统一 export ROS_DOMAIN_ID=2，且 source 过 setup.bash
7海龟不动echo 有数据、海龟没反应确认 turtlesim 存活 + 发布/收听是同一话题 + linear 符号方向符合预期
8rclpy / PYTHONPATH 报错ModuleNotFoundError 或按旧配置跑PYTHONPATH=car1_pose_control:$PYTHONPATH 保留原值；改 config 后 colcon build --symlink-install

10总结与思考

恭喜走完本站最"闭环"的一个实验。你完成的链路是：

感知
EXP-10 的 33 点骨架

复用而不重造；坐标归一化、vis 置信度、letterbox 逆映射的坑在这里不会重复踩。

决策
actions.py 优先级规则

可解释、可单测、可调试的规则引擎——不是所有决策都该上模型，安全攸关的短链路规则更可靠。

执行
Twist + 限幅 + 开关

Topic 解耦让同一套感知可以开海龟、开小车、开机械臂；默认关断与出口限幅是两道保险丝。

思考题

1. 代码里"髋部关键点不可见（vis < 0.5）→ 直接 STOP"被称为整套规则最核心的一条。 请设想：如果没有这条 fail-safe，只把"不满足任何动作规则 → STOP"作为兜底， 会出什么事故？ 提示——考虑"手里还举着但髋被纸箱挡住"这个场景，其余四条规则会怎么判定。

2. 如果把优先级顺序改成"动作触发优先"（即只要举手就前进，哪怕同时在下蹲）， 交互体验会变"灵敏"，但风险在哪里？再进一步：工业机械臂的急停按钮为什么必须是硬件电路而非同一条优先级链里的最高级软件规则？
