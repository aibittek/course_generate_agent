SLAM 原理与 URDF 模型

这节课不写一行复杂代码，目标就两件事——① 用"蒙眼逛新家"的比喻听懂 SLAM 到底在干什么；② 用 URDF + RViz 把 car1 机器人"搬"到电脑屏幕上，看看它长什么样、坐标怎么连。

难度 ⭐ · 4 学时 SLAM 概念URDF / Xacro TF 树rviz2

01问题引入：没地图的"鸡生蛋"困局

你要让扫地机器人打扫房间，它得先知道自己"在房间哪一格"；可要判断自己在哪，它又得先有一张地图。定位需要地图，建图又需要知道自己的位置——这就是 SLAM 面对的经典鸡生蛋问题。再看另一个现实：

1雷达每 0.1 秒扫一圈，只看到"眼前这一环"墙壁
2车轮里程计会打滑（麦轮原地转漂移可达 45%），走着走着就"记错"自己挪了多远
3没有地图 → 无法修正漂移；不修正漂移 → 地图拼歪（墙变双影、直角变钝角）
4SLAM 把两件事绑在一起同时解：边走边画图，边画图边锁定自己的位置
💡 一句话读懂这节课不写一行复杂代码，目标就两件事——① 用"蒙眼逛新家"的比喻听懂 SLAM 到底在干什么；② 用 URDF + RViz 把 car1 机器人"搬"到电脑屏幕上，看看它长什么样、坐标怎么连。

02原理通俗讲解：SLAM 与 URDF 是什么

🏠 蒙眼逛新家把你蒙上眼睛送进一套新房：你伸手摸到"左边 2 米有墙"，就边走边在脑子里画户型图；同时因为你记得"刚才向右转了 90°、走了 3 步"，也能在图上标出自己此刻站哪——画图与定位互相喂料，这就是 SLAM（Simultaneous Localization And Mapping，同时定位与建图）。雷达 = 你的手，里程计 = 你的步感，脑子 = SLAM 算法。
感知
激光雷达 /scan

COIN-D6 每秒 10 圈、最远 12 m，把周围墙壁变成一圈"距离点"，相当于蒙眼人的手。

定位
里程计 + 扫描匹配

轮子编码器推算走了多远（会漂），再拿新一圈扫描与上一圈对齐修正——相当于步感 + 摸墙校正。

构图
占据栅格地图

世界切成 0.05 m 的小格子：100 = 有墙、0 = 空闲、-1 = 没扫到的未知区。手电筒照到哪，哪格就"亮"。

URDF（统一机器人描述格式）则是机器人的"身份证 + 骨架说明书"：用 XML 写清每个连杆（link）的外观尺寸、每个关节（joint）怎么连、能怎么动。TF 坐标树再把 base_link、雷达、机械臂这些坐标系串成一棵树——没有这棵树，雷达数据不知道该画在车体哪一侧，后面建图全是乱的。

概念生活比喻本课程对应
SLAM蒙眼逛新家：边摸边画图，边画图边记自己站哪EXP-02 用 SLAM Toolbox 真正跑起来
占据栅格户型图的方格纸：每格标"墙 / 空 / 未勘探"分辨率 0.05 m，/pgm + /yaml 成对保存
URDF机器人的乐高拼装说明书car1.urdf：底盘 + arm_link1~6 + 夹爪
joint骨头之间的关节：有的焊死、有的能转fixed / continuous / revolute 三类
TF 树全家福站位图：谁站在谁旁边、朝向哪根是 base_footprint，树断一则全乱

03关联知识点

知识点 1
SLAM 鸡生蛋

定位要地图、建图要定位，SLAM 把两者联合求解，是移动机器人自主性的起点。

知识点 2
建图三要素

感知（雷达）→ 定位（里程计+匹配）→ 构图（栅格），缺一则地图不可用。

知识点 3
link 三重属性

visual 看的、collision 撞的、inertial 算动力学的——三者可以引用不同精度的模型。

知识点 4
joint 三类型

fixed 焊死（底盘→雷达）、continuous 无界旋转（轮子）、revolute 有界旋转（机械臂关节带 limit）。

知识点 5
TF 树根节点

根是 base_footprint（贴地投影点），保证机器人"站得稳"：base_link 抬高 0.029 m。

知识点 6
Xacro 宏

URDF 没有变量和循环，Xacro 用宏参数化生成：换轮距只改一处，宏展开后仍是标准 URDF。

04实验目标

  • 能用一句生活比喻向他人讲清 SLAM = 边走边画地图 + 同时定位
  • 能指认 car1 URDF 中 底盘 / 机械臂 / 夹爪 三部分及各自 joint 类型
  • 跑通 display.launch.py 可视化三件套，在 rviz2 中看到模型并拖动关节滑条
  • 用 view_frames 生成 TF 树 PDF，说清 base_footprint → base_link → laser_link 链路
  • 解释栅格地图三值 -1 / 0 / 100 与分辨率 0.05 m 的含义

06动画讲解：激光扫描与栅格地图

左：雷达扇形束一圈圈扫过，量出到墙面的距离；右：扫到的格子被逐格"点亮"——100（墙）、0（空闲）、-1（灰色未知）。小车走到哪，亮的格子就铺到哪，这就是建图的最小过程。

动画 1-1｜左：雷达扇形逐束测距（1.4 秒循环）；右：小车驶过，空闲格逐格点亮成"户型图"（3 秒填充 + 6 秒往返）

点击按钮给两个 link 选一种 joint，看 TF 父子关系与车体行为如何变化：

TF 树拼装台 · Joint Lab

💡 判断口诀焊死不动选 fixed；转起来没完没了（轮子）选 continuous；有最大最小角度限制、带 limit 标签（机械臂 5 自由度）选 revolute。类型选错，rviz 里要么拖不动、要么转飞了。

08实操步骤：display 三件套看模型

1source 环境，启动可视化三件套：joint_state_publisher_gui（滑条）+ robot_state_publisher（TF）+ rviz2
2rviz2 左侧 Add → RobotModel，Fixed Frame 选 base_footprint，车体与机械臂出现
3拖动滑条观察 joint 旋转；再查 TF 树与连杆统计
# ① 启动模型可视化（本实验核心命令）
ros2 launch car1_description display.launch.py

# ② 生成 TF 坐标树 PDF，检查父子关系
ros2 run tf2_tools view_frames
# 产出 frames.pdf：root 为 base_footprint

# ③ 数一数 URDF 里有多少连杆
grep -c "<link" car1.urdf

# ④（接实物）确认雷达数据在发
ros2 topic hz /scan
# 约 10.0 Hz

# car1.urdf 关键片段：底座抬高 0.029 m，fixed 连接
<link name="base_footprint" />
<joint name="base_joint" type="fixed">
  <origin xyz="0 0 0.029" rpy="0 0 0" />
  <parent link="base_footprint" />
  <child link="base_link" />
</joint>
car1 三部分构成joint 类型
底盘主体base_link + 四个麦轮base_joint 为 fixed；轮子 continuous
机械臂arm_link1 ~ arm_link6revolute ×5（带 limit，5 自由度）
夹爪gripper 两指revolute / fixed 组合

09重点与易错点

⚠️ 重点看懂 TF 树 = 拿到全课程的"导航地图坐标基准"。只要是"数据该画在哪"的问题，一律先查 TF：根是不是 base_footprint、链路有没有断、雷达是不是挂在 base_link 下。
⚠️ 常见坑现象 → 解法
rviz 里没有模型画面空白 → Add 里手动加 RobotModel，并确认 Fixed Frame = base_footprint
joint 滑条拖不动joint 类型写成 fixed 或缺少 joint_state_publisher_gui → 检查 type 与 launch 三件套
找不到功能包Package 'car1_description' not found → 忘了 source 工作空间的 install/setup.bash
模型扭曲/位置错origin 的 xyz/rpy 写错单位（米/弧度）→ 对照实物量一遍
TF 树断裂view_frames 缺 laser_link → robot_state_publisher 没起，或 URDF parent/child 写反
  • display.launch.py 一键拉起 三件套，rviz2 能看到完整车体与机械臂
  • frames.pdf 中 root = base_footprint，laser_link 挂在 base_link 之下
  • 能说出 -1 / 0 / 100 与 0.05 m 分辨率的含义
  • 能指出 car1 三部分及 fixed / continuous / revolute 各用在哪里

📝 思考题 1SLAM 的"鸡生蛋"是怎么被打破的？提示从"猜测也是一组可能答案"出发——如果把"我可能在这 100 个位置"全部同时拿去和雷达扫描比对，会引出什么方法？（预告：EXP-04 粒子滤波）
📝 思考题 2栅格地图为什么用 -1 / 0 / 100 三个值而不是布尔值？-1（未知区）在导航时应该被当成"可以走"还是"不能走"？为什么扫过的区域还留着灰色，反而更安全？
