云服务器使用与真机推理

01实验目标课段 1 · 聚焦问题 · 12 min

目标 A

在 gpufree.cn 租用 L40S 实例，选用 LeRobot 镜像，通过 JupyterLab 终端完成 cd /data/lerobot/ + pip install -e . 部署。

目标 B

把 EXP-02 打包的 zip 数据集上传云端并在 L40S 上完成训练（或直接取回本地已训好的检查点）。

目标 C

用 lerobot-record --policy.path=…（不带 --teleop）在真机上推理：机器人自主完成 Put red cube into plate。

验收

推理日志出现 Loading weights from local directory、teleop: None、'policy': {…} 输入输出特征声明，且能观察到自动抓取动作；费用方面做到用完即关机。

方法论

把"传数据 → 训 → 取模型 → 推 → 评 → 关机"固化成检查单（checklist），是云上作业不烧钱、不出错的工程纪律。

02核心原理：云训练 ↔ 真机推理的闭环课段 1 收尾 + 课段 2 · 激活旧知 · 8 min

❓ 聚焦问题（课段 1）学员上云最常踩的三个坑：本地 GPU 跑一夜还没训完 5000 步，云实例忘关机被扣了一整晚费用，或者推理命令跑完机器人一动不动——明明检查点下载回来了，从臂却像没收到指令。问题出在哪？带着这三个故障听完全课，到课段 6 你会亲手让机器人自主抓起红方块。

通俗类比：这就像"厨师在中央厨房练手艺（云端 GPU），学成后回到家里做饭（本地机械臂）"。训练吃算力（几小时到几天的矩阵乘法），推理吃实时性（60 Hz 内必须吐出动作）。两者天然分离，所以工程上分工：云上练模型、本地跑部署。

训练侧：LeRobot 镜像把 CUDA、PyTorch、LeRobot 依赖预装好，一条 pip install -e . 即完成源码安装。数据靠 zip 上传，训练产出的 checkpoints/last/pretrained_model 是一个自包含目录（config + 权重 + 处理器），下载回本地即可用。

推理侧：推理复用了采集命令 lerobot-record，但去掉了 --teleop，改为加 --policy.path=/…/checkpoints/last/pretrained_model。此时每个控制周期的数据流变成：三摄像头图像 + 6 维状态 → 喂给策略 → 得到 100 步动作块 → 取前 n 步下发给关节 → 下一周期再推理。日志里 'policy': {input_features: observation.images.left/side (3,480,640), observation.state (6,), output_features action (6,)} 就是这份"策略契约"。episode_time_s=60 让机器人有一分钟自主发挥。

为什么 repo_id 加 eval_ 前缀：推理也要开启 recorder 记录表现（方便回看与评估），但这些数据不是训练原料，用 eval_ 命名和训练集彻底分开，避免后来者把"机器人的尝试"误当成"人类示范"混进训练。

↺ 激活旧知（课段 2）回忆前两个实验两条旧知：① EXP-01 采集用 lerobot-record --teleop …，动作来源是人掰主臂；② EXP-02 训练产出 checkpoints/last/pretrained_model 自包含目录（config + 权重 + processor）。推理就是把 --teleop 换成 --policy.path——动作来源从"人"变成"模型"，命令几乎没变。
云端部署JupyterLab 新终端执行 cd /data/lerobot/ + pip install -e .，安装完成后终端无报错返回提示符，即可进入训练流程（第 11 章）。
推理契约推理启动日志打印 'policy': {input_features: observation.images.left/side (3,480,640), observation.state (6,), output_features action (6,)}——这正是策略的输入输出契约：三路图像 + 6 维状态进、6 维动作出（第 12 章）。
对照记忆采集 = record + teleop；推理 = record + policy.path。同一个命令，换掉"谁来给动作"。

04实操步骤课段 5~6 · 应用新知 · 2×15 min

Step 1
打开 gpufree.cn → 控制台 → 租用实例 → 选 L40S → 搜镜像"lerobot" → 立即创建，等待启动。
Step 2

Step 3
上传本地打包的 zip 数据集（JupyterLab 上传按钮或 scp），解压到 ~/.cache/huggingface/lerobot/<名>/ 对应位置。

05关键命令随课段 5 / 6 对照使用

# ── 云实例部署（第 11 章）
cd /data/lerobot/
pip install -e .

# ── 云端训练（与第 10 章同款，数据已上传）
lerobot-train --dataset.repo_id=liming/put_cube_plate --policy.type=act --policy.repo_id=put_cube_on_plate_act --policy.push_to_hub=false --batch_size=8 --steps=1000 --output_dir=./outputs/put_cube_on_plate_act --policy.device=cuda --num_workers=4 --wandb.enable=false --log_freq=100 --save_freq=1000 --eval_freq=1000

# ── 本地真机推理（第 12 章原文命令：record + policy.path，无 teleop）
rm -rf /home/lz-xl01/.cache/huggingface/lerobot/liming/eval_put_cube_plate
lerobot-record --robot.type=so101_follower --robot.port=/dev/arm_slave_left --robot.id=left_follower_arm --robot.cameras='{left: {index: 0, fps: 30, width: 640, height: 480, video_backend: av}, side: {index: 2, fps: 30, width: 640, height: 480, video_backend: av}}' --display_data=true --dataset.repo_id=liming/eval_put_cube_plate --dataset.num_episodes=1 --dataset.single_task="Put red cube into plate" --dataset.push_to_hub=false --dataset.episode_time_s=60 --policy.path=/home/lz-xl01/lerobot-0.4.1/outputs/put_cube_on_plate_act/checkpoints/last/pretrained_model
  • ✓repo_id 必须加 eval_ 前缀：推理记录与训练集隔离。
  • ✓episode_time_s=60：给自主执行留足时间，可按需延长。
  • ✓key 命令不含 teleop：日志显示 teleop: None，动作完全来自策略。
  • ✓退出：时间到自动退出，或 Ctrl+C 一次；连按会导致机械臂姿态异常（KeyboardInterrupt 落在 busy_wait 里属正常）。
退出日志解读推理结束后尾部可能打印 FATAL: exception not rethrown 或"核心已转储"提示——这属于 pynput 清理期的正常噪音，确认已打印 Exiting 即可忽略。

08常见问题课段 8 · 融会贯通 · 13 min

  • ✓推理时显存不足：确认图片分辨率参数与训练一致（(3,480,640)），关掉 --display_data 的高负载预览，减小 batch 类参数。
  • ✓找不到 policy.path：路径必须精确到 checkpoints/last/pretrained_model 目录本身（不是 checkpoints），内含 config 与权重。
  • ✓启动报 Mismatch…Press ENTER：直接 ENTER 沿用现有校准文件。
  • ✓机器人一动不动：检查 policy.path 是否加载成功（看 Loading weights 日志）、任务初始摆位是否与训练一致、episode_time_s 是否太短。
  • ✓云端 pip 慢 / JupyterLab 传大文件断：换国内源、分卷上传 zip 或改用 scp/rsync。
  • ✓忘记关机被扣费：下机前固定动作——控制台 → 实例 → 关机；课程结束 → 更多 → 释放实例（复制 ID 前五位确认）。
  • ✓检查点拷到推理机后加载失败：pretrained_model 必须整目录传输（config.json、权重、processor 缺一不可），打包压缩时保留目录层级。
报错 / 现象原因处置
CUDA out of memory推理分辨率与训练不一致或同卡混跑对齐分辨率、nb 单任务占卡
Loading weights…failed路径指错 / 下载不完整校验目录结构与文件大小
KeyboardInterrupt in busy_waitCtrl+C 打断帧循环正常退出，只按一次
eval_ 数据集混入训练repo_id 忘加前缀重建带 eval_ 的 repo_id
安全清单云上：install → upload → train → download → 关机/释放；本地：path 指对 → 校准 ENTER → 推理 → 单次退出。

09拓展阅读课段 8 · 融会贯通

深入① LeRobot 官方 command/6_inference.sh 把推理命令参数化（模型名、任务名一键切换），量产部署时照抄其组织方式；② 检查点目录里的 config.json 记录了训练全部超参——换机部署时它是"自解释说明书"；③ 进一步可研究 ONNX / TensorRT 导出与 Isaac Lab 仿真回放，把真机验证前置到仿真；④ 多机位部署时思考：推理 60 Hz 下每一步都要过模型吗？还是块内复用（chunk 机制本身就是为此设计）。
延伸⑤ 把实例规格、镜像版本、开机关机时间做成一页值班记录，多人共用云账号时能对账；⑥ eval_ 数据集回放多次成功率，是比"看一次演示"更硬的验收证据；⑦ 检查点体积不大（ACT 52M 约 200MB 上下），走网盘/对象存储分发给多台推理机即可复现同款行为。

10思考题课段 8 · 融会贯通

思考 1如果把带 --teleop 的采集命令和带 --policy.path 的推理命令接反（比如推理时忘了删 teleop），系统行为会有什么差别？从"动作来源"的角度解释。
思考 2真机推理时摄像头被手挡了一下，图像变模糊。结合 ACT 的输入特征（480×640 图像 + 6 维状态）想一动：模型输出会如何劣化？用什么便宜手段（数据增强 / 多视角冗余）能降低这种脆弱性？
