00课程节奏：五星学习法 · 8 段微课（每段 ≤ 15 min）

本实验按五星学习法组织：先用一个真实故障聚焦问题，再激活旧知（串口权限、校准文件、视频编码），接着示证新知（主从臂 + 三摄像头 + 人在环数据流），然后动手应用新知完成单臂/双臂遥操作与数据采集，最后借排障与拓展融会贯通。全程切成 8 段微课、每段不超过 15 分钟，段间停顿 1~2 分钟消化；纯讲授合计约 100 分钟，其余课时用于动手实操与个别辅导。

01实验目标课段 1 · 聚焦问题 · 12 min

目标 A

完成单臂遥操作：授权串口后用 lerobot-teleoperate 让 SO101 从臂实时跟随主臂，观察 60 Hz 控制闭环与关节位置回显。

目标 C

完成单臂 / 双臂数据采集：用 lerobot-record 录制规范 episode，理解"录制→复位→编码入库"的循环节奏。

验收

本地缓存中出现可读的 LeRobot 数据集（含 task 文本、状态序列与视频），且 episode 数量达标（ACT 建议最少 50 组）。

提示本实验是全课地基：EXP-02 的训练、EXP-03 的推理、EXP-04 的 VLA 全部消费这里产出的数据集。

四条目标对应四段验收证据：连接日志（SO101 connected）、12 关节回显表、录制循环日志（Recording → Reset → Map 100%）、以及缓存目录中可打开的 parquet + 视频——每条都要截图进实验报告。

02核心原理：人在环数据流课段 1 收尾 + 课段 2 · 激活旧知 · 8 min

❓ 聚焦问题（课段 1）学员现场最常踩的坑：双臂遥操作启动后从臂一动不动，或者录了半小时发现缓存目录里数据集是空的——明明命令跑完了，episode 数却是 0。问题出在哪？带着这两个故障听完全课，到课段 6 你会亲手让示教数据稳稳落盘。

把机器人想成一双刚学会拿筷子的手：它还不知道"怎么抓"，但人类操作员知道。遥操作就是给人的手上绑一根"提线"——你动主臂（leader），从臂（follower）像镜子一样跟着动，把"抓-拿-放"的完整手艺原样录下来。

整条数据流分三段：①主从控制——主臂编码器读出 6 个关节角度，经串口发给从臂执行，循环速率约 60 Hz（日志显示 time: 16.72ms (60 Hz)）；②多模态感知——左右手腕摄像头 + 头部摄像头把 640×480 / 30 fps 画面同时写入；③数据落盘——每一帧的机器人状态、动作、任务文本与视频被打包成一个 episode，任务结束后的复位期（reset）不算入有效片段。

存储路径在 ~/.cache/huggingface/lerobot/<学生名>/<数据集名>/。录制暂停时视频还要经过 SVT-AV1 编码（日志出现 Map: 100%|…| 479/479 与 SVT-AV1 Encoder Lib v3.0.0），此时机械臂不要动，等 Recording episode 1 出现再开始下一条。

为什么强调两套频率：关节指令跑 60 Hz 是为了跟手不滞后，图像停在 30 fps 是为了给编码和落盘留带宽——两者由同一个 episode 时间戳对齐，任何一路掉帧都会让"这一帧该出哪只手"的对应关系错位。

↺ 激活旧知（课段 2）回忆三条旧知：① 串口设备默认无读写权限，sudo chmod 666 /dev/arm* 才能打开；② 校准文件按 robot id 命名存放，双臂要复制成 bimanual 左/右四份；③ 视频用 SVT-AV1 编码落盘，Map: 100% 期间不能碰机械臂。三条合起来，正好解释课段 1 那两个故障。

05关键命令随课段 5 / 6 对照使用

  --robot.id=left_follower_arm \
  --teleop.type=so101_leader --teleop.port=/dev/arm_master_left \
  --teleop.id=left_leader_arm

# ── 双臂前置：复制 4 份校准文件（第 07 章，必须先执行）

cp ~/.cache/huggingface/lerobot/calibration/robots/so101_follower/left_follower_arm.json \
   ~/.cache/huggingface/lerobot/calibration/robots/so100_follower/bimanual_follower_left.json
（right 从臂、左/右主臂 4 个文件同理，共 4 条 cp）

rm -rf /home/lz-xl01/.cache/huggingface/lerobot/liming/put_cube_plate
lerobot-record \
  --robot.type=so101_follower --robot.port=/dev/arm_slave_left \
  --robot.id=left_follower_arm \
  --robot.cameras="{left: {index: 0, fps: 30, width: 640, height: 480, video_backend: av}, \
side: {index: 2, fps: 30, width: 640, height: 480, video_backend: av}}" \
  --teleop.type=so101_leader --teleop.port=/dev/arm_master_left \
  --teleop.id=left_leader_arm --display_data=true \

  --dataset.single_task="Put red cube into plate" --dataset.push_to_hub=false \

  --teleop.right_arm_port=/dev/arm_master_right \

摄像头 index 说明：单臂链路用 left: 0 与 side: 2 两路，双臂链路用 left: 0 / right: 3 / side: 5 三路——顺序并非连续编号，是指导文档实测可用的插口位置，换机器后先逐个试出可用 index 再写进命令。

06动画演示：人在环数据流课段 4 · 示证新知 · 12 min

图 6-1｜人在环采集动画：主臂指令 → 从臂跟随 → 视频与状态一并落入数据集 → reset 回放原点

注意虚线回路：采集是"一条做完、复位、再做下一条"的循环，复位期保证每条 episode 从相同初始状态出发——这直接决定 EXP-02 训练时数据分布是否干净。

看动画时对照两条实线：紫色实线是串口指令流（人 → 从臂，60 Hz），绿色实线是视觉流（摄像头 → 数据集，30 fps）——两条流在同一时间轴上对齐落盘，才构成"图像 + 状态 + 动作"三元组。

08常见问题课段 8 · 融会贯通 · 13 min

  • ✓串口打不开：先 sudo chmod 666 /dev/arm*；设备号变了就 ls /dev/arm* 重查。
  • ✓双臂一动不动：多半没复制 4 份校准文件，或启动后没按回车；启动提示 Mismatch 时按 ENTER 使用已有校准文件。
  • ✓显示 Mismatch between calibration values…：直接 ENTER（沿用 id 对应文件）；只有想重刷电机才输入 c。
  • ✓退出时报 gRPC ERROR / winit DISPLAY / FATAL: exception not rethrown：清理期的正常噪音，确认已打印 Exiting 即可。
  • ✓数据集是空的：检查 dataset.repo_id 命名、是否录入超过 episode_time_s 的时长，以及缓存目录 ~/.cache/huggingface/lerobot/<名>/<集>/。
  • ✓摄像头 index 被占用：画面黑屏或启动报无法打开设备时，用 ls /dev/video* 核对，并关掉其他占用该 index 的预览程序（含上次未退净的采集终端）。
  • ✓主从臂对调（动左出右）：校准文件复制或串口号弄混，核对 /dev/arm_slave_left|right 与 /dev/arm_master_left|right 不要交叉。

围绕启动、运行、收尾三个时段，把高频报错压成一张"望闻问切"表：

症状段（启动 / 运行 / 收尾）先查什么一行处置
启动：设备不存在ls /dev/arm* /dev/cam_*udev 规则未生效就重新插拔并 chmod 666
启动：连接后立刻断开主从臂供电与共地检查电源适配器与 USB Hub 是否独立供电
运行：从臂抖动 / 跟随滞后校准文件是否张冠李戴左臂文件绝不能 cp 给右臂，按 id 对号入座
运行：摄像头黑屏index 是否被占用关掉占用 index 的预览程序，核对 left/side 编号
收尾：数据集缺视频编码是否被强制中断等 Map 100% 编完再退出，重新录制最后一条
运行：主从方向对调左右串口是否交叉slave_left↔master_left 对号，重新插拔后重查设备号
排错口诀串口先授权、校准先复制、回车别漏按、编码别碰臂、退出只按一次。

延伸④ 摄像头 video_backend=av（PyAV）负责把原始帧实时编码进数据集，换 backend 会改变落盘格式与 CPU 占用——采集机 CPU 吃紧时优先排查这里；⑤ 同一任务采到 300 组以上时，建议按"操作员 / 时段 / 摆位"分桶打 repo_id 前缀，方便 EXP-02 做数据消融；⑥ 熟练后可对照 dataset.features 输出，把双臂 12 关节 + 3 图像 + 任务文本的张量形状抄进实验报告，为 EXP-02 的输入层讲解做铺垫。
延伸⑦ 把本页五段命令整理成 record_single.sh / record_bimanual.sh 两个脚本（照抄 command/ 目录风格），下个班开课直接换 repo_id 复用——采集脚本化是走向量产采数的第一步。
