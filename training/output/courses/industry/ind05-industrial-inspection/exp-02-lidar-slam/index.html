00课程节奏：五星学习法 · 8 段微课（每段 ≤ 15 min）

本实验按五星学习法组织：先用一个真实故障聚焦问题，再激活旧知（坐标系 + 激光测距 + 累积误差），接着示证新知（三级流水线 + 回环动画），然后动手应用新知完成一键启动到绕场存图，最后借排障与拓展融会贯通。全程切成 8 段微课、每段不超过 15 分钟，段间停顿 1~2 分钟消化；纯讲授合计约 100 分钟，其余课时用于动手实操与个别辅导。

02原理：3D 点云建图（SLAM）讲透课段 1 收尾 + 课段 2 · 激活旧知 · 8 min

❓ 聚焦问题（课段 1）学员现场最常遇到的怪事：绕场一圈存了图，重载发现同一面墙画出两条线，起点和终点错开半米——这就是"漂移"。问题出在哪？带着这个故障听完全课——到课段 6 你会亲手用回环把它拉直。

把建图想象成「蒙眼画房间」：你被蒙着眼在房间里走，手里的一根激光笔每毫秒向四周量一次距离——右手边 2.3 米有面墙、正前方 4.1 米是柜子……把这些「距离点」按你的走位反投影到空间里，点越攒越多，房间的轮廓就浮现了。这就是 3D 点云建图。难点有两个：一是你不知道自己走到哪（得边走边定位，即 SLAM = Simultaneous Localization And Mapping，同步定位与建图）；二是每一步的定位误差会累加，走一圈回来发现「起点和终点对不上」——这就是漂移。

Go2 上的三级流水线

① 传感器出点云
3D 激光雷达（Mid-360 / XT16 级多线激光）旋转扫描，发布 utlidar/cloud（sensor_msgs/PointCloud2，frame_id=utlidar_lidar）。
② 3D 压成 2D
pointcloud_to_laserscan 把点云裁剪压平成一束「虚拟单线激光」——因为巡检地图按楼层平面画就够用，算力省一个量级。
③ SLAM 拼图
slam_toolbox online_async 拿激光束做scan匹配：找最优位姿把新扫描「贴」进地图，同时输出自己在哪。
④ 出两种图
Save Map 出 map.yaml + map.pgm（给 Nav2/AMCL 用的 2D 栅格）；Serialize Map 出序列化点云图（供 slam_toolbox 二次精修）。

回环：让地图「拉链对齿」的唯一办法

scan 匹配每一步都有一点点误差，走 100 米可能错出半米——地图里的墙会「重影」。但若你绕场一圈回到起点，建图算法会认出「这面墙我见过！」（回环检测），把首尾强行对齐并把误差摊销到整条轨迹上，墙立刻变直。这就是培训方案强调的技巧：闭合回路提升建图质量。

生活化类比：slam_toolbox 像「接力描图纸」：每次扫描是一张半透明硫酸纸，按最佳角度叠上去；回环就是把第一张和最后一张用夹子对齐——中间所有纸的错位一起被修正。
↺ 激活旧知（课段 2）回忆三条旧知：① 坐标系与 TF（EXP-01 已通链路，雷达有 frame_id）；② 激光测距原理（每束激光返回一个距离值，攒成点云）；③ 累积误差（每步小错累加成大错）。三条合起来，正好解释课段 1 那个故障。

Save Map + Serialize Map 双产物
  1. 粒子检查：ros2 topic echo --no-arr /utlidar/cloud 确认 frame_id=utlidar_lidar，ros2 topic hz /utlidar/cloud 看频率稳定。
  2. 一键启动：设置 ROBOT_IP 与 CONN_TYPE 后 ros2 launch go2_robot_sdk robot.launch.py——该 launch 内置 pointcloud_to_laserscan、slam_toolbox online_async、Nav2、RViz、Foxglove 全套。
  3. 切到建图视角：RViz 左侧 SlamToolbox（SlamToolboxPlugin）面板，点击 Start At Dock 开始建图，把起始位姿定在充电桩（Dock）处——与 EXP-04 的回充闭环呼应。
  4. 遥控探索：键盘或遥控器低速起步，先沿场地外围绕一整圈回到起点触发回环，再走中间区域补盲；途中观察点云是否与墙体贴合、有无重影。
  5. 保存地图：面板 Save Map 输出 map.yaml / map.pgm，再点 Serialize Map 序列化工匠文件——两种都交作业。
  6. 质量自检：重新加载地图，墙线笔直无重影、门口/柱子轮廓闭合、起终点一致即达标。

# ④ RViz 操作（SlamToolboxPlugin 面板，鼠标点击，无命令行）
#    Start At Dock → 慢速绕场一圈闭合回路 → Save Map → Serialize Map

# ⑤ 也可用 slam_toolbox 官方 CLI 存图（标准功能）
ros2 run slam_toolbox save_map -f ~/maps/patrol_site
验收闸门：map.yaml / map.pgm 存在且 RViz 重载无重影；序列化文件同目录保留。没走出回环就保存的地图一律返工——这是本实验唯一「技巧型」硬指标。
为啥压成 2D
巡检按平面路网走位，2D 栅格足够 AMCL/Nav2 用，内存与算力都降一个量级。
为啥是 online_async
建图放后台线程跑，前台遥控不卡顿——实时性与质量的折中。
地图存哪
Save Map 产 map.yaml(metdata+分辨率)+map.pgm(灰度像素)；Serialize 存 slam_toolbox 内部结构供再编辑。
下次实验怎么用
EXP-03 的 AMCL 直接吃 map.yaml；序列化图留给想修改地图结构的同学。

06动画：点云逐帧建图与回环课段 4 · 示证新知 · 12 min

动画 2-1：左图机器人绕场一周，绿点逐帧累积出房间轮廓；右上是「不回头」的代价——首尾错开的红墙；右下是回环校正后首尾咬合的绿线（黄圈脉冲=回环命中瞬间）。
动画 2-2：五步工作流泳道——从定原点、探索、双格式存图到交付 EXP-03；黄点按课堂实际点击顺序巡游，任何一步产物缺失都无法进入下一步。
观察动画 2-1 中绿点不是均匀铺满的：机器人走过近处点密、远处点稀——所以盲区补扫时要「贴着走」；而回环黄圈出现的瞬间整条绿线会抖一下并拉直，那就是误差摊销。

07互动：建图质量沙盘课段 7 · 应用新知 · 10 min

设定探索覆盖率与步数，开关回环，预测地图质量等级

把滑杆推到「高步数 + 不回环」，误差会冲破红线——这正是「闭合回路提升建图质量」的定量直觉：漂移 ≈ 单步误差 × 步数，只有回环能把这笔账一笔勾销。

08常见问题课段 8 · 融会贯通 · 13 min

Q RViz 里没有点云？
先 echo --no-arr /utlidar/cloud 查 frame_id，再把 Fixed Frame 改成该 frame；话题没数据则回 EXP-01 查 DDS 链路。
Q 点云「拉花」重影？
走太快或机身晃动过大：降低速度、保持匀速直线；地面打滑时等步态稳定再走。
Q 启动 launch 报找不到包？
没 source go2_ros2_sdk 工作空间：source install/setup.bash 后重开；确认 CONN_TYPE 与网线/WiFi 匹配（cyclonedds | webrtc）。
Q 地图墙体错位重影？
回环没闭合或闭合时匹配失败：沿特征丰富的墙体重走一圈，起点终点重叠 2~3 米再存图。
Q Save / Serialize 都要吗？
Save 产 2D 栅格（AMCL 必需）；Serialize 产可再编辑的序列化工件——验收两个都要交。
Q 空旷走廊建不了图？
特征太少 scan 匹配无从下手：临时摆放纸箱/锥桶造特征，或沿有货架、柱子的一侧行走。
Q launch 太重卡顿？
该 launch 默认连 Nav2/RViz/Foxglove 全开：先只留建图调通，再逐步打开其余节点。
Q 地图坐标和充电桩对不上？
务必用 Start At Dock 定原点；后期随手重启建图会让位姿原点漂移，EXP-04 回充就找不到桩。

09拓展阅读课段 8 · 融会贯通

  • 宇树机载 unitree_slam / mid360_driver：官方建图服务，App 里点一点即可出图，效果好但闭源、不可随课分发——与本课 slam_toolbox 开源链路对照理解「能演示 ≠ 能二次开发」。
  • FAST-LIO（HKU-Mars）：高性能 LIO 框架，工程界常用其替代方案——拓展阅读：https://github.com/hku-mars/FAST-LIO （命令与兼容性请自行核验后再用）。
  • slam_toolbox 调参：loop_search_minimum_linear_distance（回环搜索距离）、ceres 线性求解器参数——地图重影时的第二把钥匙。
  • 点云进阶玩法：go2_ros2_sdk 同时发布点云与 TF，配合 Foxglove 可回放建图全程，交作业时附回放比截图更有说服力。
  • 3D→2D 的取舍：多层建筑需要分层建图；本课场景（单层厂区）以栅格为主，3D 点云留存作碰撞与货架核查的底档。
