遥操作自检与故障排查

这是本课的"总验收实验"。前三步（串口、校准、摄像头）全部就位后，你将跑通不带摄像头的单臂遥操作（16.74ms · 60Hz）→ 带摄像头的单臂（31.59ms · 32Hz）→ 双臂遥操作，读懂 NORM 姿态表与正常停止打印；再对照第 14 章学会三类故障的处置，最后用第 15 章脚本手册把所有手动命令沉淀成一键脚本。

02原理讲解：遥操作是怎么"隔空传动"的课段 1 收尾 + 课段 2 · 激活旧知 · 8 min

❓ 聚焦问题（课段 1）学员跑遥操作时最常踩的两个坑：① CTRL+C 按了两下——臂卡死在失锁前的力矩状态（第一下走 finally 断开串口，第二下打断清理）；② 摄像头换了个 USB 口——别名全失效（ID_PATH 变了，/dev/cam_* 找不到）。带着这两个故障看完全课——到课段 6 你会亲手让臂正常停止、摄像头永不丢别名。

打个比方：遥操作就像提线木偶 + 同声传译。你牵动主臂（leader）的关节，主臂编码器把每个关节的角度读出来；LeRobot 进程以 60Hz 的"节拍"（每 16.7ms 一次）把这组角度翻译成指令，经串口发给从臂（follower）的舵机——从臂就像被无形的手牵着的木偶，实时复现你的动作。整条链路没有"先算路径再执行"的中间模块，关节角直接进出，这就是最贴近端到端的一次数据流动。

1你的手掰动主臂 → 编码器读出六关节角度
2lerobot-teleoperate 按 fps=60 采样映射（16.7ms/拍）
3串口把目标角发给从臂 → 舵机跟随，NORM 表实时刷新

再看两个关键数字：不带摄像头时 16.74ms（60Hz）几乎全速跟随；加上两路 640×480 摄像头后变 31.59ms（32Hz），双臂加摄像头 36.29ms（28Hz）——图像采集与显示挤占了节拍。这就是"感知会吃算力预算"的最直观体现。另外，退出时CTRL+C 只能按一次：第一下让程序走 finally 断开串口、关闭相机，连按会打断清理，臂就可能保持失锁前的力矩状态卡住。

↺ 激活旧知（课段 2）回忆前三实验的三条旧知：① EXP-01 的 udev 别名（/dev/arm_master_left 等）；② EXP-02 的"先电源后 USB"插拔顺序；③ EXP-03 的摄像头校准 JSON 路径。本课把它们串成一条遥操作链路——别名找口、校准定零位、摄像头给感知，缺一不可。

04步骤实践：单臂 → 双臂跑通遥操作课段 5~6 · 应用新知 · 2×15 min

1conda activate lerobot + sudo chmod 666 /dev/arm* 放行串口
2跑不带摄像头单臂遥操作：看到 connected 与 time: 16.74ms (60 Hz) 即成功，动手掰主臂试跟随
3CTRL+C 单次停止，见到 leader/follower disconnected 打印为正常
4加 --robot.cameras=… 两路 + --display_data=true 跑带摄像头版：31.59ms (32 Hz)、NORM 六关节表、弹出夹爪/顶部视频窗（可调顶部摄像头对准作业区）

6跑 bi_so100_follower/bi_so100_leader 双臂命令：12 关节 NORM 表 16.72ms (60 Hz)；带摄像头版 36.29ms (28 Hz)；视频窗停止后需手动点 X

05关键命令随课段 5 / 6 对照使用

# ① 单臂遥操作·不带摄像头（第 06 章 3）
conda activate lerobot
sudo chmod 666 /dev/arm*
lerobot-teleoperate \
  --robot.type=so101_follower \
  --robot.port=/dev/arm_slave_left \
  --robot.id=left_follower_arm \
  --teleop.type=so101_leader \
  --teleop.port=/dev/arm_master_left \
  --teleop.id=left_leader_arm
# 正常打印：connected … time: 16.74ms (60 Hz)，动主臂从臂跟随

# ② 单臂遥操作·带摄像头（第 06 章 4，追加两段）
lerobot-teleoperate … --robot.cameras="{ left: {type: opencv, index_or_path: \"/dev/cam_left\",
  width: 640, height: 480, fps: 30, fourcc: \"MJPG\"}, side: {type: opencv,
  index_or_path: \"/dev/cam_head\", width: 640, height: 480, fps: 30, fourcc: \"MJPG\"}}" \
  --display_data=true
# 打印 time: 31.59ms (32 Hz) + 六关节 NORM 表 + 视频窗口

# ③ 双臂前·复制校准 so101 → so100/bimanual（第 07 章 2，务必执行）
mkdir -p ~/.cache/huggingface/lerobot/calibration/robots/so100_follower/
mkdir -p ~/.cache/huggingface/lerobot/calibration/teleoperators/so100_leader/
cp …/robots/so101_follower/left_follower_arm.json  …/robots/so100_follower/bimanual_follower_left.json
cp …/robots/so101_follower/right_follower_arm.json …/robots/so100_follower/bimanual_follower_right.json
cp …/teleoperators/so101_leader/left_leader_arm.json  …/teleoperators/so100_leader/bimanual_leader_left.json
cp …/teleoperators/so101_leader/right_leader_arm.json …/teleoperators/so100_leader/bimanual_leader_right.json

# ④ 双臂遥操作（第 07 章 3，CTRL+C 只按一次）
lerobot-teleoperate \
  --robot.type=bi_so100_follower \
  --robot.left_arm_port=/dev/arm_slave_left --robot.right_arm_port=/dev/arm_slave_right \
  --robot.id=bimanual_follower \
  --teleop.type=bi_so100_leader \
  --teleop.left_arm_port=/dev/arm_master_left --teleop.right_arm_port=/dev/arm_master_right \
  --teleop.id=bimanual_leader --display_data=true
# 12 关节 NORM 表，time: 16.72ms (60 Hz)；带摄像头再追加三路 cameras JSON

# ⑤ 停止与脚本化（第 15 章 1）
bash 1_calibrate_all.sh        # 依次校准 左从→右从→左主→右主
bash 2.3_teleoperate_left_with_cameras.sh   # 左臂带摄像头遥操作
bash 3_teleoperate_dual_arm.sh # 内含 mkdir+4cp+双臂命令，一键完成
◆ 双臂校准复制要点4 条 cp 把 so101 单臂校准 JSON 改名为 bimanual_* 复制到 so100 目录——不做这步双臂命令会找不到校准数据。脚本 3_teleoperate_dual_arm.sh 已将 mkdir + 4cp + bi_so100 命令全打包，一键完成。

08常见问题课段 8 · 融会贯通 · 13 min

  • PermissionError: [Errno 13] … '/dev/ttyACM0'（第 14 章 1）：串口没放权限 → sudo chmod 666 /dev/ttyACM*；日常用别名前先 sudo chmod 666 /dev/arm*
  • FileExistsError: …test/put_cube_on_plate（第 14 章 2）：数据集目录已存在——要续录就改 --dataset.repo_id 名称；数据不要了就 rm -rf ~/.cache/huggingface/lerobot/test/put_cube_on_plate
  • 退出时从臂卡住掰不动（第 14 章 3）：多因 CTRL+C 连按打断清理——拔掉该设备电源再插回即可恢复；以后只按一次
  • 带摄像头弹 winit/DISPLAY 报错打印：第 06/07 章原文日志中该行之后仍继续出现 connected 与 time 打印——以紧跟其后的 connected、60Hz/32Hz 节拍打印为运行判据
  • 遥操作没反应、一直没节拍打印：第 07 章提示"如果未开始，则多点击几下回车继续"；同时核对串口别名与校准 JSON 是否已按 4 条 cp 复制成 bimanual_*
  • 双臂找不到校准：第 07 章强调 cp "务必执行"——so101 单臂的 JSON 文件名与 bimanual 所需文件名不同，不复制就对不上号
💡 排障心法先问"上一次做到哪一步"：连接类报错查第 03/05 章（别名、chmod、校准），数据类报错查 repo_id 目录（改名或 rm -rf），机械状态类报错先断电复位——永远先看 traceback 最后一行，再回来对表。

10思考题课段 8 · 融会贯通

📝 思考题 1三组实测节拍：单臂无摄像头 16.74ms (60Hz)、单臂双摄 31.59ms (32Hz)、双臂三摄 36.29ms (28Hz)。为什么加摄像头后 Hz 几乎腰斩、而双臂只比单臂再慢一点？图像与关节指令谁更吃时间？这对"端到端策略实时性"意味着什么？
