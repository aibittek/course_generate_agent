EXP-04 · 第 2 章 · 综合性 · 8 学时

DeepSORT 追踪底座：车被挡住三秒，ID 依然不换

纯 IoU 关联的 SORT 只要目标被遮挡几帧，轨迹即断、换新 ID。本项目的 tracking/ 模块是 DeepSORT 标准结构的纯 numpy 自实现（零新增依赖）：卡尔曼常速模型（8 维状态、按框高缩放噪声、CHI2INV95 马氏门控）负责"猜目标下一帧在哪"，级联匹配按 time_since_update 排优先级，ReID 外观特征（deepsort.rknn，64×128 ImageNet 归一化、cosine ≤ max_dist=0.2）让遮挡后的同一辆车认回来，min_box=32 / max_stale=15 负责净场。本实验跑 97 项 pytest 回归 + track_demo ID 底座验证。

难度 ⭐⭐⭐ · 8 学时 Kalman 8 维级联匹配 ReID 64×128CHI2INV95

01问题引入：遮挡一帧就换 ID

地下车道里一辆白车被货车挡了两秒——再出现时，如果系统给它发了个新号，"追踪 id3"就永远追不到它了：

1纯 IoU 关联：两帧框重叠才算"同一个人" → 被遮挡 IoU 归零 → 轨迹断，换新 ID
2没有运动记忆：目标被挡时连"它大概会从哪冒出来"都不知道 → 重逢不相识
3没有外观记忆：白色皮卡 vs 白色轿车在低分辨率下长得很像 → 胡乱认亲
4目标太小 / 早已消失的幽灵轨迹还占着 ID 名额 → 画面乱画、VLM 被误导
5对策：预测先跟上 + 外观来认人 + 净场扫幽灵 = DeepSORT 三件套
💡 为什么是 R3 的核心R3 要求"追踪 ID 连续"。ID 一跳，上游的"追 id3"、下游的 follow 过滤、VLM 选车全部失效——所以追踪底座是全链路的地基，本实验 8 学时打这个地基。

02原理通俗讲解：工牌+运动记忆的保安

比喻一
卡尔曼 = 根据旧轨迹猜新位置

保安盯着一个人，他突然被货架挡住——保安不会站着发呆，而是顺着他的走向往前多看两步："他应该快从那头出来了"。这就是 predict()：8 维状态 [cx, cy, aspect, h, vx, vy, va, vh]（中心、宽高比、高 + 各自速度），常速模型 x' = Fx 即"位置 += 速度"；人一露头，再用观测框修正猜测（update()）。猜错不要紧，观测会把它拉回正轨。

比喻二
级联匹配 = 先给刚见过的人发号

发号窗口同时排着"一秒钟前刚见过"和"五分钟没见"的两张旧凭证——先认刚见过的。级联按 time_since_update 从 1 到 max_age 逐层分配：刚更新过的 track 优先匹配，长期遮挡的旧 track 预测已经不可靠，不许它抢新目标的检测框。

比喻三
ReID = 衣着认人

光靠"往哪走"还是会认错（两辆车并排拐弯）。ReID 给每个检测框拍张标准证件照（crop 缩到 64×128、ImageNet 归一化）提成特征向量，用余弦距离比对："衣着发型对得上，就是刚才那个人"（≤ max_dist=0.2 才认）。特征库存的是历史平均外观而非单帧快照，抗抖动。

比喻四
min_box / max_stale = 门卫净场

监控角落里闪现的小噪点（框宽或高 < 32 像素）不发工牌；人早走了还留在寻人启事上的照片（连续 15 帧没命中）就撤下来——但和"档案彻底注销"（max_age=70 帧）是两码事：先撤下启事（不画但留档），70 帧还没回来才注销档案。

🎯 合起来一句话DeepSORT = 运动记忆（Kalman）+ 排队优先权（级联）+ 衣着认人（ReID）+ 净场规则（min_box/max_stale）。本项目 tracker.update()（tracking/tracker.py L72-75）每帧三步：预测 → 级联匹配 → 剩余 detection 与未确认 track 做 IoU 匹配。

03关联知识点：DeepSORT 九要点

知识点要点与位置
3.1.1 结构卡尔曼预测 + IoU/外观级联关联 + 确认框；Track 生命周期 Tentative→Confirmed（hits≥n_init）→Deleted（tracking/track.py）（前置 1.2.2）
3.1.2 常速模型8 维均值 + 4 维协方差、噪声按框高缩放（σ_pos=1/20、σ_vel=1/160）、CHI2INV95 门控（df2→5.9915）（tracking/kalman.py）
3.1.3 双闸剔除min_box_w/h=32 小框剔除 + max_stale=15 超龄剔除（tracking/pipeline.py L53-62）（前置 3.1.1）
3.2.1 外观特征deepsort.rknn 64×128 ImageNet 归一化，消除单帧漏检换 ID（tracking/reid.py preprocess_crop L20-29）（前置 3.1.1）
3.2.2 异步池ReIDPool 4 worker（RKNN 非线程安全，每线程独立实例）、extract 超时 timeout=10 → features=None 走纯 IoU（tracking/reidpool.py L24-67）
3.2.3 ID 调参min_confidence=0.3 与 ID 稳定性（pipeline.py L20-21 两级置信过滤，与 detect.score_thr=0.25 配合）（前置 3.1.1）
3.3.1 类别限定class_filter=[car]，COCO 80 类通用检测（前置 1.1.1）
3.3.2 底座验证track_demo --list / --text 验证 ID 底座，无 LLM、stdin 直达 engine（前置 3.2.3）
3.3.3 丢失恢复遮挡丢失后同 ID 恢复靠 ReID；unlock_on_loss 全丢则恢复全显示（前置 3.2.1）
💡 与 SORT 的差别SORT = 卡尔曼 + IoU，快但怕遮挡；DeepSORT 在其上补了外观特征与级联匹配两项。本模块对照 nwojke/deep_sort 的 BSD 参考实现，用纯 numpy 重写（kalman.py / matching.py），不引入 torch/GPU 依赖。

09重点与易错点

  • 别用手工 IoU 替代级联：级联按 time_since_update 排优先级，保证长期遮挡的旧 track 不夺走新目标的匹配；纯 IoU 会让长时遮挡后误关联。
  • 区分 max_stale=15 与 max_age=70：前者是"不画但保留轨道"的软阈值，后者是轨道生命周期上限（超了直接 DELETED）——先撤启事，再注销档案。
  • ReID 不是万能：目标外观剧烈变化（背转面）时余弦距离兜不住，需要 max_stale 配合剔除真消失目标。
  • 超时降级不抛异常：ReIDPool.extract 超时（timeout=10）→ 整帧 features=None 走纯 IoU、失败 crop 用零向量哨兵补齐——任何一步失败都回到纯 IoU，主循环绝不挂死。
  • 纯 numpy 不加依赖：Kalman/匹配核心勿引入 torch/GPU 依赖；pytest 纯逻辑 x86 可跑，先于硬件验证。
  • tuned 值复原：min_confidence 调参后务必恢复 0.3（可接受 0.25–0.6）；class_filter 保持 [car]。
  • track_demo 无唤醒词：stdin 直达 engine，比 track_app 少一层语音；--list 是验证 ID 底座的核心调试开关。

🎯 数值手感h=100 像素时位置噪声标准差 = h/20 = 5px、速度噪声 = h/160 ≈ 0.625px/帧；新建 track 首帧速度完全未知，初值协方差放得更大（位置 2σ·h=10px、速度 10σ·h=6.25px/帧）——猜得越没底，越要等观测来教。

10总结与思考

本实验打通了追踪底座的四层机制：卡尔曼给出"运动记忆"（8 维常速预测 + 按框高缩放噪声 + 马氏门控），级联匹配给出"排队公平"（刚见过的先认），ReID 给出"衣着认人"（64×128 特征、cosine ≤0.2、历史均值抗噪），min_box/max_stale 给出"净场规则"（32 像素与 15 帧两道闸）。97 项 pytest 是行为基线，track_demo --list 是肉眼验证。产出：pytest 全绿记录、卡尔曼+级联示意图、ReID 遮挡恢复观察、调参笔记、ID 底座验证结果。
