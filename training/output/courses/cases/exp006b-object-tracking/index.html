PROJECT OVERVIEW

项目速览：四条流水线，一台单状态机

object_tracking 是一个"看—听—说—记"闭环的通用目标追踪应用，视觉与语音两条流水线在 TrackEngine 的同一个循环里协同。

视觉流水线

帧 → YOLOv8n RKNN（COCO 80 类，class_filter=[car]）→ ReID 外观特征 → DeepSORT 级联匹配 → 确认框按 follow_ids 过滤绘制 → MJPEG 发布。

语音 / 指令流水线

唤醒词 → ASR → LLM FunctionCall → _native_gate 门控 → tool_dispatch → submit_effect 入队（maxsize=8）→ 主循环 apply → 流式 TTS 分句播报。

三级开发模式

文本（--text，stdin 喂指令、无麦克风）→ 语音（+录音/播放）→ 摄像头（+ROS 话题）。每级只叠加一层硬件依赖：先离线跑通，再逐步上硬件。

入口与输出

主入口 apps/track_app.py，离线演示 apps/track_demo.py；浏览器访问 http://<IP>:8088/track.mjpg 查看实时标注流，事件落盘 runs/logs/events.jsonl。

PARAM REFERENCE

关键参数速查

全部取自 config/track_config.yaml，实验中反复出现的数值边界先在这里混个脸熟。

detect · 检测段

score_thr=0.25 · iou_thr=0.45 · imgsz=640 · class_filter=[car]——第一级过滤，决定哪些框进入追踪。

tracker · 追踪段

use_reid=true · min_confidence=0.3 · min_box_w/h=32 · max_stale=15——第二级过滤与软保留阈值。

tracking · 引擎段

pause_wait=true · pause_timeout=30.0——指令挂起时只读帧不处理，30 秒看门狗自动恢复。

vlm · 描述选车段

cell_cap=16 网格封顶 · vlm.fake_result_id=3 仅链路调试——超过 16 个候选直接 fail-closed。

server · 服务段

port=8088 · stream_name=track.mjpg；LLM 服务端口 8080；指令队列 maxsize=8 满则丢最旧。

speech · 语音段

wake_words=[小飞小飞, 小飞同学] · kws.threshold=0.25 · 文本模式队列 maxsize=100（约 10 秒缓冲）。

PROJECT BRIEF

项目总览

一辆搭载摄像头与六麦麦克风的智能小车，怎么做到"听得懂、看得准、跟得住、坏得明明白白"。

项目主线

摄像头画面进 YOLOv8n 检测与 DeepSORT 追踪，语音指令经 LLM FunctionCall 门控下发，VLM 用网格描述挑目标，全链路事件落盘 events.jsonl。

能力目标

会读需求（R1-R13）、会读单状态机主循环、会改配置不炸锅、会解释每一次匹配与每一次降级，最终独立完成五步全功能验证。

硬件与模型

工控主机 + 摄像头 + XFM 六麦阵列；Qwen3.5-0.8B（rkllm）、Qwen3.5-0.8B-vision、yolov8n.rknn、deepsort.rknn 四个模型协同工作。

验收标准

追踪/清除/截图指令全部经门控生效，描述选目标可回映真实 ID，断网断模型时按降级链退化不崩溃，日志可完整复盘。

GLOSSARY

八个高频术语速查

贯穿九个实验的核心词汇，先混个脸熟，后续章节会反复用到。

fail-closed

"拿不准就不放行"：门控、VLM 解析拿不到确定结果时一律拒绝执行，宁可不动也不乱动。

单状态机

TrackEngine 只有一条 RUN 主循环（读帧→处理→排干指令→绘制→发布），像电梯调度统一排班，杜绝多线程抢状态。

FunctionCall

LLM 不直接干活，只在 track_ids / clear_track / save_snapshot 三个原生工具里做选择题，由 _native_gate 把关。

cell_cap=16

VLM 网格描述选目标时最多切 16 格（448×448 缩略图），格子编号再映射回真实追踪 ID。

min_box 32

边长低于 32 像素的检测框不进追踪链，太小的框特征不可靠，进了只添乱。

epoch 打断

新一轮语音播报使 epoch 递增，旧播报与迟到指令因编号过期被丢弃，解决"自说自话"。

unlock_all

清除指令或目标丢失导致追踪全部解除的事件，落盘 events.jsonl，是复盘"为什么跟丢了"的关键线索。

三级开发模式

文本 → 语音 → 摄像头逐级叠加：任何功能先用 --text 跑通逻辑，再上硬件，出问题好定位。

[ASR 实时]

[cmd] 与 [track_vlm]

runs/logs/events.jsonl
