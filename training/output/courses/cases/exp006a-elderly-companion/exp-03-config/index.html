EXP-03 · 第 1 章 · 设计性 · 4 学时

fall_config.yaml 配置详解：系统唯一的"总闸"

整个 elderly_companion 只认一份 YAML：config/fall_config.yaml，共十四段，管着从模型路径、检测阈值、状态机时间参数到串口设备、LLM 服务端口的一切。本实验吃透 config_schema 必填/可缺省双轨、CLI > yaml > 代码默认三层覆盖优先级，学会用 env_check 一键体检七个依赖库、模型文件与串口设备，做到"改参数不动代码、动代码必过自检"。

难度 ⭐⭐ · 4 学时 十四段 YAMLconfig_schema 覆盖优先级env_check

01问题引入：改一个阈值为什么要惊动全系统

课堂上最常见的事故：同学把"躯干角 50°"直接写进状态机源码里测试 —— 结果代码里 50、YAML 里 50、注释里 45，三处不一致，谁也说不清线上到底用的哪个。工程化的答案是：所有可调量只住在配置文件里。

1阈值散落源码 → 改一次要全文搜索，漏一处就是隐性 bug
2集中到 fall_config.yaml → 调参 = 改一行，重启即生效，还可 git diff 审查
3再加 config_schema 校验 → 键名拼错、必填缺失在启动时立刻报错，不带病运行
4最后由 env_check 把关 → 依赖库、模型文件、串口设备逐一探测，EXIT 0 才准开工
💡 一个类比配置文件像家里的配电总闸 + 分路标签：哪里该通电、多少安培（阈值）都写在面板上。总闸不清晰，谁都不敢动线路。

02原理通俗讲解：参数的三层来源与"双轨制"

同一个参数可能来自三个地方，优先级从高到低：

第 1 优先
命令行 CLI 参数

如 --score-thr 0.4 --log-level DEBUG：一次性实验覆盖，不落盘、不污染文件，跑完即失效。适合"今天临时试一个值"。

第 2 优先
fall_config.yaml

持久化的正式值：团队共享、随版本走。适合"这个项目的正式参数"。CLI 没给的键，全部以这里为准。

第 3 优先
代码内默认值

config_schema 的兜底：yaml 没写、CLI 也没给的可缺省键，自动填默认值，保证程序永远拿得到值。

而 config_schema 本身是双轨制：

轨道schema 写法缺失时的行为例子
纯 type（必填）type: str（无 default）yaml 里没写 → 启动直接 config error: missing keydetect.model_path 等路径类键
(type, default)（可缺省）带默认值yaml 没写 → 自动填默认，程序照常跑detect.score_thr、state.angle_thr
🔔 隐患坑：schema 有默认不等于 YAML 是活键典型如 session.wake_words：schema 给了默认值（可缺省轨道），于是 yaml 里没写时也会"正常启动"—— 但你以为在改唤醒词、实际生效的是 schema 默认。要改的键必须显式写进 yaml，别依赖兜底。

04实验目标

  • 能按用途默写十四段配置的分段清单，并说出 state / detect / alert / llm 四段的关键键与默认值
  • 能解释CLI > yaml > 代码默认三层优先级，并现场演示一次 CLI 覆盖
  • 能区分 config_schema 的必填（纯 type）与可缺省（带 default）双轨行为
  • 能独立运行 env_check，读懂 [env] OK / MISSING / 自检通过三种输出与退出码含义
  • 牢记三个端口/设备易混点：TTYACM0（六麦）vs TTYUSB0（告警）vs TTYUSB1（雷达）；8080（LLM）vs 8088（MJPEG）

08实操步骤：env_check 自检与 CLI 覆盖实验

1进入工程目录，先跑官方自检 —— 七库、模型文件、/dev/ttyUSB0 逐一探测
2故意制造 schema 键名拼错（detect.model_path → detect.model_pth），观察启动报错
3改回后做一次 CLI 覆盖：--score-thr 0.4 --log-level DEBUG，确认临时值生效且 yaml 未被改动
4逐条核对 state 段六个时间/角度参数与 EXP-01 三条时序的对应关系
5口述三个设备/端口分工（六麦 ACM0、告警 USB0、雷达 USB1；LLM 8080、MJPEG 8088）并复验
# ① 进入工程并运行环境自检（只读探测，不会自动安装任何东西）
cd ~/ros2_ws/src/xflz_eai_car1/app/elderly_companion
python3 common/env_check.py --config config/fall_config.yaml
# 预期逐条输出：[env] OK numpy 1.24.3 ... 直到 [env] 自检通过（EXIT 0）
# 探测 7 库：numpy / cv2 / scipy / rknnlite / sherpa_onnx / serial / yaml
# 同时探测模型文件与串口设备；缺项输出 [env] MISSING /dev/ttyUSB0（EXIT 2）

# ② schema 报错演示：把 detect.model_path 拼成 detect.model_pth 后启动
python3 apps/fall_video_demo.py --video testdata/fall_slow_x264.mp4 --text
# 预期：config error: missing key  → 立刻改回（必填轨道，绝不带病启动）

# ③ CLI 覆盖实验：临时值生效，yaml 保持原样
python3 apps/fall_video_demo.py --video testdata/fall_slow_x264.mp4 --text --score-thr 0.4 --log-level DEBUG
# 优先级：--score-thr 0.4 > yaml 的 score_thr: 0.25 > schema 默认
🔍 端口备忘/dev/ttyACM0 = XFM 六麦硬件唤醒（speech 段）；/dev/ttyUSB0 = 告警串口（alert 段 L115）；/dev/ttyUSB1 = 毫米波雷达，告警不走它。硬件插拔后枚举号可能漂移，报错先 ls /dev/tty* 核对。

09重点与易错点

  • 三层覆盖优先级：CLI > yaml > 代码默认，临时试值用 CLI、正式值进 yaml
  • 双轨制：纯 type 必填缺了报 config error；带 default 可缺省自动兜底
  • env_check 是只读自检：不自动装依赖，缺啥报啥，EXIT 0 才开工
  • 重点键位：vlm.enabled 默认 false（L16）、angle_thr 50（L57）、ask_timeout 12（L62）、alert.port USB0（L115）、llm 端口 8080（L170/173）
⚠️ 常见坑现象 → 解法
键名拼错启动 config error: missing key → 核对 schema：改 yaml 键名而不是改 schema
误把"可缺省"当"没生效"改了概念却没改 yaml（session.wake_words 典型）→ 要改的键显式写进 yaml
CLI 参数顺序/拼写错--sore-thr 静默或报错 → 每次跑完看日志里的实际生效值
串口张冠李戴告警没反应，插的是 USB1（雷达）→ alert.port 对准 USB0
端口混用curl 8088 找 LLM / MJPEG 8088 找 llm → LLM 在 8080（/v1/models），预览流在 8088
体检当安装器MISSING 后等它自动修 → env_check 只读，依赖需按讲义自行安装
