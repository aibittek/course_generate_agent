## 一、课程目标

### 1.1 知识目标
通过本课程的学习，学生能够：
1. 掌握老人跌倒监护综合项目 R1-R12 功能需求体系与五层模块架构（common/vision/fall/speech/llm）
2. 理解 fall_config.yaml 十四段配置体系、config_schema 校验机制与 CLI 覆盖规则
3. 掌握 XFM 六麦唤醒→sherpa-onnx KWS→zipformer 流式 ASR→Matcha-TTS 播报的完整语音链路原理
4. 理解 YOLOv8 行人检测（RKNN NPU）+ BlazePose/RTMPose 姿态估计双后端的视觉流水线
5. 掌握几何特征跌倒判定（躯干角/宽高比/髋部速度）与六状态机流转机制
6. 理解 RKLLM 本地大模型推理（Qwen3.5 RK3576 NPU）与 Flask OpenAI 兼容 HTTP 服务架构

### 1.2 能力目标
通过本课程的学习，学生能够：
1. 具备在 B2/C1 平台上独立部署并运行老人跌倒监护系统全链路的能力
2. 能够独立完成语音交互、视觉检测、跌倒判定、告警证据、LLM 对话五大模块的集成测试与故障排查
3. 能够通过 fall_config.yaml 配置调优检测阈值、语音参数与告警策略，解决实际场景偏差
4. 能够基于接口清单与源码定位问题，完成 STM32 告警硬件联调与证据存档验证

### 1.3 素养目标
通过本课程的学习，学生能够：
1. 养成"先离线验证、后实时部署"的嵌入式 AI 工程安全意识
2. 具备语音+视觉+判定+告警多模块协作的系统集成开发精神
3. 树立对边缘计算资源约束（RKLLM 1.5G 内存/VLM 开关）与隐私安全的工程伦理意识

## 三、教学内容

### 第1章 项目需求与系统架构

#### 教学内容
- R1-R12 功能需求体系（跌倒检测/语音询问/告警存档/取消机制）
- 跌倒→ASK→ALERT→取消全流程与语音打断/重问/超时兜底(12s)机制
- 五层模块划分：apps/common/vision/fall/speech/llm
- 视觉流水线：YOLO→IoU→姿态→特征→状态机
- 语音单状态机（IDLE/LISTENING/SPEAKING）+ 单录音线程 + 队列路由
- monitor↔VoiceLoop 三接口（on_kws/on_asr/has_ask_session）解耦设计
- 多输入源抽象 FrameSource（image/video/ROS）与文本模式（--text）统一

#### 重点难点
- **重点**: R1-R12 需求体系；五层模块职责划分；视觉与语音双流水线数据流
- **难点**: monitor↔VoiceLoop 三接口解耦；文本/音频模式状态机统一

### 第3章 语音交互

#### 教学内容
- XFM 六麦硬件唤醒（AIUI 事件/beam/angle）与软件 KWS 关键词检出（sherpa-onnx）
- 流式 ASR（zipformer 增量解码 + 端点检测）
- TTS 播报与预合成缓存（零合成延迟）
- 唤醒后启动录音（XFM 时序）+ 双次排空防回声
- ASK 应答窗口（4.5s 静音 + 2s 兜底快答）与单次应答防重复
- 语音→意图→任务闭环测试

#### 重点难点
- **重点**: 语音链路 KWS→ASR→TTS 全流程；唤醒后录音启动时序
- **难点**: 双次排空防回声；ASK 端点检测与兜底快答

#### 教学活动
- [x] 讲授：docs/07_语音测试用例.md

### 第5章 跌倒判定与告警证据

#### 教学内容
- 几何特征判定：躯干角>50° / 宽高比<0.5 / 髋部速度尖峰
- 六状态机（IDLE/FALLING/LYING/ASK/ALERT/CANCELLED）每人独立 + IoU 跨帧关联 + cooldown 60s
- STM32 串口告警协议（0xAA 0x55 帧 + CRC8 @1Mbps）+ 告警节流
- 证据存档三件套：FrameRing 前后帧截图 / .avi 视频 / events.jsonl
- MJPEG 实时推流（:8088/fall.mjpg）

#### 重点难点
- **重点**: 几何特征判定阈值；六状态机流转；STM32 帧协议
- **难点**: IoU 跨帧人员关联与每人独立 FSM；证据存档完整性验证

### 第6章 大模型与系统验证

#### 教学内容
- RKLLM 本地大模型推理（Qwen3.5 RK3576 NPU, librkllmrt.so）
- Flask OpenAI 兼容 HTTP 服务（/v1/chat/completions）与多轮对话历史滑动窗口
- server_manager 子进程生命周期（端口自动管理/清理）
- VLM 视觉复核（vision_judge，默认关闭/内存考虑）
- 跌倒判定与 LLM 对话并存路由
- 全链路闭环验证：唤醒→对话→跌倒→询问→应答→告警→存档

#### 重点难点
- **重点**: RKLLM 推理与 OpenAI 兼容服务；全链路闭环验证
- **难点**: VLM 复核开关与内存约束；跌倒判定与 LLM 对话并存路由
