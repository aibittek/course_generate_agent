06先看现象：一步步跑通 RFID 读卡

先不读代码——按命令卡把"自检 → 服务端 → 客户端 → CLI 观察反馈流"四个现象亲手跑出来，特别是三种结局（成功 / 超时 / 取消）都要亲眼看到一遍。看到现象再回头看 07 的代码。

终端 0编译 + 脱机自检驱动把硬件故障和 ROS 逻辑故障分开排查
1编译两个包并加载环境终端 0

接口包（ros_sensor_interfaces，.action 定义在里面）与节点包（ros_sensor）都要编。

cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select ros_sensor ros_sensor_interfaces
source install/setup.bash

✔ 编译后忘了 source，ros2 run 就找不到包——每次新开终端都要 source。

2脱离 ROS 自检 MFRC522终端 0

SPI 接线、GPIO、供电问题都会在这一步暴露，不会污染 ROS 层的判断。

cd src/xflz_eai_car1/driver/ros_sensor/ros_sensor/ros_sensor
sudo python3 rc522_reader.py --test
$ sudo python3 rc522_reader.py --test RC522 RFID Reader on RK3588 SPI : /dev/spidev1.0 CS GPIO : 114 RST GPIO : 116 Speed : 500000 Hz -------------------------------------- VersionReg(0x37) = 0xB2 TmodeReg write 0x8D -> read 0x8D PASS 初始化完成

✔ VersionReg 读出 0x00 或 0xFF = 芯片没应答：查 CS=114 / RST=116 接线、3.3V 供电、python-periphery 是否安装。

6不写一行客户端，直接发 Goal 并看反馈终端 C

--feedback 是动作与服务最直观的分界线：服务 call 出来只有最终一行，动作能看到整条状态流。

ros2 action send_goal /rfid_scan ros_sensor_interfaces/action/RfidScan "{timeout_sec: 30}" --feedback
$ ros2 action send_goal /rfid_scan ros_sensor_interfaces/action/RfidScan "{timeout_sec: 30}" --feedback Goal accepted with ID: … Feedback: SCANNING Feedback: SCANNING Result: success=True uid=7E1A3B02 type=MIFARE Classic msg=读卡成功

✔ Goal 的 YAML 字段名必须与 .action 完全一致——是 timeout_sec 不是 timeout，写错直接解析失败（08 节任务 5 专门让你踩这个坑）。

7复现另外两种结局终端 C

超时与取消也要亲眼各看一遍——三种结局合起来才是完整的动作语义。

# 结局 2 · 超时 abort：故意不放卡，等 timeout_sec 秒
ros2 action send_goal /rfid_scan ros_sensor_interfaces/action/RfidScan "{timeout_sec: 10}" --feedback
# → SCANNING 持续滚动 10s → Result: success=False msg=读卡超时

# 结局 3 · 取消 canceled：上一条跑起来后按 Ctrl+C（CLI 会发 cancel）
# → Feedback 中断 → Result: success=False msg=已取消
