# 课程文案规范（Course Copy Spec）

版本：v1.4　｜　生效：2026-10-15　｜　规范唯一维护处：本文件

## Overview

本规范定义本项目所有"教程型内容"的写法。加载后，将本规范当作硬约束执行，而非参考建议。规范本身可调整：修改本文件即改规范（流程见文末"修订机制"）。

适用范围（硬边界）：**仅 `training/output/` 目录**下的 HTML 讲义页、Markdown 文本、目录/卡片文案、思考题与练习题文本。以下内容一律不适用：`courses/` 等历史源讲义、`ros2_ws/` 源码与注释、记忆文件、规范自身。

## 一、读者定位（每次动笔前先对齐）

- 读者是**初学者**：默认没接触过 ROS2、机械臂、URDF；不要求读者记住任何前文细节，关键前情用一句话回带。
- 术语**首次出现必须随文给一句白话定义**，不依赖读者查资料。既有口径照用：ROS2 = 机器人的"普通话 + 微信群 + 一键工具箱"，引出语用"简单来说，"。
- 单个新概念一段内不超过 2 个；宁可拆节，不要堆叠。

## 二、文风（大白话 · 去 AI 味）

**必须：**
- 短句为主，一句一个意思；能用动词开头就不用名词堆砌。
- 先疼后药：先讲"会遇到什么问题/困惑"，再给方案。
- 每节保证**一句话可复述**的核心结论。
- 类比贯穿且同一对象全篇只用一个类比（如"普通话·微信群·工具箱"），不换喻体。
- 跳转指针写内容关键词（"见下方'总机 vs 群聊'对比"），不写媒介词。
- 允许口语化设问引出，但一节最多一次。

**禁止（AI 味特征）：**
- 三段式排比、"首先/其次/最后"框架腔、"值得注意的是""总而言之""综上所述"。
- 空洞程度词堆砌（"极大地""有效地显著提升"）——要量化就给具体数字/现象。
- 每段末尾小结、每个小节都"总结一下"。
- 媒介自指标语："注意看动画""下面用动画演示""动画看懂了"——视觉素材自己会说话。
- 否定式排比（"不是 X，不是 Y，而是 Z"连用）、故作悬念的"你猜怎么着"。
- 夸大的象征意义（"这一步看似简单，实则意义深远"）。
- **引用表演**：不写"源码注释原话""原文写道""正如注释所说"——事实直接下判断，出处收进括号（文件名/常量名/行号任一即可）。人不自证"我没编造"。
- **证据堆叠**：同一个事实不连抛三四种表述充数（度数 + PWM + 弧度常数 + 英文注释全文四连引）——推算过程给一次，出处给一个，够了就停。
- **破折号换气**："——"是 AI 最典型的换气口，**一段最多 1 处**；多出来的改句号硬断。
- **元语言收尾**：段尾不绕回自身作结（"这张表就是它的依据""这正是……的原因"）——讲完最后一个事实就停，不替读者点题。
- **标题带自述**：小节/提示条标题直写内容（"限位的两层口径"），不加"……与出处""……及其意义"这类自我说明词。

**允许保留（不算 AI 味，勿误删）**：教材式图题"动画 1-x｜…"（等同"图 1-x"的命名索引）、SVG 的 aria-label（无障碍需要）。

修订过的正例可对照：Python 写的节点和 C++ 写的节点，语言不通凭什么直接对话？——因为签了同一份消息合同（IDL）。

## 三、原理怎么讲（面向初学者的讲解骨架）

每个原理按固定顺序推进：**现象 → 机制 → 验证**。

1. **现象开场**：从学习者已经看到或能一步复现的现象切入（一张截图、刚做过的操作），提出"为什么会这样"。不从定义开场，更不从公式开场。
2. **机制拆解**：一次只推进一层，用已知锚点挂新知。必须使用类比时遵守两条——
   - 同一对象全篇只用一个类比（见第二节）；
   - 类比必须**揭盖**：讲完指出哪里像、哪里不像（如：微信群 ≈ 话题，但"群里人人可见" ≠ ROS2 话题的点对点订阅）。不揭盖的类比会造成负迁移，比不用类比更糟。
3. **先直觉后形式**：先用白话说清"谁变、朝哪变、变了会怎样"，公式与参数后置；公式出现时必须带单位与物理含义，并注明"记住结论即可，推导不必背"。
4. **可验证收尾**：每个原理至少配一条能亲眼验证的证据——一条命令的输出、一次现象的变化。说不出怎么验证的原理，视为没讲完。
5. **收口**：段末给"一句话复述"供学习者自查；与后文的接口要写明用在哪（"这条结论第 N 节直接用"）。

## 四、展示方式选型（静态 / 动画 / 交互怎么选）

按"要表达什么"选载体；同一内容能用更轻的载体就不用更重的。

| 要表达什么 | 首选载体 | 例 |
|---|---|---|
| 结构、组成、关系 | 静态结构图（内联 SVG） | 节点-话题架构图、TF 树 |
| 顺序、分支、决策 | 流程图 + 文字编号步骤 | 启动流程、异常分支 |
| 多主体消息往来 | 时序图 | 发布 → 订阅 → 渲染链 |
| **变化过程**（随时间/操作演变） | **动画演示**（SVG+CSS 内联动效；录屏等不可内联的留"素材位"占位；见第五节"演示部分"） | 关节运动时 TF 树重算、消息沿话题流动 |
| **因果规律**（输入变 → 输出怎么变） | **带交互的小控件**（滑杆/输入 + 实时结果 + 判定） | 关节角 → 末端姿态、参数试算 |
| 对比、参数罗列 | 表格 | 限位双口径表 |

**动画规范：**
- 必须"无声自明"：没有旁白也能看懂——配"看哪里"的观察点标注（高亮、箭头、字幕条）；
- 一页最多 1 个主动画，避免抢焦点；禁止媒介自指标语（见第二节），动画自己完成演示；
- 前后各一句：动画前布置观察任务（"注意 X 怎么变"），动画后收束结论（"所以 X 依赖 Y"）。

**交互规范（四件套，缺一即不合格）：**
- **单结论**：一个交互只验证一个原理/结论；
- **默认演示值**：打开即处于能立刻点出结论的状态，学习者不调参也能看出规律；
- **可重置**：一键回到初始演示态；
- **判定语**：结果区给 ✔/✘ + 一句话解释，不能只回显数字。
- 另需写明操作提示（拖哪里、点哪里、先关什么窗口），交互结束紧跟"你刚才证明了什么"一句话，把操作收回原理。

## 五、分区输出形态（每类内容必须交付对应形态）

| 分区 | 必须包含的输出形态 |
|---|---|
| **原理部分** | 白话讲解 + 贯穿类比 + **结构/示意图**（SVG 或 diagram 类 widget）；一图配一段，图与文互相指认（文说"见下图"，图标"图 x-y"） |
| **操作部分** | 编号步骤 + **可直接复制的命令/代码块**；每步写明：做什么、会看到什么、判断成功的标志；命令块内用注释标关键参数 |
| **演示部分** | 现象描述落到**观察点清单**（看哪里、看什么、出现什么算对）；涉及动效/截图的，明确"素材位：xxx"占位说明 |
| **代码逻辑部分** | **必配架构图或流程图**（节点关系→架构图；执行顺序→流程图；多组件消息往来→时序图），三选一即可，图后紧跟文字解读关键分支/数据流向 |
| **练习/思考题** | 每题要么给作答线索，要么给"一句话答案"区；命令类练习必须是**全命令可复制**、参数与前文口径一致 |

## 六、图解硬要求（整份讲义级别）

- 每份讲义**至少 1 张架构图**（系统/节点/话题关系）。
- 有分支决策的流程**必须画流程图**，不许只用文字描述分支。
- 图一律内联自包含（SVG 写进页面），不引外部图片 CDN；图题格式"图 x-y｜一句话说明"。
- 图内文字用词与正文一致（同一概念不许图内一个词、正文另一个词）。

## 七、生成后自检清单（交付前逐项过）

1. 文风扫描：全文 grep 第二节的禁止词清单（含"原话/原文写道/正如……所说"），命中即改；再按段数一遍"——"，单段 >1 处就拆句号。
2. 分区对照：第五节表格逐行核对，缺形态即补。
3. 图解核对：架构图≥1；分支流程有无流程图；图题编号连续。
4. 交叉引用真实：每个"见第 N 节/见下方"锚点存在且指向正确。
5. 结构自检（HTML）：div 配平、`<pre>` 配对、`id sN` 与 `href #sN` 全对上、显示编号变则三处同步（实验页侧栏 / 目录页卡片 / 节间过渡语）。
6. 术语/数值防编造：卡片里的术语、算法、型号先在源码或讲义 grep 到出处再写。
7. 原理段核对：每个原理段是否走完"现象 → 机制 → 验证"，是否至少一条可验证证据 + 段末一句话复述；类比是否揭盖（指出了哪里像哪里不像）。
8. 展示选型核对：变化过程是否给动画（或"素材位"占位），因果规律是否给交互；动画有无"看哪里"观察点、前后是否各有一句观察任务与结论；交互是否满足四件套（单结论 / 默认演示值 / 可重置 / ✔✘判定语）。

## 修订机制（怎么调整这套规范）

- **谁改**：用户直接改本文件，或在对话里说明调整点让 agent 代改。
- **怎么改**：改动对应小节即可，改完在下方修订记录加一行（日期 + 改了什么 + 为什么）。
- **生效方式**：本文件是唯一事实源（single source of truth）；项目 MEMORY.md 只保留一条指向本文件的硬规则，不复制正文。改了这里，下一次会话自动按新版执行。
- **冲突处理**：本规范与项目 MEMORY.md 的"课程文案风格"条目如有冲突，以本文件为准，并同步更新 MEMORY.md。
