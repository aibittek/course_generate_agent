# 课程资源生成规则库

本规则库定义课程资源生成过程中的所有规则和标准，确保输出质量一致性。

---

## 一、命名规范规则

### 1.1 课程目录命名
- **格式**: `courses/{分类}/{课程英文标识}/`
- **分类**:
  - `sheet1/` - 核心实验室课程
  - `sheet2/` - 行业创新应用实验室课程

### 1.2 课程英文标识映射

#### Sheet1: 核心实验室课程
| 课程名称 | 英文标识 |
|---------|---------|
| 机器人视觉应用与开发 | cv_practice |
| 机器人自然语言交互应用与开发 | speech_practice |
| 机器人ROS2应用与开发 | ros_practice |
| 机器人SLAM与Nav应用开发 | slam_practice |
| 机器人机械臂应用与开发 | arm_practice |
| 机器人大模型综合应用开发 | llm_practice |
| 综合实训实践 | training |

#### Sheet2: 行业创新应用实验室课程
| 课程名称 | 英文标识 |
|---------|---------|
| 物料分拣应用场景 | sorting_scene |
| 柔性制造应用场景 | manufacturing_scene |
| 家庭整理应用场景 | home_scene |
| 室内巡检应用场景 | inspection_scene |

### 1.3 文档文件命名
- **格式**: `{课程英文标识}_{文档类型}.md`
- **文档类型编码**:
  | 类型 | 编码 | 说明 |
  |------|------|------|
  | 知识图谱 | `knowledge_graph` | 三级知识结构 |
  | 教学大纲 | `syllabus` | 教学设计文档 |
  | 实验指导书 | `lab_guide` | 实验项目指导 |
  | 练测题库 | `quiz` | 练习测试题 |

### 1.4 示例
```
courses/sheet1/cv_practice/
├── cv_practice_knowledge_graph.md
├── cv_practice_syllabus.md
├── cv_practice_lab_guide.md
└── cv_practice_quiz.md
```

### 1.5 禁止规则
- ❌ 中文文件名
- ❌ 空格（用下划线代替）
- ❌ 特殊字符（仅允许下划线）
- ❌ 超长文件名（不超过50字符）

## 二、Markdown格式规范

### 2.1 标题层级
| 层级 | 语法 | 用途 |
|------|------|------|
| 一级 | `# 标题` | 文档主标题（仅一个） |
| 二级 | `## 标题` | 大章节 |
| 三级 | `### 标题` | 小节 |
| 四级 | `#### 标题` | 子节（慎用，最多2层） |

### 2.2 表格格式
```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
| 内容 | 内容 | 内容 |
```
- 表头使用粗体或单独一行
- 表格前后空一行

### 2.3 列表格式
```markdown
- 无序列表项
  - 嵌套项（缩进2空格）

1. 有序列表
2. 第二项
```

### 2.4 代码块
````markdown
```python
# 代码内容
def example():
    pass
```
````
- 必须指定语言类型
- 代码块前后空一行

### 2.5 强调格式
| 语法 | 效果 | 用途 |
|------|------|------|
| `**粗体**` | **粗体** | 强调、重点 |
| `*斜体*` | *斜体* | 术语、引用 |
| `` `代码` `` | `代码` | 代码、命令 |

### 2.6 禁止规则
- ❌ 手写表格边框（使用标准Markdown表格）
- ❌ 多余空行（最多连续2行）
- ❌ 非标准emoji（仅使用 ✅ ❌ ⚠️ 🔴 🟡 🟢 ⭐）
- ❌ 嵌套过深的列表（超过3层）

## 三、内容质量标准

### 3.1 知识图谱标准
| 检查项 | 标准 | 说明 |
|-------|------|------|
| 章节数 | ≥3章 | 每门课至少3章 |
| 每章节数 | ≥3节 | 每章至少3节 |
| 每节知识点 | ≥3个 | 每节至少3个知识点 |
| 类型分布 | 概念40%、原理30%、流程20%、事实10% | 允许±10%偏差 |
| 描述长度 | ≤50字 | 知识点描述简洁 |

### 3.2 教学大纲标准
| 检查项 | 标准 | 说明 |
|-------|------|------|
| 目标维度 | 知识、能力、素养 | 三维目标必须齐全 |
| 学时一致 | 总和=总学时 | 分项之和=总学时 |
| 考核方式 | 包含过程评价 | 不能只有期末考试 |
| 先修课程 | 逻辑正确 | 不能有循环依赖 |

### 3.3 实验指导书标准
| 检查项 | 标准 | 说明 |
|-------|------|------|
| 实验数量 | ≥6个 | Sheet1课程 |
| 类型配比 | 综合≥30% | 设计性≥30%，验证性≤40% |
| 结构完整 | 包含6要素 | 目的/原理/设备/步骤/思考/报告 |
| 可操作性 | ≥80% | 步骤清晰可执行 |

### 3.4 练测题标准
| 检查项 | 标准 | 说明 |
|-------|------|------|
| 知识点覆盖 | ≥90% | 有题目覆盖的知识点 |
| 难度分布 | 易50%、中30%、难20% | 允许±10%偏差 |
| 题型分布 | 单选/多选/简答/编程 | 四类齐全 |
| 题目标注 | 关联知识点 | 每题标注知识点编号 |

## 四、准确性规则

### 4.1 技术术语规范
- 使用标准术语（如ROS2而非ROS1遗留概念）
- 首次出现提供英文或解释
- 保持全文一致

### 4.2 禁止内容
- ❌ 过时的技术名词
- ❌ 未经验证的技术细节
- ❌ 与培养方案矛盾的描述
- ❌ 虚假或夸大的功能描述

### 4.3 代码正确性
- 无语法错误
- 符合语言规范
- 可实际运行

## 五、版本管理规范

### 5.1 版本号规则
- **格式**: `v{主版本}.{次版本}`
- **主版本**: 重大结构调整（如新增章节）
- **次版本**: 内容更新/修正

### 5.2 更新日志格式
```markdown
## 更新日志
| 版本 | 日期 | 更新内容 | 更新人 |
|------|------|---------|-------|
| v0.1 | 2026-06-11 | 初始生成 | Agent |
```
